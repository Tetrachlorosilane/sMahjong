# 专家模型训练计划书（v1 · 2026-10-04）

> 目的：把"单一网络 + 单线 RL 累积"改成**「多专家 + 场景化权重」**。本文件是**执行计划**（每线练什么、用什么判据、什么条件下停），
> 与它配套的事实依据在 `docs/TRAINING-V4.md §15`（画像与专家选择）、`NOTES.md §6.5 第六十二~六十六轮`（审计链与已知无用清单）。

## 0. 为什么走这条路（一句话）

**实测结论：现有单线 RL 的"每轮更新"对强度的期望效果与 0 不可区分**（10 代链 −4.26 显著负、24 代链 18,000 场合并不显著 ≈ −0.30 ⇒ **链级符号不稳定**），
而**画像能看出风格差异**（立直率 19% vs 36%、副露率 15% vs 51%、平均打点 5,840 vs 7,244）⇒ 与其继续押"单线变得更强"，不如**按维度分线造专家、再用场景化权重组合**。

## 2. 总体架构（四层）

```
        ┌──────────────── 场景化权重层（阶段 4）────────────────┐
        │  离线：按局面特征给各专家加权（分析） → 在线：小门控模型  │
        └───────▲───────────────▲───────────────▲─────────────┘
                │               │               │
        打点线(已认证)      防守线(要造)      和率线(要造)           ← 阶段 3：多线训练
        种子 14-g05        种子 g08         种子 16-g04
                │               │               │
                └───────────────┴───────────────┘
                    基模 = v4-league-g08（现任；同时是每线的**初始对手**）
```

- **阶段 3（多线训练）**：三条线各自独立训练，**只共享基模 g08 与判据体系**，互不干扰；每线有"目标轴 + 护栏轴"。
- **阶段 4（场景化权重）**：先**离线**做加权分析（不开新训练），再决定是否上在线门控小模型。

## 3. 每条线的规格卡

> 通用：每线都用现成回路（`tools/run-league.ps1`），**每代换新牌山**、候选 **SHA256 去重**、`--workers 16`、决策规模 1000 场/代；
> 判据**只走闸门**；画像用于**描述风格与检查护栏**，不用于判强弱。

### 3.1 打点线（**唯一已认证**，先做）

| 项 | 内容 |
| --- | --- |
| 目标轴 | 平均打点、満貫以上率（按 `limit` 口径更可信）、跳満/倍満率 |
| 护栏轴 | 顺位点 / 平均得点**不许显著更差**；和率掉幅 **≤1 pp**（现成专家 `14-g05` 已经掉了 1.8 pp，**这是要修的**） |
| 种子 | **`v4-league14-g05`**（不是 g08 —— 唯一有 CI 支持的起点） |
| 对手池 | **g08 必在** + `14-g05` 自己以外最近两代 + teacher；池里**不要**放低打点型（`10-g01`） |
| 课程方向 | 提高"立直/宝牌/副露搭子价值高"局面的权重；**奖励仍用顺位点**（⛔ 别换 `hand_delta`，那会重演 A 路"更贴标签却更差"） |
| 判据 | ① 闸门 vs **g08**：CI 排除 0 且为正；② 画像：平均打点 ≥ `14-g05` 且**和率差幅收窄到 ≤1 pp**；③ 连续 3 代不达标 ⇒ 停线 |
| 预算 | 先 **10 代（≈65 分钟/代含判决 ⇒ 约 2 小时）**，再按结果加长 |

### 3.2 防守线（要造）

| 项 | 内容 |
| --- | --- |
| 目标轴 | **铳率显著下降**（配对、同牌山、n≥600 才可能判 1 pp 级差异） |
| 护栏轴 | 顺位点 / 得点不许显著更差；和率掉幅设上限（建议 ≤1.5 pp） |
| 种子 | **`g08`**（⛔ 别用 `14-g05` 作种子：它铳率 +1.3 pp、方向相反） |
| 对手池 | 放**高打点型**（`14-g05`、`17-g24`）当"威胁源"，逼出押し引き |
| 课程方向 | 「他家立直宣言后自家打牌」局面过采样（可用对手池 + 立直率高的对手自然诱导） |
| ⛔ 不要重复 | **危险度标签已被证否**：引擎 `Danger` 早已是输入通道且更差（AUC 0.50~0.54 vs 头 0.64~0.65）、真手牌 oracle 的特权监督对"实际放铳那一手"增益为 **0.000**（§14.12.6 / 第六十三~六十五轮） |
| 判据 | ① 铳率 Δ 的 CI 排除 0 且为**负**；② 完场轴不显著更差；③ 画像里立直率/副露率**不许**崩到负对照那种水平 |

### 3.3 和率线（要造）

| 项 | 内容 |
| --- | --- |
| 目标轴 | 和率、平均和了巡目（速度） |
| 护栏轴 | 顺位点 / 得点；**打点掉幅设上限**（建议 ≤300 点，否则变成"便宜手"负对照） |
| 种子 | **`v4-league16-g04`** —— 六轴全部"分不出"的**最中性起点**（不继承任何极端风格） |
| 对手池 | 掺**低打点型**（`10-g01`：副露 50.6%、打点 5,840）诱导"先和为先" |
| 课程方向 | 副露/食い断局面过采样 |
| 判据 | ① 和率 Δ 的 CI 排除 0 且为正；② 打点掉幅 ≤300；③ 画像里副露率**不许**超过某个上限（先标定，避免重演负对照） |

## 4. 每线的训练流程（每代 8 步，全部已有工具）

1. **采集**：`X,X,对手,对手 --rotate`（⛔ **禁止镜像 `X,X,X,X`** —— 完场轴会退化，`Σplacement=10` ⇒ 平均顺位恒 2.5）
2. **轨迹校验**：`tools/selfplay-check.mjs`（含 `hand` 行的役种断言）
3. **紧凑集**：`dataset build`（现 88 s/1000 场）
4. **训练**：`pretrain`（PPO；`--kl-early-stop 0.10`、`--max-steps 2000`、`--val-every 100 --val-patience 5`；⛔ `--il-weight 0`、⛔ `--ref-beta 0`）
5. **导出** + 值头 audit（`--ev-ref legit --strict`）
6. **自评**：200 场 2+2 vs 上一代（**每代换 seed**，CI ±7.6 ⇒ 只看大变化）
7. **闸门**（唯一强弱判据）：多套新牌山，CI 排除 0 且为正才采纳
8. **画像**（风格与护栏）：`python -m mahjong_ml.v4 profile --run <本次 gate tag> --incumbent v4-league-g08`（⚠ **逐候选单独跑**，见 §8 撞键）

**开训前自检清单**（缺一不可）：`python/selfcheck.py`（659/0）· `node tools/doc-refs-check.mjs` · `trainer --selftest`（S: 那份）·
`java -jar server/build/mahjong-server.jar --selftest`（1445/0）· `node tools/trainer-v4-parity.mjs --golden` · `node tools/v4-cache-check.mjs` · `gate --self-check`。

## 5. 判据体系（唯一权威 = 闸门）

| 用途 | 判据 | 最小规模 |
| --- | --- | --- |
| **单代采纳** | 多套**新**牌山配对，**CI 排除 0 且为正** | ≥2 套 × 1000 场（±2.35） |
| **一条线是否成功** | 终点 vs 起点（**累积而不逐代把关**），4~8 套新牌山 | **6000~12000 场（20~40 分钟）** |
| **风格/护栏** | 画像轴（打点/铳率/和率/立直/副露/役种/巡目） | 同场多策略 ≥300 场/候选 |
| ⛔ 禁止 | `engine_top1` / 引擎 CE / 危险度旧口径 AUC / 任何"贴标签的读数"当强弱判据 | — |

**口径注意**：`win_rate`/`deal_in_rate` 是**每座位·小局**（不是每场，差 11~12 倍）；`満貫以上率` 用 **`limit`** 口径（点数口径会把亲家 12000 误判成跳満，已修但两口径仍不同）；
任何"我赢了"的结论都要带 **n 与 CI**。

## 6. 阶段 4：场景化多模型权重（先离线，后在线）

1. **离线加权分析**（不训练）：对每一场/每一手，用画像轴把局面分桶（例如"他家立直 + 自家 2 向听""自家听牌 + 打点 ≥ 満貫"），
   统计**哪个专家在该桶里更强**（用同一批牌山的配对结果）。产出：**一张"局面 → 该信谁"的表**与各专家的适用边界。
2. **在线门控小模型**（仅在①显示有稳定可分性时才做）：输入用**廉价 obs 特征**（巡目、他家立直数、自家向听/打点潜力、点况顺位），输出"交给哪条线"。
   - 判据：门控版 vs 单一最强专家的**闸门配对**；**只走闸门**。
   - 风险：门控本身是新的黑箱 —— 必须能解释（例如先做线性/规则门控，再考虑小网络）。

## 8. 已知陷阱清单（**每条都踩过**，动手前扫一遍）

1. **候选伪重复**：132 个 `net.bin` 只有 109 个不同 ⇒ 选题必须先 SHA256 去重；同配置 + 同种子会**逐字节复现**同一个候选。
2. **共用牌山 ⇒ 判决不独立**：历季 19 个判决共用同一对牌山；**每代必须换新牌山**，且 `seed` 与采集 seed **错开**。
3. **套间散布 ≫ CI**：换牌山能摆动 ~4 点 ⇒ 判决要报"套间散布 / CI 半宽"，>1× 时只能读成"条件于这几套牌山"。
4. **`profile` 逐场序列撞键**（修中）：多 run 共用同批 seed 时现任序列被覆盖 ⇒ **配对表必须逐候选单跑**。
5. **`selfcheck` 一条负向对照曾是假绿**（修中）：缓存键含 `mtime_ns` 而 Windows 分辨率 ~15.6 ms、写入字节数不变 ⇒ 命中旧缓存。
6. **镜像自对弈退化完场轴**：一律 `X,X,对手,对手 --rotate`。
7. **A/B/C 三条标签路已全部关闭**（引擎牌效 / 搜索算子排序 / 真手牌 oracle）⇒ **不要重做**；危险度标签同理。
8. **`--il-weight > 0` 有害**（一代 −12.65）；`--ref-beta` 会把每轮压成 no-op（KL 0.005）⇒ 本计划两条都用 0。
9. **数值口径**：`--lr 1e-2` 会把 v4 打塌（融合 ReLU 死区）；KL 早停 0.03 会在 66 步掐断（现用 0.10）。
10. **结构性盲点**：抢杠**不向被抢那家发问**（策略侧没有该决策）；`kyuushu`/四槓散了/三家和了等在 mleague 预设下**不可达** ⇒ 别把"测不到"当"没问题"。
11. **所有对比都要同牌山 + 配对**；跨模型比较必须先统一牌山。
12. **判据纪律**：贴标签的读数（`engine_top1`/引擎 CE/危险度 AUC）**不是**强弱判据（已写进 `AGENTS §6.5`）。

## 9. 停止 / 转向条件（预先登记，避免"越跑越久"）

- **单线停止**：连续 **3 代**闸门 CI 跨 0 且画像护栏被破 ⇒ 停该线，记录"该轴在本配方下造不出来"。
- **多专家路线停止**：三条线各自跑完 10 代后，**没有任何一条**在闸门上显著为正 ⇒ 判定"多线训练同样给不出可判据的进步"，
  转**架构/算力效率**议题（不再是"换配方/换标签"）。
- **阶段 4 停止**：离线加权表若显示"同一桶里没有稳定更强者"（例如各专家在同一桶的配对 CI 全跨 0）⇒ **不做在线门控**。

## 11. 结论（2026-10-06）：**"单线在平均意义上变强"这一子命题不成立**；⚠ **阶段 4（风格抉择）尚未验证**

> ⚠ **口径边界（2026-10-06 修正）**：本节驳回的是 **"把某条风格线单独练 10 代就能稳定强于 `g08`"** 这个子命题。
> **多专家架构本身没有被否证** —— 它的核心部件是**风格抉择（阶段 4 的场景化加权 / 门控小模型）**，而那一层
> **至今既没训练过、也没做过离线可行性分析**。风格差异是**实测存在**的（打点 +358 / 副露 −3.2pp ~ +4pp 等），
> 所以"**没有任何一条单线更强**"**不等于**"**按局面切换专家也拿不到收益**"。⇒ 第 4 节（阶段 4）**照原计划执行**。

**实验设置**（全部统一）：`-RefBeta 0 -IlWeight 0`、每线 10 代 × 1000 场/代、12 workers、种子一律 `v4-league-g08`
（唯打点线为 `v4-league14-g05`）；**终点一律 vs `v4-league-g08`**、多套**新**牌山逐场配对。

| 线 | 对手池 | 终点 Δ（顺位点） | 95% CI | n | 备注 |
| --- | --- | --- | --- | --- | --- |
| 防守线 | `{14-g05, atk2-g09}` | +0.80 / +0.93 ⇒ **合并 +0.867** | [+0.188, +1.560] | 24,000 | 曾判为"首次显著为正" |
| **防守线复现**（同配方、独立重掷） | 同上 | **−3.54** | [−4.50, −2.58] | 12,000 | **0/8 套为正** |
| 方向测试 | `{14-g05, atk2-g09, def3-g08}` | +0.30 | [−0.67, +1.27] | 12,000 | 副露率 +2.5 pp |
| 打点线 | 空池（种子 `14-g05`） | +0.00 | [−0.96, +1.00] | 12,000 | 打点 +358（vs `g08`） |
| 和率线 | `{10-g01}`（便宜手） | **−1.12** | [−2.09, −0.17] | 12,000 | 打点 −54、副露 +4.0 pp、和率 −0.5 pp |

**判定**：**同配方复现得 −3.54，与首次 +0.867 相差 4.4 点且 CI 不重叠** ⇒ 首次那个"显著为正"是**链级涨落**，
**撤回**该结论。10 代链的**链间散布 ≥4 点**，而**配方 / 对手池 / 种子风格都无法预测符号**
（历季同型链条再添 −4.26 与 +0.00）。⇒ 按 §9 预登记条件：**多专家/风格线路线不成立，转"架构与算力效率"议题**。
