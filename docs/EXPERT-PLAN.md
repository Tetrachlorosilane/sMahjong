## 0. 为什么走这条路（一句话）

**实测结论：现有单线 RL 的"每轮更新"对强度的期望效果与 0 不可区分**（10 代链 −4.26 显著负、24 代链 18,000 场合并不显著 ≈ −0.30 ⇒ **链级符号不稳定**），
而**画像能看出风格差异**（立直率 19% vs 36%、副露率 15% vs 51%、平均打点 5,840 vs 7,244）⇒ 与其继续押"单线变得更强"，不如**按维度分线造专家、再用场景化权重组合**。

## 3. 每条线的规格卡

> ⚠ **本节是计划原文（"要造 / 先做"）**，三张卡都已经按它跑过。**终点判决在 §11**，一句话版：

> 通用：每线都用现成回路（`tools/run-league.ps1`），**每代换新牌山**、候选 **SHA256 去重**、`--workers 16`、决策规模 1000 场/代；

### 3.1 打点线（**唯一已认证**，先做）

| 项 | 内容 |
| --- | --- |
| 目标轴 | 平均打点、満貫以上率（按 `limit` 口径更可信）、跳満/倍満率 |
| 护栏轴 | 顺位点 / 平均得点**不许显著更差**；和率掉幅 **≤1 pp**（现成专家 `14-g05` 已经掉了 1.8 pp，**这是要修的**） |

| 课程方向 | 提高"立直/宝牌/副露搭子价值高"局面的权重；**奖励仍用顺位点**（⛔ 别换 `hand_delta`，那会重演 A 路"更贴标签却更差"） |

## 4. 每线的训练流程（每代 8 步，全部已有工具）

1. **采集**：`X,X,对手,对手 --rotate`（⛔ **禁止镜像 `X,X,X,X`** —— 完场轴会退化，`Σplacement=10` ⇒ 平均顺位恒 2.5）
2. **轨迹校验**：`tools/selfplay-check.mjs`（含 `hand` 行的役种断言）
3. **紧凑集**：`dataset build`（现 88 s/1000 场）
4. **训练**：`pretrain`（PPO；`--kl-early-stop 0.10`、`--max-steps 2000`、`--val-every 100 --val-patience 5`；⛔ `--il-weight 0`、⛔ `--ref-beta 0`）
5. **导出** + 值头 audit（`--ev-ref legit --strict`）
6. **自评**：200 场 2+2 vs 上一代（**每代换 seed**，CI ±7.6 ⇒ 只看大变化）
7. **闸门**（唯一强弱判据）：多套新牌山，CI 排除 0 且为正才采纳
8. **画像**（风格与护栏）：`python -m mahjong_ml.v4 profile --run <本次 gate tag> --incumbent v4-league-g08`（⚠ **逐候选单独跑**，见 §8 撞键）

**开训前自检清单**（缺一不可）：`python/selfcheck.py`（659/0）· `node tools/doc-refs-check.mjs` · `trainer --selftest`（S: 那份）·
`java -jar server/build/mahjong-server.jar --selftest`（1445/0）· `node tools/trainer-v4-parity.mjs --golden` · `node tools/v4-cache-check.mjs` · `gate --self-check`。

## 5. 判据体系（唯一权威 = 闸门）

| 用途 | 判据 | 最小规模 |
| --- | --- | --- |
| **单代采纳** | 多套**新**牌山配对，**CI 排除 0 且为正** | ≥2 套 × 1000 场（±2.35） |
| **一条线是否成功** | 终点 vs 起点（**累积而不逐代把关**），4~8 套新牌山 | **6000~12000 场（20~40 分钟）** |
| ⚠ **一条线/一个专家的最终判定（2026-10-06 起）** | 闸门 + **≥24,000 场池化** + **超出噪声底** + **事先登记** | **24,000 场 ≈ 50 分钟**（§12.5） |
| **风格/护栏** | 画像轴（打点/铳率/和率/立直/副露/役种/巡目） | 同场多策略 ≥300 场/候选 |
| ⛔ 禁止 | `engine_top1` / 引擎 CE / 危险度旧口径 AUC / 任何"贴标签的读数"当强弱判据 | — |

**口径注意**：`win_rate`/`deal_in_rate` 是**每座位·小局**（不是每场，差 11~12 倍）；`満貫以上率` 用 **`limit`** 口径（点数口径会把亲家 12000 误判成跳満，已修但两口径仍不同）；
任何"我赢了"的结论都要带 **n 与 CI**；⚠ **CI 排除 0 只是入场券，不是判决**（§12.5：还要超出噪声底）。

## 6. 阶段 4：场景化多模型权重 —— **已判定（2026-10-06）：门控不值得训**

> 本节原文写的"先离线、后在线"**已经执行完**，结论与原文的乐观口气相反。**数字全部出自
> `docs/TRAINING-V4.md §16`**（估计量、三个坑与红证在 `NOTES.md §6.5 第六十七轮`）：

1. **离线加权分析 —— 做了**：四方同桌 4,000 场（8 套牌山 × 500 场，四位专家各坐四个座位）、
   45,559 小局 / 2,751,168 条决策；桶由**该座位自己的 obs** 决定（巡目 × 他家立直数 × 自家向听 × 是否已立直）⇒ 22 桶。
2. **oracle 上界（"每桶都交给当时最合适的专家"）**：**样本内 +0.780 顺位点/场**（已知高估）、
   **诚实（留一牌山）+0.327**；⚠ 相对**桶内标签置换零分布**只有 **z = +0.65**（零分布 sd = **1.008 顺位点/场**）。
3. **可切换桶清单**：22 桶里 **1 桶**通过（占局面 2.1%、+0.151 顺位点/场），而**纯噪声下平均就有 0.6 桶、最多 5 桶**
   ⇒ 那份清单是**假阳**，拿不出学习目标。
4. **门控本身的增量 = −0.166 顺位点/场**：把"按桶切换"和"干脆只选一位全局最强（`atk2` = +0.493）"放在同一把尺子上比，
   **按桶切换更差**；三种桶粒度（22 / 12 / 15 桶）结论一致（诚实上界 +0.26~+0.36、增量全为负）。
5. ⚠ **另一条同样重要**：「只换一位专家、不门控」也没什么可拿 —— 最强的 `atk2` 对 `g08` 只有
   **+0.163 [−1.357,+1.502]**（8 套配对，胜 4 负 4）。
6. ⇒ **两条路（择优 / 抉择）在这批专家上都没有收益**。要走的不是"怎么选"，而是
   「**先把专家练到显著更强**」—— 而"买分辨率"那条曾被否决的路，前提（判决成本）已经变了（§12.4/§14c）。

## 8. 已知陷阱清单（**每条都踩过**，动手前扫一遍）

1. **候选伪重复**：132 个 `net.bin` 只有 109 个不同 ⇒ 选题必须先 SHA256 去重；同配置 + 同种子会**逐字节复现**同一个候选。
2. **共用牌山 ⇒ 判决不独立**：历季 19 个判决共用同一对牌山；**每代必须换新牌山**，且 `seed` 与采集 seed **错开**。
3. **套间散布 ≫ CI**：换牌山能摆动 ~4 点 ⇒ 判决要报"套间散布 / CI 半宽"，>1× 时只能读成"条件于这几套牌山"。
4. **`profile` 逐场序列撞键**（**2026-10-05 已修**）：多 run 共用同批 seed 时现任序列被覆盖 ⇒ 修法是键 = `(墙 seed, run 序号)`；修前"跑 15 个 tag 一次出表"会把唯一的专家抹掉（读数见 `docs/TRAINING-V4.md §15.7.3`）。
5. **`selfcheck` 一条负向对照曾是假绿**（**已修**）：缓存键含 `mtime_ns` 而 Windows 分辨率 ~15.6 ms、写入字节数不变 ⇒ 命中旧缓存；修法是显式清记忆表 + 夹具少一个字节。
6. **镜像自对弈退化完场轴**：一律 `X,X,对手,对手 --rotate`。
7. **A/B/C 三条标签路已全部关闭**（引擎牌效 / 搜索算子排序 / 真手牌 oracle）⇒ **不要重做**；危险度标签同理。
8. **`--il-weight > 0` 有害**（一代 −12.65）；⚠ **`--ref-beta` 的口径已更正**：它**不是**"净负的坏旋钮"，而是**刹车**
   （β 太大 ⇒ 每轮被压成 KL 0.005 的 no-op）⇒ **别乱动它**（`NOTES.md §6.5 第六十六轮`「仍然有效」段）。
9. **数值口径**（**2026-10-04 计划当时的取值**；回路现行缺省见 `python/mahjong_ml/v4/loop.py`）：`--lr 1e-2` 会把 v4 打塌
   （融合 ReLU 死区，top1 0.837→0.165、policy CE 恒定 1.897）；KL 早停曾用 0.03（会在 ~66 步掐断）。
10. **结构性盲点**：抢杠**不向被抢那家发问**（策略侧没有该决策）；`kyuushu`/四槓散了/三家和了等在 mleague 预设下**不可达** ⇒ 别把"测不到"当"没问题"。

12. **判据纪律**：贴标签的读数（`engine_top1`/引擎 CE/危险度 AUC）**不是**强弱判据（已写进 `AGENTS §6.5`）。

## 12. 下一步规划：架构与算力效率（2026-10-06）

> **议题变更一句话**：问题不再"换哪个配方/标签"，而是"**如何让一步更新在期望上为正**"。
> **纪律**：每个方向都写"**它与已否证路线的区别**" —— 说不出区别的，就是重列黑名单。
> ⛔ **不许重做**（`NOTES.md §6.5 第六十六轮` 的 12 条）：历季联赛配方 · 买分辨率（**前提已变，见 §12.4**）·
> A 引擎牌效标签 · B 搜索算子排序当标签 · C 真手牌 oracle · 贴标签的读数当判据 · 跨季伪重复 · 共用牌山 ·
> `--lr 1e-2` · teacher 蒸馏 · critic 四条死路 · 2000 场级大闸门当进度表。

### 12.0 本规划的起点：阶段 4 已收口，但"练出更强专家"没被否证

- 阶段 4 判定 **门控不值得训**（§6 · `docs/TRAINING-V4.md §16`）。
- ⚠ **没有被否证的那一条**：`TRAINING-V4.md §16.7` 第 5 条 —— "要走的不是怎么选，而是**先把专家练到显著更强**"。
  它卡在"**尺子看不见**"（每轮位移 ~1 点 vs 分辨率/散布），而**尺子的成本前提刚刚变了**（§12.4）
  ⇒ 它是 §12.1 / §12.5 的间接动机，**本身不构成独立方向**（它仍属"换配方"，已试过 6 条）。

### 12.1 方向一：优势源（**优先，唯一有机理证据**）

| 项 | 内容 |
| --- | --- |
| **想解决什么** | **一步更新在期望上不为正**。现状 = `--advantage hand` + `--rank-weight 0.2`（`tools/run-league.ps1:145-146`）。 |
| **现状为什么可疑**（不是猜测，是回路自己的注释） | `python/mahjong_ml/v4/loop.py:146-148`：「v4 回路原来固定'自己×2 + teacher×2'，于是**结果奖励里关于'通用强度'的信息很少** —— 对手永远是同一批（teacher 与自己的上一代），**你变强变弱都在同一张桌子上**」。 |
| **候选 A：更大批量 / 更多局** | **做法**：配方一个字不改，只放大每代场次（1000 → 4,000/代）与 batch；看 `std(A_raw)`、KL、`clip_frac` 是否按 1/√n 收。**它解决什么**：奖励信息量不变，**信噪比**变好。 |
| **候选 B：per-decision 信用分配** | **做法**：把"小局级 + 终局顺位点"细化到逐决策 —— 走 `docs/TRAINING-V4.md §14.2` 的手级 GAE（λ<1 + bootstrap，`next_index` 由 `(game, hand_no, seat)` 构造，**已经落地过**），或把逐决策牌效/进张变化做成 shaping 奖励。 |
| **候选 C：用搜索得到的 Q 差当优势** | **做法**：把搜索的评估值差当 **critic 的一侧**（优势 = 搜索 Q − V），**不是**当监督标签。 |
| **候选 D：只降方差、不找新信号** | **做法**：只做 baseline 重标定（`--baseline-fit scale`，已落地）+ 更大批量，**不引入任何新奖励**。这是**唯一数学上保证不劣**的一条（基线是状态函数 ⇒ 线性重标定不改梯度期望、只降方差）。 |
| **成本** | A/D：改参数 + 1 季（10 代 ≈ **65 min**）+ 判决（24,000 场 ≈ **50 min**）⇒ **≈2 h/次**。B：`adv.py` 侧 ≈ **1 天** + 同上。C：还要搜索策略接口（见 §12.3）⇒ **≥3 天**。 |
| **判据** | §12.5（闸门 + ≥24,000 场池化 + **超出噪声底**）；⚠ 单线链另加"\|Δ\| 超过链间散布 **≥4 点**"才谈符号。 |
| **⛔ 已知否证 / 区别** | 否证在案的：A 引擎牌效标签（−12.65）、critic 四条（加宽读出头 +0.019 / PBRS `A'=A` / 绝对门槛 / 拿标签侧真值当参照）、`--ref-beta` 太大 ⇒ no-op。**区别**：**A/D 不引入任何新监督信号**（只改信噪比 / 只降方差）；**B 的信号是手级 TD 回报**（不是引擎牌效、不是搜索排序的静态排序）；**C 用的是搜索的数值 Q 差**（不是它的候选排序表）。 |

### 12.2 方向二：动作空间（先纠正一个既有事实）

| 项 | 内容 |
| --- | --- |
| ⚠ **既有事实（先说清）** | **"136 张牌的选择"这个描述不成立**：动作空间**早就是引擎给的候选列表** —— `docs/PROTOCOL.md §8.2` 的 `legal[]` = "**本次全部合法动作**（动作空间的掩码来源）"，`chosen_index` = 该动作在 `legal` 里的下标；策略头 = **`[n]` logits + 掩码 softmax**（`docs/TRAINING-V4.md §6` 多头表）。⇒ **"候选打分回归"不是新方向，它就是现状**（要换的只是**损失形态**，不是表示）。 |
| **想解决什么** | 现状是"在 n 个候选上做**分类**"，n 随局面变（弃牌最多 ~14，鸣牌段另有键）⇒ **探索维度 = n**。想缩的是"策略一次要在多大的离散集合上分概率质量"。 |
| **候选 A：先排序 / 分段** | **做法**：两级决策 —— 先用便宜的"段头"（牌种族 / 安全度段 / 是否鸣牌段）挑一段，再在段内挑候选；每级选择数从 n 降到 ~√n 量级，**联合分布不变、但每一步的条件分布更好学**。**与现状的区别**：把"一次性 \|n\| 分类"改成**序贯 + 因子化**，是结构改动。 |
| **候选 B：候选打分回归（⚠ 作为对照，不是新方向）** | **做法**：把分类损失换成 listwise / ordinal 排序损失，网络输出与张量表**不变** ⇒ 三端契约不动、可纯离线先测。判据仍走 §12.5。 |
| **成本** | B：**纯 Python，1 天** + 1 季（≈65 min）+ 判决（≈50 min）。A：动策略头 ⇒ **三端**（`net.bin` 张量表 + Java/C++ 镜像 + golden 夹具重出，即 `docs/TRAINING-V4.md §14.3` 的 P4 代价）⇒ **3~5 天** + 夹具。 |
| **判据** | 离线只能用"学没学到"的探针（候选 top1 / CE）；⛔ `engine_top1` **不是**强弱判据（它与闸门符号相反且两边都显著）。**强弱仍只能由 §12.5 答**。 |
| **⛔ 已知否证 / 区别** | `cand.derived` 是**策略命脉**（关掉它 top1 0.871→0.480、policy CE 0.35→1.52）⇒ **不许删/降候选派生量**。与 B 路（搜索排序当标签）的区别：这里动的是**策略头的参数化/损失**，**不引入任何外部标签源**。 |

### 12.3 方向三：搜索替代策略梯度 —— 上界已被实测钉住

| 项 | 内容 |
| --- | --- |
| **实测现状**（`NOTES.md §6.5 第六十四轮`） | ① 相对 teacher 的**改判率只有 0.95%**（**423 / 44,566** 可改判子集；独立交叉验证 0.86%，**190 / ~22k**）；② **鸣牌段 15,406 行 100% 原样返回 teacher**（构造如此）；③ teacher 立直的 1,397 个决策里只改判 **3 次（0.21%）**；④ 改判的 `ΔU` 最小 303 / 中位 420 / 最大 490 ⇒ **全是刚过 `margin=300` 的边际翻转**；⑤ 它与 `g08` 差的 26% **几乎全是 `teacher≠g08`**（search 只把结果挪 **0.42pp**，而且**朝 `g08` 挪**）。 |
| **想解决什么** | 若搜索能覆盖**全动作空间**（含鸣牌/见逃/默听），它可能提供**不依赖 teacher 的**行为策略或优势源。 |
| **具体做法（按顺序，前一步不过就不做下一步）** | ① 先给 `SearchPolicy.utility()` **补齐缺失项**（现在见逃/默听**没有任何项**，鸣牌段直接透传 teacher）；② 用**已有的廉价量**重测改判率（Java 生产者 200 场 + `V4Probe <g08>` 逐行取 argmax，与第六十四轮同一套脚本）；③ 只有改判率 **≥2%**（B 路当时定的"值得蒸馏"线）才谈下一步。 |
| **成本** | ① 实现 **2~3 天**；② 量改判率：200 场采集 **十几分钟** + 分析分钟级；③ 若真进：在线搜索的**每决策成本未测**（现前向 22.50 ms/决策；搜索要评估每个候选的 rollout/DFS，量级只会更大）⇒ **采集吞吐会成为新瓶颈**（35 场/s @24 workers 是当前基线）。 |
| **可能收益（诚实上界）** | 上界**已经由 ①⑤ 钉住**：最多只在那 ~1% 的边际决策上有新信息，而"边际翻转"意味着"搜索认为略好"的那部分本身是脆的。⇒ **它支撑不起一次蒸馏，更支撑不起在线替代。** |
| **结论** | **不作为主线**；只在"§12.1 的 A/D 用完仍然看不见任何位移"时，作为**最后一个候选**按 ①②③ 的顺序做，且**先跑 ② 的 200 场量改判率**（这一步成本最低、杀得最快）。 |
| **⛔ 已知否证 / 区别** | B 路否证的是"把**现成的排序**当**监督标签**"（→ `--label-policy` 那 5 处改动不实现）；本方向问的是"把搜索当**行为策略/优势源**"。两者**共享同一个上界证据**（改判率），所以"先补齐动作空间再量改判率"是**唯一**能把它与 B 路区分开的动作；量完仍 <2% ⇒ **永久关闭**。 |

### 12.4 方向四：算力效率（把"判决"从奢侈品变成日用品）
