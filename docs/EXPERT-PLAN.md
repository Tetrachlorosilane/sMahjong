## 0. 为什么走这条路（一句话）

**实测结论：现有单线 RL 的"每轮更新"对强度的期望效果与 0 不可区分**（10 代链 −4.26 显著负、24 代链 18,000 场合并不显著 ≈ −0.30 ⇒ **链级符号不稳定**），
而**画像能看出风格差异**（立直率 19% vs 36%、副露率 15% vs 51%、平均打点 5,840 vs 7,244）⇒ 与其继续押"单线变得更强"，不如**按维度分线造专家、再用场景化权重组合**。

## 3. 每条线的规格卡

> ⚠ **本节是计划原文（"要造 / 先做"）**，三张卡都已经按它跑过。**终点判决在 §11**，一句话版：
> 打点线 **+0.00 [−0.96,+1.00] n=12,000**（打点确实 +358⚠ **跨批次拼合，见 §15.0**，但顺位点不动）、
> 防守线**曾**合并出唯一的显著为正（+0.867 n=24,000）而**同配方复现 −3.54 n=12,000 ⇒ 撤回**、
> 和率线 **−1.12 [−2.09,−0.17] n=12,000**。§11 另有方向测试 +0.30 [−0.67,+1.27] n=12,000。

> 通用：每线都用现成回路（`tools/run-league.ps1`），**每代换新牌山**、候选 **SHA256 去重**、`--workers 16`、决策规模 1000 场/代；
> 判据**只走闸门**；画像用于**描述风格与检查护栏**，不用于判强弱。

### 3.1 打点线（**唯一已认证**，先做）

| 项 | 内容 |
| --- | --- |
| 目标轴 | 平均打点、満貫以上率（按 `limit` 口径更可信）、跳満/倍満率 |
| 护栏轴 | 顺位点 / 平均得点**不许显著更差**；和率掉幅 **≤1 pp**（现成专家 `14-g05` 已经掉了 1.8 pp，**这是要修的**） |
| 种子 | **`v4-league14-g05`**（不是 g08 —— 唯一有 CI 支持的起点） |
| 对手池 | **g08 必在** + `14-g05` 自己以外最近两代 + teacher；池里**不要**放低打点型（`10-g01`） |
| 课程方向 | 提高"立直/宝牌/副露搭子价值高"局面的权重；**奖励仍用顺位点**（⛔ 别换 `hand_delta`，那会重演 A 路"更贴标签却更差"） |
| 判据 | ① 闸门 vs **g08**：CI 排除 0 且为正；② 画像：平均打点 ≥ `14-g05` 且**和率差幅收窄到 ≤1 pp**；③ 连续 3 代不达标 ⇒ 停线 |
| 预算 | 先 **10 代（≈65 分钟/代含判决 ⇒ 约 2 小时）**，再按结果加长 |

## 4. 每线的训练流程（每代 8 步，全部已有工具）

1. **采集**：`X,X,对手,对手 --rotate`（⛔ **禁止镜像 `X,X,X,X`** —— 完场轴会退化，`Σplacement=10` ⇒ 平均顺位恒 2.5）
2. **轨迹校验**：`tools/selfplay-check.mjs`（含 `hand` 行的役种断言）
3. **紧凑集**：`dataset build`（现 88 s/1000 场）
4. **训练**：`pretrain`（PPO；`--kl-early-stop 0.10`、`--max-steps 2000`、`--val-every 100 --val-patience 5`；⛔ `--il-weight 0`、⛔ `--ref-beta 0`）
5. **导出** + 值头 audit（`--ev-ref legit --strict`）
6. **自评**：200 场 2+2 vs 上一代（**每代换 seed**，CI ±7.6 ⇒ 只看大变化）
7. **闸门**（唯一强弱判据）：多套新牌山，CI 排除 0 且为正才采纳
8. **画像**（风格与护栏）：`python -m mahjong_ml.v4 profile --run <本次 gate tag> --incumbent v4-league-g08`（⚠ **逐候选单独跑**，见 §8 撞键）

**开训前自检清单**（缺一不可）：`python/selfcheck.py`（659/0）· `node tools/doc-refs-check.mjs` · `trainer --selftest`（S: 那份）·
`java -jar server/build/mahjong-server.jar --selftest`（1445/0）· `node tools/trainer-v4-parity.mjs --golden` · `node tools/v4-cache-check.mjs` · `gate --self-check`。

## 5. 判据体系（唯一权威 = 闸门）

| 用途 | 判据 | 最小规模 |
| --- | --- | --- |
| **单代采纳** | 多套**新**牌山配对，**CI 排除 0 且为正** | ≥2 套 × 1000 场（±2.35） |
| **一条线是否成功** | 终点 vs 起点（**累积而不逐代把关**），4~8 套新牌山 | **6000~12000 场（20~40 分钟）** |
| ⚠ **一条线/一个专家的最终判定（2026-10-06 起）** | 闸门 + **≥24,000 场池化** + **超出噪声底** + **事先登记** | **24,000 场 ≈ 50 分钟**（§12.5） |
| **风格/护栏** | 画像轴（打点/铳率/和率/立直/副露/役种/巡目） | 同场多策略 ≥300 场/候选 |
| ⛔ 禁止 | `engine_top1` / 引擎 CE / 危险度旧口径 AUC / 任何"贴标签的读数"当强弱判据 | — |

**口径注意**：`win_rate`/`deal_in_rate` 是**每座位·小局**（不是每场，差 11~12 倍）；`満貫以上率` 用 **`limit`** 口径（点数口径会把亲家 12000 误判成跳満，已修但两口径仍不同）；
任何"我赢了"的结论都要带 **n 与 CI**；⚠ **CI 排除 0 只是入场券，不是判决**（§12.5：还要超出噪声底）。

## 6. 阶段 4：场景化多模型权重 —— **已判定（2026-10-06）：门控不值得训**

> 本节原文写的"先离线、后在线"**已经执行完**，结论与原文的乐观口气相反。**数字全部出自
> `docs/TRAINING-V4.md §16`**（估计量、三个坑与红证在 `NOTES.md §6.5 第六十七轮`）：

1. **离线加权分析 —— 做了**：四方同桌 4,000 场（8 套牌山 × 500 场，四位专家各坐四个座位）、
   45,559 小局 / 2,751,168 条决策；桶由**该座位自己的 obs** 决定（巡目 × 他家立直数 × 自家向听 × 是否已立直）⇒ 22 桶。
2. **oracle 上界（"每桶都交给当时最合适的专家"）**：**样本内 +0.780 顺位点/场**（已知高估）、
   **诚实（留一牌山）+0.327**；⚠ 相对**桶内标签置换零分布**只有 **z = +0.65**（零分布 sd = **1.008 顺位点/场**）。
3. **可切换桶清单**：22 桶里 **1 桶**通过（占局面 2.1%、+0.151 顺位点/场），而**纯噪声下平均就有 0.6 桶、最多 5 桶**
   ⇒ 那份清单是**假阳**，拿不出学习目标。
4. **门控本身的增量 = −0.166 顺位点/场**：把"按桶切换"和"干脆只选一位全局最强（`atk2` = +0.493）"放在同一把尺子上比，
   **按桶切换更差**；三种桶粒度（22 / 12 / 15 桶）结论一致（诚实上界 +0.26~+0.36、增量全为负）。
5. ⚠ **另一条同样重要**：「只换一位专家、不门控」也没什么可拿 —— 最强的 `atk2` 对 `g08` 只有
   **+0.163 [−1.357,+1.502]**（8 套配对，胜 4 负 4）。
6. ⇒ **两条路（择优 / 抉择）在这批专家上都没有收益**。要走的不是"怎么选"，而是
   「**先把专家练到显著更强**」—— 而"买分辨率"那条曾被否决的路，前提（判决成本）已经变了（§12.4/§14c）。

## 8. 已知陷阱清单（**每条都踩过**，动手前扫一遍）

1. **候选伪重复**：132 个 `net.bin` 只有 109 个不同 ⇒ 选题必须先 SHA256 去重；同配置 + 同种子会**逐字节复现**同一个候选。
2. **共用牌山 ⇒ 判决不独立**：历季 19 个判决共用同一对牌山；**每代必须换新牌山**，且 `seed` 与采集 seed **错开**。
3. **套间散布 ≫ CI**：换牌山能摆动 ~4 点 ⇒ 判决要报"套间散布 / CI 半宽"，>1× 时只能读成"条件于这几套牌山"。
4. **`profile` 逐场序列撞键**（**2026-10-05 已修**）：多 run 共用同批 seed 时现任序列被覆盖 ⇒ 修法是键 = `(墙 seed, run 序号)`；修前"跑 15 个 tag 一次出表"会把唯一的专家抹掉（读数见 `docs/TRAINING-V4.md §15.7.3`）。
5. **`selfcheck` 一条负向对照曾是假绿**（**已修**）：缓存键含 `mtime_ns` 而 Windows 分辨率 ~15.6 ms、写入字节数不变 ⇒ 命中旧缓存；修法是显式清记忆表 + 夹具少一个字节。
6. **镜像自对弈退化完场轴**：一律 `X,X,对手,对手 --rotate`。
7. **A/B/C 三条标签路已全部关闭**（引擎牌效 / 搜索算子排序 / 真手牌 oracle）⇒ **不要重做**；危险度标签同理。

### 12.0 本规划的起点：阶段 4 已收口，但"练出更强专家"没被否证

- 阶段 4 判定 **门控不值得训**（§6 · `docs/TRAINING-V4.md §16`）。
- ⚠ **没有被否证的那一条**：`TRAINING-V4.md §16.7` 第 5 条 —— "要走的不是怎么选，而是**先把专家练到显著更强**"。
  它卡在"**尺子看不见**"（每轮位移 ~1 点 vs 分辨率/散布），而**尺子的成本前提刚刚变了**（§12.4）
  ⇒ 它是 §12.1 / §12.5 的间接动机，**本身不构成独立方向**（它仍属"换配方"，已试过 6 条）。

### 12.1 方向一：优势源（**优先，唯一有机理证据**）

| 项 | 内容 |
| --- | --- |
| **想解决什么** | **一步更新在期望上不为正**。现状 = `--advantage hand` + `--rank-weight 0.2`（`tools/run-league.ps1:145-146`）。 |
| **现状为什么可疑**（不是猜测，是回路自己的注释） | `python/mahjong_ml/v4/loop.py:146-148`：「v4 回路原来固定'自己×2 + teacher×2'，于是**结果奖励里关于'通用强度'的信息很少** —— 对手永远是同一批（teacher 与自己的上一代），**你变强变弱都在同一张桌子上**」。 |
| **候选 A：更大批量 / 更多局** | **做法**：配方一个字不改，只放大每代场次（1000 → 4,000/代）与 batch；看 `std(A_raw)`、KL、`clip_frac` 是否按 1/√n 收。**它解决什么**：奖励信息量不变，**信噪比**变好。 |
| **候选 B：per-decision 信用分配** | **做法**：把"小局级 + 终局顺位点"细化到逐决策 —— 走 `docs/TRAINING-V4.md §14.2` 的手级 GAE（λ<1 + bootstrap，`next_index` 由 `(game, hand_no, seat)` 构造，**已经落地过**），或把逐决策牌效/进张变化做成 shaping 奖励。 |
| **候选 C：用搜索得到的 Q 差当优势** | **做法**：把搜索的评估值差当 **critic 的一侧**（优势 = 搜索 Q − V），**不是**当监督标签。 |
| **候选 D：只降方差、不找新信号** | **做法**：只做 baseline 重标定（`--baseline-fit scale`，已落地）+ 更大批量，**不引入任何新奖励**。这是**唯一数学上保证不劣**的一条（基线是状态函数 ⇒ 线性重标定不改梯度期望、只降方差）。 |
| **成本** | A/D：改参数 + 1 季（10 代 ≈ **65 min**）+ 判决（24,000 场 ≈ **50 min**）⇒ **≈2 h/次**。B：`adv.py` 侧 ≈ **1 天** + 同上。C：还要搜索策略接口（见 §12.3）⇒ **≥3 天**。 |
| **判据** | §12.5（闸门 + ≥24,000 场池化 + **超出噪声底**）；⚠ 单线链另加"\|Δ\| 超过链间散布 **≥4 点**"才谈符号。 |
| **⛔ 已知否证 / 区别** | 否证在案的：A 引擎牌效标签（−12.65）、critic 四条（加宽读出头 +0.019 / PBRS `A'=A` / 绝对门槛 / 拿标签侧真值当参照）、`--ref-beta` 太大 ⇒ no-op。**区别**：**A/D 不引入任何新监督信号**（只改信噪比 / 只降方差）；**B 的信号是手级 TD 回报**（不是引擎牌效、不是搜索排序的静态排序）；**C 用的是搜索的数值 Q 差**（不是它的候选排序表）。 |

### 12.2 方向二：动作空间（先纠正一个既有事实）

| 项 | 内容 |
| --- | --- |
| ⚠ **既有事实（先说清）** | **"136 张牌的选择"这个描述不成立**：动作空间**早就是引擎给的候选列表** —— `docs/PROTOCOL.md §8.2` 的 `legal[]` = "**本次全部合法动作**（动作空间的掩码来源）"，`chosen_index` = 该动作在 `legal` 里的下标；策略头 = **`[n]` logits + 掩码 softmax**（`docs/TRAINING-V4.md §6` 多头表）。⇒ **"候选打分回归"不是新方向，它就是现状**（要换的只是**损失形态**，不是表示）。 |
| **想解决什么** | 现状是"在 n 个候选上做**分类**"，n 随局面变（弃牌最多 ~14，鸣牌段另有键）⇒ **探索维度 = n**。想缩的是"策略一次要在多大的离散集合上分概率质量"。 |
| **候选 A：先排序 / 分段** | **做法**：两级决策 —— 先用便宜的"段头"（牌种族 / 安全度段 / 是否鸣牌段）挑一段，再在段内挑候选；每级选择数从 n 降到 ~√n 量级，**联合分布不变、但每一步的条件分布更好学**。**与现状的区别**：把"一次性 \|n\| 分类"改成**序贯 + 因子化**，是结构改动。 |
| **候选 B：候选打分回归（⚠ 作为对照，不是新方向）** | **做法**：把分类损失换成 listwise / ordinal 排序损失，网络输出与张量表**不变** ⇒ 三端契约不动、可纯离线先测。判据仍走 §12.5。 |
| **成本** | B：**纯 Python，1 天** + 1 季（≈65 min）+ 判决（≈50 min）。A：动策略头 ⇒ **三端**（`net.bin` 张量表 + Java/C++ 镜像 + golden 夹具重出，即 `docs/TRAINING-V4.md §14.3` 的 P4 代价）⇒ **3~5 天** + 夹具。 |
| **判据** | 离线只能用"学没学到"的探针（候选 top1 / CE）；⛔ `engine_top1` **不是**强弱判据（它与闸门符号相反且两边都显著）。**强弱仍只能由 §12.5 答**。 |
| **⛔ 已知否证 / 区别** | `cand.derived` 是**策略命脉**（关掉它 top1 0.871→0.480、policy CE 0.35→1.52）⇒ **不许删/降候选派生量**。与 B 路（搜索排序当标签）的区别：这里动的是**策略头的参数化/损失**，**不引入任何外部标签源**。 |

### 12.3 方向三：搜索替代策略梯度 —— 上界已被实测钉住

| 项 | 内容 |
| --- | --- |
| **实测现状**（`NOTES.md §6.5 第六十四轮`） | ① 相对 teacher 的**改判率只有 0.95%**（**423 / 44,566** 可改判子集；独立交叉验证 0.86%，**190 / ~22k**）；② **鸣牌段 15,406 行 100% 原样返回 teacher**（构造如此）；③ teacher 立直的 1,397 个决策里只改判 **3 次（0.21%）**；④ 改判的 `ΔU` 最小 303 / 中位 420 / 最大 490 ⇒ **全是刚过 `margin=300` 的边际翻转**；⑤ 它与 `g08` 差的 26% **几乎全是 `teacher≠g08`**（search 只把结果挪 **0.42pp**，而且**朝 `g08` 挪**）。 |
| **想解决什么** | 若搜索能覆盖**全动作空间**（含鸣牌/见逃/默听），它可能提供**不依赖 teacher 的**行为策略或优势源。 |
| **具体做法（按顺序，前一步不过就不做下一步）** | ① 先给 `SearchPolicy.utility()` **补齐缺失项**（现在见逃/默听**没有任何项**，鸣牌段直接透传 teacher）；② 用**已有的廉价量**重测改判率（Java 生产者 200 场 + `V4Probe <g08>` 逐行取 argmax，与第六十四轮同一套脚本）；③ 只有改判率 **≥2%**（B 路当时定的"值得蒸馏"线）才谈下一步。 |
| **成本** | ① 实现 **2~3 天**；② 量改判率：200 场采集 **十几分钟** + 分析分钟级；③ 若真进：在线搜索的**每决策成本未测**（现前向 22.50 ms/决策；搜索要评估每个候选的 rollout/DFS，量级只会更大）⇒ **采集吞吐会成为新瓶颈**（35 场/s @24 workers 是当前基线）。 |
| **可能收益（诚实上界）** | 上界**已经由 ①⑤ 钉住**：最多只在那 ~1% 的边际决策上有新信息，而"边际翻转"意味着"搜索认为略好"的那部分本身是脆的。⇒ **它支撑不起一次蒸馏，更支撑不起在线替代。** |
| **结论** | **不作为主线**；只在"§12.1 的 A/D 用完仍然看不见任何位移"时，作为**最后一个候选**按 ①②③ 的顺序做，且**先跑 ② 的 200 场量改判率**（这一步成本最低、杀得最快）。 |
| **⛔ 已知否证 / 区别** | B 路否证的是"把**现成的排序**当**监督标签**"（→ `--label-policy` 那 5 处改动不实现）；本方向问的是"把搜索当**行为策略/优势源**"。两者**共享同一个上界证据**（改判率），所以"先补齐动作空间再量改判率"是**唯一**能把它与 B 路区分开的动作；量完仍 <2% ⇒ **永久关闭**。 |

### 12.4 方向四：算力效率（把"判决"从奢侈品变成日用品）

## 14. 结论肯定性审计（含"翻盘可能" / "我是否武断"）

> **三档**：**确立（硬）** = 有多个独立读数、量级远超噪声、且机理清楚；**条件性** = 有实测但依赖某个**未验证的假设**；

> 每条都写：**证据（n/CI/口径）· 依赖哪个假设 · 什么实验能推翻它（翻盘条件，具体到命令与成本）**。

### a) 「单线练 10 代不能稳定变强」 —— **条件性**

- **证据**：打点线 **+0.00 [−0.96,+1.00] n=12,000**；和率线 **−1.12 [−2.09,−0.17] n=12,000**；防守线首测合并 **+0.867 [+0.188,+1.560] n=24,000**、
  **同配方复现 −3.54 [−4.50,−2.58] n=12,000（8/8 为负）⇒ 撤回**；方向测试 +0.30 [−0.67,+1.27] n=12,000；历季 24 代 ≈−0.30、10 代 −4.26。
- **依赖的假设**：只试了**约 6 条配方**、**每条只跑一次**、**每代 1000 场**（数据量小）；
  闸门配对**无偏**但分辨率有限（T1 等价候选 Δ=−0.13、胜 996 / 负 1004）；**优势源固定**为 `--advantage hand` + `--rank-weight 0.2`。
- **翻盘条件**：**换优势源/加数据量后重跑并池化**。命令与成本：
  ```powershell
  # ① 新配方 1 季（10 代）：每代 ~6.5 min ⇒ ≈65 min（不加每代闸门）
  pwsh -File tools\run-league.ps1 -Generations 10 -Label <新标签> -Seed <未占用> -RefBeta 0 -IlWeight 0 -NoGate
  # ② 两次独立采集各 12,000 场（8 套 × 1500，新牌山 seed）⇒ 2 × ~25 min
  python -m mahjong_ml.v4 gate --incumbent tools\build\v4-league-g08\net.bin `
      --candidate tools\build\<新标签>-g10\net.bin --seeds <8 个新 seed> --games 1500 --block 1500 `
      --workers 16 --out S:\mahjong-training\gate --tag <新标签>-endpoint --producer cpp
  # ③ 池化（只读）⇒ 分钟级
  python\regate_gate.py --tags <新标签>-endpoint,<新标签>-confirm --incumbent v4-league-g08 --candidate <新标签>-g10
  ```
  ⇒ 一次翻盘尝试 **≈2.5~3 h**。**判定要用 §12.5**（|Δ| 还要大于链间散布 ≥4 点才谈符号）。

### b) 「按局面切换现有专家无收益」 —— **条件性（最该被质疑的一条）**

- **证据**：oracle 抉择器**诚实上界 +0.327 顺位点/场**（留一牌山；样本内 +0.780 = 已知高估）；
  相对**桶内标签置换零分布** **z=+0.65**（sd **1.008 顺位点/场**，K=20）；**门控增量 −0.166**（vs 只挑全局最强 `atk2` 的 +0.493）；
  22 桶仅 1 桶通过而**纯噪声平均 0.6 桶（最多 5）**；三种桶粒度结论一致（诚实上界 +0.26~+0.36、增量全负）。
- **依赖的假设（关键）**：**反事实代理** —— 用"该专家在**该桶里的实测收支**"代替"**把专家真的搬到 `g08` 座位**"。
  桶 → 专家的选择在**同一批牌山**上是**被选出来的**（`max_e`），诚实性靠留一修补，但**从未真正把路由策略拿去打**。
- **翻盘条件**：**真实重放实验** —— 把"桶 → 专家"表实现成一个**路由策略**，在**新牌山**上与 `g08` 逐场配对，然后按 §12.5 判决。成本：
  ```powershell

  # ② 采集：四位同桌、只把"按桶切换"这一席换成路由策略

      --seed <新 8 套> --out S:\mahjong-training\raw\stage4b\wN      # 8 × ~117 s ≈ 16 min
  & $env:MAHJONG_TRAINER features S:\mahjong-training\raw\stage4b\wN --workers 12   # 8 × 3.6 s

  ```
  ⇒ **≈半天 + 1~1.5 h 机时**。⚠ 但**先验概率很低**：门控增量在诚实口径下**已经是负的**，
  而且"只换一位专家"的**直接**读数（无需代理）也只有 **+0.163 [−1.357,+1.502]**（4 胜 4 负）⇒
  要翻转得**同时**推翻"代理偏差"与"直接测量"两条。

### c) 「噪声底 1.0 / 需 ≥24,000 场」 —— **条件性**

- **证据**：阶段 4 的**桶内标签置换零分布**（最严口径 `bucket_hand`，K=20）：**均值 +1.5 ± 41.6 点/小局**
  = **sd 1.008 顺位点/场**、**极差可达 2.4~2.9**（`bucket_wall`：sd 1.513、max 2.854）；
  真实读数 z=+0.65。闸门侧：单次 12,000 场 **±0.96**、合并 24,000 场 **±0.68**；
  套间散布 **2.657 / 0.686 = 3.87×**；12,000 场那份 `p=0.1319` 的输入**喂两遍**会假造成 `p=0.0326`。
- **依赖的假设**：零分布是在**当前采集规模（4,000 场 / 8 套牌山）**与**当前牌山抽样**下、用 **K=20** 次置换量的；
  ⚠ 而且**两条噪声源不通用**（闸门配对用链间/套间散布；抉择器用置换零分布）—— 本节**不把它们混成一个数**。
- **翻盘条件**：**更大规模下的零分布重测**。命令与成本：
  ```powershell
  $env:MAHJONG_TRAINER='S:\mahjong-training\tools\trainer\trainer.exe'
  # 采集翻倍（16 套 × 500 场）：16 × ~2 min ≈ 32 min；分析（读盘 + K=20）≈ 30~60 min
  & $env:MAHJONG_TRAINER selfplay 500 --workers 12 --rotate --aux --policy "net:<g08>,net:<atk2>,net:<def3>,net:<win>" `
      --seed <新 16 套> --out S:\mahjong-training\raw\stage4c\wN
  python -m mahjong_ml.v4.chooser_probe --dir S:\mahjong-training\raw\stage4c --perm-reps 20 --out S:\mahjong-training\reports\stage4c-chooser.json
  ```
  ⇒ **≈1~1.5 h**。若 sd 随规模**显著下降**（例如 →0.5），则"1.0 的噪声底"被推翻。

### d) 「便宜 / 开门方向必掉强度」 —— **确立（硬）· 全清单里最硬的一条**

- **证据**：两条**独立**路线**同向**且量级远超噪声 ——
  ① **标签路**（`--il-weight 1`，引擎牌效标签）：**−12.65 [−14.92,−10.42] n=2,000**（CI 半宽 2.25，**一次就抓住**；
  机制：平均打点 **7037→6010**、和了率 **24.1%→20.8%**）；
  ② **对手池路**（和率线，`{10-g01}` 便宜手）：**−1.12 [−2.09,−0.17] n=12,000**（打点 −54、副露 +4.0 pp、和率 −0.5 pp）。
- **依赖的假设**：这两种操作化（引擎牌效标签 / 便宜手对手池）足以代表"便宜/开门"这个方向；
  闸门**无偏**（T1 已验证）；`engine_top1` 涨了（0.6345→0.704）**证明监督信号确实吃进去了**，不是"没接上"。
- **翻盘条件**：换一种操作化（**把打点当护栏**、只在副露/食い断桶里加信号），池化 ≥24,000 场且**超出噪声底**。成本：

### e) **不能外推的部分**（⚠ 明确写出来，防被误引） —— **确立（边界声明）**

我们**只动过**：PPO 配方（学习率/KL/优势口径/奖励尺度）、**标签源**（引擎牌效 / 搜索排序 / 真手牌 oracle，三条全关）、**对手池**。
我们**从未动过**：**网络容量**、**表示**（特征/张量块）、**动作空间**、**搜索**（在线）、**离线 RL**。

  而不是"给专家喂更强的信号"）。

- **翻盘条件**：任一项外推方向的**首次实测** —— 成本见 §12.1（优势源 ≈2 h/次）、§12.2（动作空间，纯 Python 1 天起）、

### 15.2 轴二：风格可辨识度 / 多样性

| 项 | 内容 |
| --- | --- |
| **衡量什么（玩家的感受）** | 玩家能不能**感觉出"换了个对手"** —— 这是"可选对手"这件事的**全部意义**：四代网络打起来一模一样，多代就是摆设。 |

### 15.3 轴三：拟人度 / 自然度

| 项 | 内容 |
| --- | --- |
| **衡量什么（玩家的感受）** | "像在跟人打"还是"像在跟机器打"。网络打出**人类几乎不会打**的动作（反常动作）会让牌桌出戏 —— 玩家的原话通常是"这 AI 好怪"。 |
| **怎么量** | ① **分布距离**：把候选的画像轴与**真人牌谱**在同一套轴上的分布比（立直率 / 副露率 / 和了巡目 / 打点 / 铳率 / 平均役种数）；② **反常动作率**：逐决策与"人类动作条件频率"比，低概率动作（如"无筋中张立直宣言后打危险牌""能和不和且无顺位理由"）的占比；③ **格式侧已通**：客户端 `--export-tenhou` 导出的牌谱与**天鳳格式同构**（mjlog XML + `docs/input-json.md` 的 JSON 规格，`docs/DESIGN.md`「对局记录与回放」），所以"把我们的对局喂进天鳳系工具/复盘器"这条路是**通的**。 |
| **现有数据能不能算** | **半空白**。导出侧 ✅（`--export-tenhou` + 校验器 `tools/tenhou-log-check.mjs` 13 条）；⚠ **对照语料 ❌** —— 仓库里只有**导出器与校验器**，**没有真人牌谱语料**（`S:\mahjong-training` 下也没有 human/tenhou 目录）⇒ 这一轴的**对照源要新引入**（天鳳公开牌谱 / mjlog）。⇒ 现在**只能算"我们四代之间像不像"**，**算不了"像不像人"**；反常动作率也缺"人类动作频率表"。 |
| **判据（什么算好）** | ① 画像轴落在真人分布的**中心区间**（中心待语料到位后定）；② 反常动作率低于登记阈值（待定）；③ ★ **真人盲测里"这局是人是机器"的猜中率接近 50%** —— 这是唯一真正测"拟人"的判据，属 §15.8。 |

### 15.4 轴四：决策时延 / 节奏

| 项 | 内容 |
| --- | --- |
| **衡量什么（玩家的感受）** | 出牌要不要干等、鸣牌询问会不会卡、一巡要不要好久；以及"AI 的节奏像不像人"（人类会想一想再打，**瞬时出牌反而像机器**）。 |
| **怎么量（模型侧，全部离线可算，工具现成）** | `trainer v4bench <net.bin> <轨迹.jsonl>`（C++，逐段计时）· `tools.V4Probe --bench` / `--cache`（Java）。**实测（核准过的数字）**：<br>· **C++ 前向批处理化**（`docs/TRAINER-CPP.md` §6.24）：自对弈 **200 场** `net:g08 ×4` **311 s → 中位 53.8 s（5.8×）**；同机同批 **50 场 A/B 6.10×**；最终二进制再跑一次 **51.8 s**；每决策 worker 时间 **≈18.2 ms → ≈3.1 ms**（`v4bench` 单线程前向净 **17.34 → 1.70 ms**，档 1 单独是 12.41 ms）。AGENTS §6.5 记同一件事为 **6.14×（301 s → 49 s）**，200 场轨迹**逐字节不变**。<br>· **Java 服务端 v4 前向**（含特征，上了 L2 增量事件缓存）：**38.12 → 22.50 ms/决策（1.70×）**（`docs/HANDOVER.md` §2.17）；`docs/BOT-AI.md` §9 记 ≈**22.5 ms/决策**。⇒ **单决策量级 = 十几~二十几毫秒**（v3 大约 **1 ms**）。<br>· **并行度**：`--workers` 拐点 = **24**（32 逻辑核；8→24 约再快 2.5–3×，**32 无增益 / 1.37×**，且有发热降频）—— `AGENTS.md` §6.5 与 `TRAINER-CPP.md` §6.24。 |

### 15.5 轴五：不气人的行为

| 项 | 内容 |
| --- | --- |
| **衡量什么（玩家的感受）** | 会不会**被 AI 气到**。最典型三类：**无意义见逃**（明明能和却不和）、**明显送和**（把牌往对手手里送）、**卡住 / 崩局**（该他动却不动、整场静默死亡）。 |
| **怎么量** | ① **见逃**：引擎已把**三种振听 + 见逃记账**做全（`AUDIT S-45`：舍张/同巡/立直振听，判据 `SelfTest.furitenRuleTests`）⇒ "见逃次数 / 见逃时的巡目与打点差"**可离线统计**（`selfplay-check` 动作分布里的 `pass` 是它的上界）。⚠ **必须区分**有理由的见逃（终局顺位判断，`docs/DESIGN.md`「见逃」四条闸门）与**无理由见逃** —— **后者必须是 0**。<br>② **明显送和**：铳率 + **平均铳点** + **被自摸失点**（`profile` 三根轴都有），再加"**无筋中张立直宣言后仍打危险牌**"的逐决策计数（危险度是现成的 `Danger`，纯函数、可单测）。<br>③ **超时 / 卡顿**：`ask.deadline_ms` 到点 → 服务端**默认摸切**；判据工具现成（`tools/timeout-test.mjs` / `clock-test.mjs` / `riichi-stale-test.mjs`）。<br>④ **崩局率**：训练接口有硬纪律（策略**不许**把异常抛给牌桌线程、`decideBot` 必须兜底、`Table.playGame` 的异常兜底必须**广播终局**，`AGENTS.md` §6.5/§6.3），但"**整场静默死亡**"确实发生过（`AGENTS.md` §6.3 的吃碰校验那条）⇒ 体验口径登记 **崩局率 = 0**，判据 = 长跑 soak（`tools/trainer-soak-check.mjs`）+ `game_end` 必达。<br>⑤ ⚠ **结构性盲点（本节登记为"体验缺陷"）**：**抢杠不给询问机会** —— 抢杠**成立即结算**，不给被抢者与抢者"要不要和"的机会（`docs/DESIGN.md`「抢杠」段、`AUDIT S-57②`；加杠与国士抢暗杠两条路都自动成立）。⇒ 玩家"我其实不想抢 / 我想见逃"时**没有接口**，体感上是**被剥夺选择权**。同类登记：`AUDIT` 档 C 的**打点升级型见逃**（见逃去狙満貫/役満）**未实现**（`docs/DESIGN.md`「不做/妥协」），玩家会觉得"少了一个人味儿的抉择"。 |
| **现有数据能不能算** | **大部分能算**（见逃 / 铳点 / 超时 / 崩局都有现成工具与轴）；**"哪些算无意义""多气人"的阈值**要真人评分标定。 |
| **判据（什么算好）** | ① **无理由见逃 = 0**；② 铳率 / 平均铳点**不低于对手池中位**（别当"送和机器"）；③ 默认 20+5 下**超时计数 = 0**；④ **崩局率 = 0**（`game_end` 必达）；⑤ 结构性盲点**逐条登记在册**（允许存在，但**不许没人知道**）。 |

### 15.8 轴八：主观评分流程（真人盲测怎么做，以及"3 局不算数"）

**这是把上面七轴从"能算的代理量"变成"产品判决"的唯一通道。** 纪律与 §12.5 同源：**判据、样本量、场次写在开打之前**。

**① 样本量（低于这个数一律判无效）**

| 项 | 最低要求 | 为什么 |
| --- | --- | --- |
| 每个候选 | **≥ 8 局**（同一批牌山、同一规则预设） | 一局麻将的方差极大（自摸/里宝/放铳的运气成分远大于风格差） |
| 评分者 | **≥ 3 位真人** | 单人偏好是噪声（"我就喜欢立直"不是产品结论） |
| 每候选评分份数 | **≥ 24 份**（3 人 × 8 局） | 与上面两条等价，写出来是为了**当场能查出"只测了 3 局"** |
| 对照 | 同时段内**至少再跑一个已知候选**（如现任 `g08`） | 没有对照就没有"好/差"，只有"还行" |

⛔ **"我只测了 3 局"这种数据一律判无效**，不许写进结论：它连"这两代是不是同一个东西"都答不了（顺位点族的口径下，
200 场才是一个观测序列、**≥24,000 场才算池化判决**，§12.5）—— 真人 3 局的信息量比它低好几个数量级。

**② 盲测设计（五条，缺一条就有偏）**

1. **不告诉评分者是哪一代**：界面只出现 A/B/C 代号，**每局随机换名**；
2. **同一批牌山**（至少同一个小局集合），否则"他运气好"会冒充"他打得好"；
3. **座位随机化**（照 `--rotate` 那套），避免"坐庄多就好玩"；
4. **同一评分者不连续打同一代**（顺序随机化），避免新鲜感/疲劳冒充风格差；
5. ⚠ **允许并记录"分不出"**：说不出来就记"分不出"，**不许逼他挑一个** —— 逼迫会把噪声变成信号（这正是 `docs/TRAINING-V4.md` §16.4 里"假阳"的真人版）。

**③ 必答问题清单**（每条 1–5 分 + "分不出"；题目与七轴一一对应）

| # | 问题 | 对应轴 |
| --- | --- | --- |
| 1 | 这一局打得**刺激**吗？（有没有満貫以上的大手、出现时爽不爽） | §15.1 |

**④ 判据**

1. 每个候选都要报**均分 + 分不出率 + 份数**（三个数缺一不可）；
2. 候选之间比**配对**：同一评分者、同一批牌山，报差值的 CI/符号检验（口径同 §12.5 的"事先登记"）；
3. ⛔ **在拿到真人评分前，任何"这个模型好不好用"的结论都不成立** —— 包括"它虽然闸门打平、但体验更好"这句**正面**结论：
   它同样**没有被测过**。现在能说的只有"**这一轴还没量**"（§15.9 的空白表）。

### 16.2 "加一个可选对手"到底要不要重新打包 —— 现成路径（读 `docs/BOT-AI.md` 的机制，不猜）

**结论：不要。加一代可选对手是"丢一个目录"级别的操作，客户端与服务端都不用改。**

| 问题 | 答案（机制出处 = `docs/BOT-AI.md` §1/§2/§3/§4） |
| --- | --- |
| 服务端要改代码吗？ | **不用**。服务端**启动时自动挂载**启动目录下的 `bot-ai/`，「**一个一级子目录 = 一个可选 AI**」（与 `replays/`、`players/` 同层）。加一代 = 往 `bot-ai/` 里丢一个目录，**不用改代码、不用加启动参数、重启以外没有任何操作**。 |
| 客户端要改吗？ | **不用**。客户端只看到**名字清单**（`hello_ok.bot_ais[].name` / `room.bot_ai`），建房间/等待室按名字选（`create_room.bot_ai` / `set_bot_ai`）。⚠ 清单里**故意不发** `spec`（策略串是服务器本机绝对路径）。 |
| 要重新打包发布资产吗？ | **随发布包出货才要**：`python -m mahjong_ml.packbot --out bot-ai --from-ckpt <v4 ckpt> [--include …] --zip release/bot-ai` ⇒ 每个包一个**独立 zip**（解压到 `bot-ai/` 下即可用）+ 一份 `README.txt`；服务器 zip 里 `bot-ai/` 与 `jar`/`start.sh` **同层**，且 `./update.sh` **不动 `bot-ai/`**（升级不丢这几代，`docs/DEPLOY.md` §3.5）。⚠ v4 权重走 `packbot` 会自动走 `v4/export.py`（`net.bin` **格式 2**，服务端 `NetWeights` 按 `format` 分派到 `V4Policy`）。 |
| 有没有"不打包先试"的路？ | **有两条**：`--bot-ai-dir <目录>`（可重复；**直接指到训练侧 `ckpt/`**，没有 `bot.json` 也能用）· `--bot-ai-reg <名字>=<策略串>`（点名注册/覆盖，后面的赢）。⇒ 试一代新权重**不用碰发布包**。 |
| 名字有什么硬规则？ | **可打印 ASCII**（进报文，e2e 的 ASCII 审计会红）；**不许含 `,` `@` `#`**（策略串文法保留字）；`kind:net` **不许**占用 `teacher`/`first`/`pass`/`random` 四个内置锚点；**重名 = 覆盖**（后面的赢），不报错。 |
| 包坏了怎么办？ | **只跳过它一个**（WARN），其余包照常用；只有**点名的**（`--bot-ai` / `--bot-ai-reg`）坏了才启动期报错。 |
| 换成权重之前要知道什么？ | **v4 的三条限制**（`docs/BOT-AI.md` §9）：① v4 的 `--alpha auto` **未实现**（传了直接报错，要用 `--alpha <数值>`）；② v4 前向实测 ≈**22.5 ms/决策**（含特征）⇒ **当 bot 可以、当自对弈主力还是太慢**（v3 约 1 ms，§15.4）；③ 权重 **5.2 MB/个**（v3 是 1.0 MB）⇒ 包与"一包全给"都比 v1.11.0 大一个量级。 |
| **本仓库现状（实测，不猜）** | `bot-ai/`（运行时数据、不进仓库）里现在有 **8 个包**：`teacher` / `first` / `pass` + `ppo-v3-g01-g01` + `v4-bc-004` / `v4-p3-001` / `v4-ppo-001` / **`v4-league-g08`** ⇒ **现任已经是"可选对手"了**；而 `atk2-g09` / `def3-g08` / `win-g10` / `10-g01` **都还没进 `bot-ai/`** —— 要出货就照上表打一个包。 |
| 怎么验"包能挂上"与"包能打"？ | ⚠ **两件事分开验**（`docs/BOT-AI.md` §8 与 `AGENTS.md` §6.6）：① 启动日志的清单 + `node tools/bot-ai-test.mjs 127.0.0.1 10086`（清单/建房/换一代/非房主被拒/未知名字与路径串被拒）；② **真打一场**（`--selfplay 1 --policy net:<包里的 net.bin>` 那类），别只看挂载成功。 |

### 16.3 这张表怎么用（谁决定出货）

1. **强度列**只回答"它在顺位点尺子上如何" —— **`g08` 之外的候选打平或更差，都不是"淘汰"理由**；
2. **出货判断的顺序**：先补 **§15.2/§15.3 的工具与语料**（距离/可分性、真人牌谱）→ 再跑 **§15.8 的盲测** →
   最后按 **§15 各轴的判据**表决；⚠ **在真人评分之前，"这个模型好不好用"不成立**；
3. **优先级（产品任务，不是强度任务）**：把"**可选对手的风格多样性**"当**产品目标**推进 ——
   至少给出**四种能感知的不同口味**（现任中性 / 高打点立直 / 副露流 / 速度快攻），
   每种搭配"它适合谁、它逼你练什么"的一句话定位；
   ⛔ **不要再拿顺位点尺子继续磨**（那是 §12 的议题，且已有"链间散布 ≥4 点"的天花板，§12.4）；
4. ⚠ **本节不授权任何代码/配方改动**：所有"要修/要补"的东西（抢杠见逃接口、默听率字段、解释通道、真人采集）**只登记在这里**；
