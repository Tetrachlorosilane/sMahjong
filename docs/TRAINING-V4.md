## 1. 目标与非目标

### 1.1 目标（按优先级）

| # | 目标 | 可判据的表述 |
| --- | --- | --- |
| **G1** | **强于内置 teacher** | 2+2 同牌山配对（相邻 + 对家两种座位配置）vs `teacher`：**Δ ≥ +2 顺位点且 95% CI 排除 0**；阶梯 θ−teacher 的 CI 同样排除 0；对 `first`/`random` 不退 |
| **G2** | **信息平价**：人类能看到的全都有，看不到的全都没有 | `docs/FEATURES-V4.md` §1 的两张清单，逐项有自动化判据（§9 判据①②） |
| **G3** | **每块信息的价值可证** | 消融矩阵：逐块关掉，同种子配对 CI 说出"这块值多少"（§8.3） |
| **G4** | **能上线**：纯 Java 手写前向 + 增量推理，服务端可直接加载运行（**不设单决策耗时门槛**） | `FEATURES-V4.md` §8 的实测口径 + `tools/V4Probe --bench/--cache` |
| **G5** | **可复现**：同种子产物逐字节相同；增量 == 全量重算 | §8.6 的两条硬闸门 |
| **G6** | **训练期封闭 + 场外均衡**（防"框外过拟合"） | 规范 §1.4 三条红证全绿（标签不进输入 / 隐藏量不进 obs / 奖励不含过程隐藏量）；每轮 `balance.json` 无超阈，**超阈轮次不得进判据**（§7.4、§7.5） |

### 1.2 非目标（明确不做，免得跑偏）

- ❌ **不追求"输入与 teacher 同口径"**。v3 的立直宣言巡目、牌河顺序、副露来源都是**刻意**不做的
  （`NOTES.md` §6.5 审计条目③），v4 全部要做 —— 代价是换标签源（§2.2）。
- ❌ **不做搜索**（MCTS/CFR 类）当主方法：Java 侧要纯手写前向，搜索会让自对弈慢一个量级。
  搜索**最多**当离线标签源（`docs/TRAINING.md` §10 的第 2 条未决问题）。
- ❌ **不引入新的第三方 ML 依赖到服务端**（Maven/ONNX/PyTorch 一律不进 `server/`）。
- ❌ **不改规则引擎的判定逻辑**：v4 只动"观测 → 输入"与"训练侧"，`Round`/`Evaluator` 的行为不变。

### 1.3 保留的硬限制（不可协商）

| 项 | 上限 | 出处 |
| --- | --- | --- |
| 参数量 | ≤ 3 M（目标 1.0–1.5 M） | `docs/TRAINING.md` §3.3 |
| GPU | ≤ 80% 占用、≤ 4.5 GB 显存 | `docs/TRAINING.md` §0.1.3 |
| CPU | ≤ 24 workers | `docs/TRAINING.md` §0.1.2 |
| 数据根 | `S:\mahjong-training`，总配额 200 GB、分项配额、自动回收 | `docs/TRAINING.md` §0.1.1 |
| 一处决策漏斗 | 仍然只有 `Table.decideBot(seat, Decision)` | `AGENTS.md` §6.5 |
| 反作弊 | 训练侧只实现 `ActionPolicy`（拿不到 `Round`） | `AGENTS.md` §6.5 |

## 2. 为什么重做（不是"想更 fancy"）

### 2.1 v3 的三条硬伤（实测，见 `FEATURES-V4.md` §2）

牌河只剩按牌种计数（顺序、摸切手切、立直宣言张全丢）；副露只剩种类/牌种计数（`from`/被鸣那张/巡数全丢）；
立直只剩一个布尔（宣言张与宣言巡数没有）。**这不是"精度不够"，是"信息不对称"**：
人类玩家在牌桌上能看见的时序与来源，网络一样也看不见。

### 2.2 "口径分裂"的根因：把 teacher 同时当标签源与信息上界

v3 当年拒绝加"立直宣言巡目"，理由是"补了会造出**特征比老师更聪明**的口径分裂，反而让标签对不上"。
这个担心**是对的**，但根因不在特征，而在**把 teacher 当成了唯一标签源**：

```
v3：输入信息 ≈ teacher 的视野    标签 = teacher 的动作   ⇒ 一旦输入更全，动作标签就不再是"最优"
v4：输入信息 = 人类玩家的视野    标签 = 引擎真值 + 自对弈结果 ⇒ 输入再全也不会与标签冲突
```

自对弈时**引擎是上帝视角**（它知道所有人的手牌、牌山、结局），所以"向听/进张/听牌/对手手牌/放铳/终局得分"
这些**都可以是标签**（`FEATURES-V4.md` §5.2），而它们恰好是 teacher 只能靠启发式猜的东西。

### 2.3 现状证据（为什么不能靠"再滚几代"）

| 事实 | 数值 | 出处 |
| --- | --- | --- |
| 三代自对抗续训合计增益 | **Δ = +0.01 顺位点 [−0.99, +1.02]，n=10,400** | 本会话实测（release v1.11.0 说明） |
| 步长不是瓶颈 | 满轮 6.0M 行时 `KL` 在 epoch 2 撞 0.03 墙，**仍无增益** | 同上 |
| 只有一代的 2+2 CI 排除 0 | `g05` **+2.66 [+0.14, +5.18] p=0.068**（边缘） | `docs/TRAINING.md` §4 P4 |
| 价值头变好 ≠ 变强 | val MAE 5.39 → 5.08 → 5.05，强度不动 | 同上 |

⇒ "每代只挪 2–3% 决策"这条路已到平台；**换表示**（而不是加算力/调步长）是唯一还没试过的轴。

## 3. 设计思路总览

```
                    ┌──────────── obs v3（人类可见的全部）────────────┐
                    │ tile[34,48]   evt[60,96]   ctx[64]   cand[n,128] │
                    └───────┬───────────┬──────────┬──────────┬───────┘
                            │           │          │          │
                     逐牌种编码器   事件流编码器   上下文MLP   候选编码器
                     (共享MLP)     (GRU+小Transformer)         (MLP)
                            │           │          │          │
                            └──► 双向状态-增量管理（state ⇄ delta，两轮）◄──┘
                                        │
                                  d_model = 192 的融合表示
                                        │
        ┌───────────┬───────────┬───────┴────┬───────────┬──────────┐
     策略头       价值头       顺位头      信念头      危险头      牌效头
   (候选打分)  (分布价值)   (1..4)   (对手手牌/听牌) (放铳概率)  (向听/进张)
                                        │
                            运行期只用：策略头（+ 可选 信念/危险 做风险敏感）
```

三条设计主线（对应你点名的三项技术）：

| 主线 | 解决什么 | 一句话实现 |
| --- | --- | --- |
| **关键张注意力** | 候选动作与"哪些牌/哪些事件与它有关"的**动态关联**（筋、壁、现物、宝牌、他家牌河的一段） | 候选向量当 **query**，34 个牌种 token + 最近 K 条事件 token 当 **key/value**，多头交叉注意力 |
| **增量缓存 + 循环推理** | v3 每次决策重算一切；实际状态只变了 1–2 个牌种 | `tile` 行增量更新；`evt` 只追加；隐状态 `h_t = GRU(h_{t-1}, 新事件)` ⇒ 每决策 O(新增) 而不是 O(全局) |
| **状态与增量双向管理** | 只给"当前快照"会丢历史，只给"事件流"会丢聚合（剩几张、谁立直了） | 状态塔与增量塔**互相调制**两轮：delta→state 门控写回；state→delta FiLM 偏置 |

## 4. 输入框架的类设计（可组合、可消融、三端镜像）

目标：**加一个信息块 = 写一个类 + 注册**，不要动主干；且"关掉一个块"是配置而不是改代码
（规范 §7 的消融 id 就是这么来的）。

```python
# python/mahjong_ml/v4/spec.py —— 唯一注册表（块 id / 宽度 / 顺序 / 版本）
@dataclass(frozen=True)
class Block:
    bid: str            # "tile.per_opp" 之类，消融开关用的就是这个
    width: int          # 该块在所属张量里的通道数
    requires_obs: tuple[str, ...]   # 依赖的 obs 字段（缺字段=报错，不填 0）
    derived_version: int | None      # 需要 sidecar 的哪个版本

class BlockRegistry:
    def tensor_of(self, bid) -> str: ...      # 这个块属于 tile/evt/ctx/cand 哪个张量
    def assemble(self, obs, sidecar, *, ablate=()) -> Tensors: ...
    def fingerprint(self) -> str: ...          # 块清单指纹 → 写进 net.bin（格式 2）

# 编码器 / 融合 / 头 都是可替换组件
class Encoder(Protocol):    def __call__(self, x) -> Tensor: ...
class Fusion(Protocol):     def __call__(self, state, delta, cand) -> Tensor: ...
class Head(Protocol):
    name: str; loss_weight: float
    def __call__(self, fused) -> Tensor: ...
```

- **组合**：`Model(spec, encoders, fusion, heads)`；换塔/换融合/加头都不改主干。
- **镜像**：Java 侧 `server/.../ai/v4/` 与 C++ 侧 `trainer/src/v4/` 各有一份**同 id 同宽**的实现，
  靠 `FEATURES-V4.md` §9 判据③（四个张量逐元素）钉住。
- **价值**：① 消融矩阵（G3）变成配置而非分支代码；② 三端一致有单一事实来源（规范 + 注册表）；
  ③ 未来 v5 只改注册表与编码器，不动训练编排。

## 5. 网络架构

### 5.1 塔（宽度 / 深度）

| 塔 | 输入 | 结构 | 输出 | 参数量 |
| --- | --- | --- | --- | --- |
| **Tile 塔** | `[34,48]` | 共享 MLP `48→64→64`（逐牌种，权重共享） + 2 层自注意力（4 头，d=64） | `[34,64]` tokens + 池化向量 `[192]` | ~120 k |
| **Event 塔** | `[60,96]` | MLP `96→192` + 类型/副露嵌入 + 巡目正弦位置编码 + **GRU(192)** + 2 层 Transformer（4 头） | 最近窗口 token `[60,192]` + 循环状态 `h[192]` | ~520 k |
| **Ctx 塔** | `[64]` | MLP `64→192→192` | `[192]` | ~50 k |
| **Cand 塔** | `[n,128]` | MLP `128→192→192` | `[n,192]` queries | ~90 k |
| **融合** | 三塔输出 | 见 §5.2（两轮双向 + 关键张注意力） | `[n,192]` | ~300 k |
| **头** | `[n,192]` / `[192]` | 见 §6 | 见 §6 | ~400 k |
| **合计** | | | | **≈1.5 M**（上限 3 M） |

深度取舍：**浅而宽**（每塔 ≤2 层注意力，d=192）。理由：Java 手写前向是纯标量代码，**每决策的耗时随深度
线性涨**，而 34×48 的输入没有"深"的必要 —— **信息与时序**才是瓶颈。

### 5.2 关键张注意力 + 状态/增量双向管理

```
# ① 候选 → 牌种（关键张注意力）：候选自己的那张、其筋牌、宝牌、他家牌河里的同牌种
q  = W_q · cand[i]                         # [192]
kv = TileTokens                            # [34, 64]
a  = softmax(q·W_k(kv)^T / √d + bias(bid)) # bias 可学：同牌种/同筋/宝牌位给先验偏置
u_tile = a · W_v(kv)

# ② 候选 → 事件（近因注意力）：最近 K 条事件里与这个候选相关的
u_evt = MHA(q, EventTokens, EventTokens + turn_pos)

# ③ 双向：delta → state（门控写回） 与 state → delta（FiLM 偏置）
g      = sigmoid(W_g · [u_evt, u_tile])       # 该候选"值得看历史"的程度
state' = state + g ⊙ W_s(u_evt)               # delta 写回状态（第 1 轮）
evt'   = evt ⊙ (1 + γ·tanh(W_f(state')))      # 状态调制历史（第 2 轮，FiLM）
u      = [u_tile, u_evt', u_ctx] → MLP → [192] （再与 state' 拼接）
```

- **为什么两轮而不是一次拼接**：状态与增量是**互相定义**的（"他立直了"是状态，"哪张是宣言牌"是增量；
  反过来"这张是现物"要同时看牌河计数与那段事件）。两轮是"互信息来回"的最小实现。
- **位置编码只用相对量**：事件 token 用"距当前决策几巡/几条"的正弦编码 + 相对方位偏置；
  **不做绝对座位编码**（沿用 v3 的"旋转到自己为 0"的纪律）。
- **参数量小、算子全在白名单里**（`FEATURES-V4.md` §8），Java 手写可行。

### 5.3 增量缓存与循环推理（性能与正确性）

**两级缓存**（Java/C++/Python 三端同语义）：

| 级 | 缓存什么 | 何时失效 |
| --- | --- | --- |
| L1 张量级 | `tile[34,48]` 的行（只改变化的牌种）+ `ctx` 的派生部分 | 舍牌 → 1 行 + 四家计数器；鸣牌 → 1–2 行 + `meld_count`；**杠/翻宝牌 → 相关行 + `dora_indicator` 行**；立直 → 立直家全部行的 `river_before/after` 分区 |
| L2 表示级 | Tile 塔 token `[34,64]`（逐行可缓存）、Event 塔隐状态 `h`（只吃新事件）、Ctx 向量 | 事件追加 → 只算新 token 并推进 `h`；**跨局 reset**（`h` 不跨小局，除非显式开启"跨局 carry"做实验） |

- **循环推理**：`h_t = GRUCell(h_{t-1}, 新事件 tokens)` ⇒ 每决策 O(新增事件数)，与"这一局已经打了多久"无关。
- ⚠ **可复现性冲突**：状态化会破坏"同种子同轨迹"（`AGENTS.md` §6.5 的硬要求）。
  三条纪律：① 隐状态**每小局开头清零**且**每局一份策略实例**（沿用 `PolicyFactory`）；
  ② 任何缓存都必须能从**当前决策的 obs + h** 完整重建（判据④）；
  ③ 提供 `--no-cache`/`--stateless` 开关，自检与对拍**永远用无缓存路径**做基准。
- ⚠ **最危险的失败模式是"缓存陈旧但结果看起来正常"**：所以唯一判据是
  `增量 == 全量重算`（逐元素 ≤1e-5，覆盖舍牌/鸣牌/杠/翻宝/立牌/流局/连庄七类事件）。

#### 落地实况：Java 侧 L2（表示级）已上（2026-09-28）

`mahjong/ai/V4Cache.java` + `V4Policy.forwardCached()`（**默认开**，`--no-v4-cache` 关）。
**L1（张量级）没做** —— 它要动 `tileMatrix` 的派生量（引擎侧 `HandEval`/`Danger`），
这一轮先做收益最大的事件塔（实测事件塔占前向的 ~2/3）。

| 项 | 实测（`tools.V4Probe --cache`，721 条真实决策 / 8 小局 / v4-p3-001） |
| --- | --- |
| 特征 | 3.55 ms/决策 |
| 前向（无缓存） | 34.69 ms/决策 |
| **合计（无缓存 → 有缓存）** | **38.12 → 22.50 ms/决策（1.70×）**；前向本身 34.7 → ~18.9（1.83×） |
| 归因（缓存深度 1/2/3） | 只增量隐状态 25.76 → 再复用事件编码行 24.35 → 再复用注意力 `in_proj` **22.50** |
| 命中 | 677 命中 / 44 建槽 / **0 陈旧**；编码 2,287 行 vs 复用 19,516 行（89.5%） |
| 正确性 | 三档深度**七个头逐位相同**（`floatToIntBits`，721 决策 × 7 头无一处不同） |

三条实现口径（其中两条是踩出来的，见 `NOTES.md` §6.5 第十一轮）：
① **逐行函数只有一份**（`V4Features.eventRow`）：token 行只依赖 `(事件, 座位)`，
所以幸存行可以**按引用平移**、只有新增的 delta 行要算 —— 另写一份必然漂移；
② **校验必须逐行逐元素**（`V4Cache.overlapOk`）：与本次 obs 的窗口在重叠区间逐位比对，
任何一格不等就丢掉整个槽、退回全量 —— "应该是它"这种假设正是陈旧缓存能溜过去的地方；
③ ⚠ **逐行函数**（`V4Features.eventRow` / `blocks.event_matrix` 的逐行版）收的是"**待填的行缓冲**"，
而调用方**会复用**同一个缓冲（建槽时逐事件重放就是复用一支 `tok`）⇒ **它必须自带清零**。
不清零 = 第 i 行是"前 i 条事件按位或"的**静默累积**；`s.h` 原先没人消费，所以这个 bug 藏了很久
（2026-10-02 W1 把 `h_evt` 接进融合的当天，"增量 == 全量"与"陈旧退回"三条判据一起红）。
④ **`h` 的口径三端统一（W1，第六十轮，已落地）**：`h_evt` = "**本小局从 0 起、逐事件推进全部真实事件**"
的 carry —— 生产端 = 缓存槽 `s.h`（增量）**或**整手重放（无缓存路径），离线端 = 数据集 `h0`
（= 重放 `events[0, n-K)`，用**学生网**算）+ 窗口那 60 步推进。三条路线**逐位同源**
（`SelfTest.v4CacheTests` 直接比 `hCache == hFull`、且"前缀 carry + 窗口 == 整手重放"，
无容差）；golden 夹具 format 2 把每用例的 `h0`/`h_evt` 写出来，让三端"同一 `h0` ⇒ 同一输出"可判据。

⚠ **别再拿"扰动 `h0` 就该让输出变"当判据**：随机初始化的 GRU 是收缩的（更新门 z≈0.5 ⇒ `0.5^60≈1e-18`），
实测满窗上 `h0` 的影响只有 **3e-8**（< 夹具容差 1e-4）⇒ 三端**都忽略 `h0`** 也照样"通过"。
夹具因此把 `event.cell` 的**更新门偏置抬到 +3**（z≈0.95，纯夹具权重选择）把影响放大到 1.6e-1，
并直接比 `h_evt` 向量（比只看七个头灵敏得多）。详见 `docs/VALVES-AND-FIXTURES.md` §3 W1。

**判据（两条一起，缺一条就是假绿）**：
- `SelfTest.v4CacheTests`：真实 obs 序列（确定性自对弈现采）上 三档深度逐位相等 +
  **真的命中**（命中数 > 0、复用行数 > 0）+ 窗口 token 行 == `eventMatrix`（逐位）+
  **缓存 carry == 全量整手重放（逐位）** + **前缀 carry + 窗口 == 整手重放（逐位）** +
  改坏事件流（少一条 / 改内容）必须判陈旧并退回全量 + 关缓存后命中数为 0；
- `node tools/v4-cache-check.mjs <net.bin> [场] [小局] [种子]`：**同种子开/关缓存 ⇒ 整场轨迹逐字节相同**
  （最外层证据）。⚠ W1 之后这条**第一次非平凡**（`h` 被融合消费了）。⚠ 红证实测：把缓存故意做旧
  （落后一条事件）⇒ 立刻 FAIL（偏移 1621 处第一个不同）。

⚠ **剩下的 18.9 ms 全是不可复用的稠密计算**（**这里不设时间指标，只记实测** —— 早年那对单决策耗时
预算不现实，已从 `FEATURES-V4.md` §8 删除）：事件 Transformer 的注意力 + FFN
（注意力跨行混合、每决策必算）、融合里 34 张牌行与 60 个事件 token 的 k/v 投影。
下一步按性价比（**只为变快，不为达标**）：① 逐候选/逐头并行 ② int8 量化 ③ 缩 `dModel`（要重训）
④ 扁平 `float[]` + 行偏移 + scratch 复用 —— 它是 ①② 的地基，**本身不是大头**
（GC 实测只占墙钟 **0.03%**，见 `NOTES.md` §6.5 第十一轮）。C++ 侧镜像同一套缓存
（自对弈采集在那边，收益更大）。

暂不做搜索。如果 P4 之后还需要推力，优先试：**把价值头当搜索的叶子评估**（只在小规模、离线标签生成上），

## 6. 多头体系

| 头 | 形状 | 监督来源（**全部来自引擎/自对弈，不来自 teacher**） | 损失 | 权重（退火） | 推理期 |
| --- | --- | --- | --- | --- | --- |
| **策略头** | `[n]` logits（掩码 softmax） | PPO 的优势（自对弈回报） | PPO-Clip（λ=1、优势只在学生行归一化） | 1.0 | ✅ **主力** |
| **分布价值头** | `[51]` 分箱（HL-Gauss，范围 ±30k 点） | 本局 `final_scores − 起点` | 交叉熵（分布） | 0.5 → 0.25 | ✅（critic / 风险敏感决策） |
| **顺位头** | `[4]` logits | 本场终局 `placement` | 交叉熵 | 0.3 | 可选（终局取舍） |
| **信念头：对手手牌** | `[3,34]` 概率 | 自对弈真值 `opp_hand[3][34]` | 交叉熵（逐家、逐牌种） | 0.2 → 0.05 | ❌（**训练信号/诊断**） |
| **信念头：对手听牌** | `[3]` | 真值 `opp_tenpai[3]` | BCE | 0.2 | ✅（押し引き输入） |
| **危险头（放铳概率）** | `[n,4]`（候选 × 打到谁手上） | 自对弈结果 `opp_dealin[3]` + 他家听牌真值 | BCE | 0.3 | ✅（与信念头一起驱动押し引き） |
| **牌效头** | `[n,3]`：打后向听 / 进张枚数 / 听牌形 | `HandEval.afterDiscard`（引擎，**免费**） | 回归/分类 | 0.3 → 0.1 | ❌ |
| **听牌头（自家）** | `[1]` | 引擎真值 | BCE | 0.1 | ❌ |
| **teacher 模仿头** | `[n]` logits | **仅在 P2 冷启动期**用 teacher 动作 | 交叉熵 | 0.3 → **0**（20k 步退火到 0） | ❌ 退火后删除 |

设计判据：

1. **只有策略头与价值头是"上线必需"**；其余是训练信号或可选诊断 —— 保证推理路径短（判据：删掉非必需头后
   `net.bin` 仍能加载并打牌）。
2. **teacher 只出现在一个可退火到 0 的头**里。这是"teacher 只做初始收敛"的实现方式：
   P2 之后它自动消失，不存在"偷偷以老师为上界"的通道。
3. **belief/danger 头是"用公开信息预测隐藏信息"**，训练用真值（自对弈）、推理只用公开输入 ——
   与作弊面的分界线写在 `FEATURES-V4.md` §1.2。
4. **价值头改成分布**（不是标量 MSE）：v3 的价值头 MAE 一路变好而强度不动，一部分原因是标量均值
   丢掉了尾部风险；顺位点/押し引き恰恰关心尾部。指标见 §8.4。

## 7. 训练工作流（尽量复用既有编排）

### 7.1 数据管线（三套文件，物理分离）

```
raw/<label>/g*.jsonl        obs v3 + 动作（协议）        ← 采集（C++ 生产者，候选 3× 吞吐）
raw/<label>/g*.feat.bin     输入派生 sidecar v3（§5.1）   ← --features（引擎算）
raw/<label>/g*.aux.npz      标签（§5.2，训练专用）        ← --selfplay --aux（**两个生产者都支持**；
                                                         C++ 与 Java 逐字节相同，见 §7.2 判据①）
compact/<label>/            紧凑数组（tile/evt/ctx/cand + 标签列）
```

- `dataset build` 增 `--aux`（把 `aux.npz` 并成标签列）；**推理路径只读 `feat.bin`**（判据⑥）。
  ✅ 已落地（2026-09-27）：`python -m mahjong_ml.dataset build <dir> <out> --aux` → 6 个 `aux_*` 列；
  缺 `g*.aux.npz` **报错**（不填 0）；`python -m mahjong_ml.auxlabels check <dir>` 逐文件核对版本/行数/obs 版本。
- 复用：`budget.py`（时间预算/缓存档闸门）、`paths.py`（配额 + 自动回收）、`producer.py`（java/cpp 切换）。
- ⚠ v4 的 sidecar 变大（~340 B/决策 → 一轮 6M 决策 ≈ 2 GB），紧凑集也更大：
  缓存档上限要**按 v4 的字节/场重标**（`budget.fit_cost/fit_disk` 本来就是从台账实测回填的，不用改代码）。

### 7.2 编排：`python -m mahjong_ml.v4 loop`（**默认 C++ 生产者，训练端不依赖 Java**）

v4 的轮次**不再手敲命令**：一条命令跑完一轮的八个相（计划 → 采集 → 派生特征 → 校验 → 紧凑集 →
训练 → 导出 → 评测+判据+台账），每轮从上一条产出的 `net.bin` 起步。

| 相 | 谁跑 | 命令要点 |
| --- | --- | --- |
| 计划 | Python | `--target-minutes > 0` ⇒ `budget.plan_round`（台账实测反推 + 资源闸门，点名谁限制的）；否则 `--games` |
| 采集 | **C++**（`trainer selfplay`） | `--rotate --aux`；策略串 = `net:<上一代 net.bin>@0#T` ×2 学生 + `teacher` ×2 |
| 派生特征 | **C++**（`trainer features`） | sidecar `g*.feat.bin`（与 Java 逐字节） |
| 校验 | node | `tools/selfplay-check.mjs`（含 `reward_to_go` 的独立重算） |
| 紧凑集 | Python | `v4.dataset --aux --student "<与采集逐字相同的串>"`（`is_student` 靠字符串相等判定） |
| **值头先行**（可选） | Python | `--critic-steps N > 0` 时先跑 `v4.pretrain --only-heads value --freeze-trunk --objective bc --value-target <同>`：主干与**策略头都不动** ⇒ KL 恒 0、不占 KL 预算；产物当 PPO 的 `--init` |
| 训练 | Python | `v4.pretrain --objective ppo --behaviour <采集那份> --behaviour-temp T`（**口径闸门** `KL(π_old‖π_new)≈0`）+ 数值口径（grad-clip / KL 早停 / 双口径 KL） |
| 导出 | Python | `v4.export weights` → 格式 2 `net.bin`（下一轮的 `--init`/`--behaviour` 就是它） |
| **判据** | Python | `v4 value-audit --strict --ev-ref legit`（**EV ≥ 0.7 × 合法天花板 + 覆盖率 ≤3pp**）→ `league/<label>-audit.json`；`--strict-gate` 时不过就**停整条回路** |
| 评测+判据 | **C++**（`trainer selfplay`）+ Python | 2+2 同牌山（`net,net,teacher,teacher`）→ `eval.paired_test`（按 seed 配对 + bootstrap + `required_n`）→ 台账 `league/<label>-v4.json` |

⚠ **值头那条判据以前断在回路之外**（回路只看 2+2 顺位点 ⇒ 目标里"覆盖率 ≤3pp"没人判）。
现在它是 `audit` 相，每轮出口跑一次并把 `ev / ev_ref / ev_need / cov0.5·0.8·0.95 / ok`
写进台账；**读不到审计文件按"未过"处理**（不默认放行），`--strict-gate` 才真的拦住回路
（缺省只记账 —— 先看几轮分布再决定要不要拦）。

```powershell
python -m mahjong_ml.v4 loop --label v4-g01 --init tools\build\v4-bc-004\net.bin `
       --generations 3 --games 400 --workers 24 --objective ppo --value-target final `
       --student-temp 0.5 --eval-games 2000 --no-java
# **多轮 × 每轮短**（§14.10 的实测口径：一轮 ~100 步 + 每轮重新采一批）：
python -m mahjong_ml.v4 loop --label v4-mr01 --init <net.bin> --generations 8 --games 400 `
       --objective ppo --value-target delta --advantage hand --rank-weight 0.2 `

python -m mahjong_ml.v4 loop --label v4-g01 --init <net.bin> --generations 3 --dry-run   # 只打印命令
```

⚠ **训练口径的开关必须走回路**（第二十一轮补的）：`--value-target {final,rtg,delta}`、
`--advantage {auto,gae-hand,hand}`、`--rank-weight`、`--baseline-fit`、`--grad-clip`、
`--kl-early-stop`、`--kl-min-steps`、`--max-steps`（=「每轮短」那条杠杆）。
以前这些**只活在 shell 历史里** ⇒ 一轮的实际训练口径不可复现；现在它们显式进 `train` 命令
（`--dry-run` 与台账都看得见），自检钉住"命令里真的带上了"。

#### 强度怎么判：`python -m mahjong_ml.v4 arena`（**别拿 200 场的 Δ 当结论**）

逐场顺位点 `sd ≈ 53` ⇒ 检出 **Δ=2 顺位点**要 **~5,000 场**。回路的每轮评测（200 场）**没有判决力**，
它的 Δ 只能当"记录"，不能当"变强/变弱"。要看强度用竞技场：

```powershell
python -m mahjong_ml.v4 arena --policies teacher,net:tools/build/v4-ppo-001/net.bin `
    --games 3000 --block 500 --seed 20260930 --out <可写目录>
```

- 逐对 `--policy A,A,B,B --rotate` ⇒ **同牌山配对**、跨对可比；`--rotate` 让每个策略坐遍四家。
- **序贯判决**：按 `--block` 分块，CI 排除 0 提前收工（至少一块）；跑满仍跨 0 ⇒ "这个样本量下分不出"，
  并报"还差多少场"。
- **结论只看 CI**；分块要**合并逐场值重算**（不是合并 CI）。
- 先跑 `--self-check` 三个自证（已知更强的一对必须判出、同策略必判分不出、换标签校准假阳率 ≈α）。

#### 一轮的**预算配方**（第二十五轮的战役实测把两个坑钉出来了）

| 症状（实测） | 根因 | 配方 |
| --- | --- | --- |
| `--max-steps 100` 配 `--kl-min-steps 100` ⇒ **KL 早停永不触发**（三代 `stop_reason` 全 `None`，KL 从 0.079 掉到 0.0085 没人管） | 判据只在 `step ≥ min_steps` 时看，而一轮最多 100 步 | `effective_kl_min_steps()` 把 `min_steps` 钳到**轮长的 1/5**（日志会喊"原值够不着"） |
| 学生行 top1 **逐轮掉**（0.890 → 0.798 → 0.785，n≈17k） | 每轮只 100 步**联合微调**（`--stage-a 0 --stage-b 0`）、KL 又没管住、行为策略每轮换 | 别把 `--stage-a/--stage-b` 设 0：**分阶段**（a = 策略+牌效、b = 冻主干只训头、c = 联合） |
| 值头 EV ≈ 0（−0.075 / −0.004 / +0.016），闸门三代全 FAIL | 100 步里值头学不动 `delta`（它从"整场口径"的旧头起步） | 给够步数（几百步 / `--epochs ≥ 2`），或先 `--stage-b` 让头在冻住的表示上收敛 |

**推荐的长轮配方**（与 `v4-sp-004` 上实测过的那轮同源；`--stage-a/--stage-b` 是**比例**，不是步数）：

```powershell
python -m mahjong_ml.v4 loop --label v4-mr02 --init <net.bin> --generations 1 --games 120 `
  --objective ppo --value-target delta --advantage hand --rank-weight 0.2 `
  --max-steps 600 --epochs 2 --stage-a 0.2 --stage-b 0.3 --kl-min-steps 60 `
  --eval-games 150 --no-java
```

⚠ **对照实验的做法**：两次跑**同一个 `--seed`** ⇒ 采集用同一副牌山、评测也用同一副牌山
（`seed + 5000 + 代`），于是"换配方"变成**同数据同牌山的 A/B**（牌山相同 ⇒ 两次的 Δ 直接可比）。
`v4-mr01`（坏配方）与 `v4-mr02`（这份配方）就是这么配的对。

**判据（"训练端脱离 Java"）**：
① `node tools/trainer-aux-parity.mjs 5 4 teacher 20260101 --rotate --selfcheck` PASS —— 标签侧
   `g*.aux.npz` **连 zip 容器一起逐字节相同**（负向对照：翻一个字节必须报出是哪个成员）；
② `loop … --no-java --dry-run` 打出的命令里**一个 `java` 都没有**（自检 `v4 回路：默认命令里没有 JVM` 钉住）；
③ 冒烟：4 场 × 2 小局、C++ 采集 + `--aux` + PPO 一轮走通（`ckpt/v4-smoke-g01`），
   紧凑集里 `aux_opp_hand / aux_opp_tenpai / aux_win_flag / aux_opp_dealin` 都非空。
⚠ `MAHJONG_NO_JAVA=1` 是**硬守卫**：选到 java 生产者**当场报错**（不是"能跑但慢十几倍"）。
⚠ 仍然只有 Java 能做的两件事（与 v4 回路无关）：`--teacher-label`（DAgger）与 `net:` 的 `@α` 先验。

### 7.3 对手池与联赛

- **对手**：历史快照（滑动窗口）+ teacher + 脚本基线（`first`/`random`/`pass`）+ **v3 的最强代**（作为"旧世代基准"）。
- **联赛**：沿用 Plackett-Luce Elo + "谁克我就多跟它打"的加权采样（`league.py`）；
  防循环相克：对手池里永远保留 teacher 与脚本基线（它们是"锚"，不会随种群漂移）。
- ⚠ **采集那桌的顺位点/收支不是判据**（只有学生在探索采样）—— 这条口径沿用 `NOTES.md` §6.5。

### 7.4 自对弈期的封闭性（硬约束）

**一句话**：自对弈时引擎是上帝视角，但**上帝视角只许写标签，不许进输入，也不许进奖励**。

| 判据 | 具体做法 | 防的是什么 |
| --- | --- | --- |
| **输入只来自 obs** | 前向只吃 obs v3 的四个张量；训练侧只实现 `ActionPolicy`（拿不到 `Round`） | 上帝视角一进输入，"封闭"就只剩口号 |
| **标签与输入物理分离** | `feat.bin`（输入派生）/ `aux.npz`（隐藏真值标签）两套文件、两套列名 | 防"顺手带进去"（规范 §1.4） |
| **红证①：撤标签，输出不变** | 删掉 `aux.npz` 后重新前向，**logits 逐位不变** | 证明标签真的没进输入（比读代码强） |
| **红证②：obs 不含隐藏量** | 改 `Round` 隐藏量（别家手牌/牌山/里宝）后同一座位 `Observation.toJson()` **逐字节相同**；塞一个隐藏字段进 obs 必须让测试**红** | "以为没进、其实进了"（v2→v3 的 `kuitan` 恒 0 是同类静默） |
| **红证③：没有框外中间量奖励** | 奖励/优势只由**对局结果**（`hand_delta` / `placement` / 放铳事件本身）构成；⛔ 不用"对手是否听牌""牌山下一张"这类**过程隐藏量** | 用框外中间量做奖励 = 让模型学推理时拿不到的信号 |
| **辅助头不回喂** | 信念/危险/牌效头输出**只进损失**；推理时可整块删除 | 防"自己预测自己吃"的循环泄漏 |
| **对手族分层** | 信念/危险头必须在**训练池之外的族**（teacher / 脚本基线 / 未参训历史代）上单独报指标 | 自对弈的隐藏结构来自"自己的旧版本"⇒ 同族内评测会高估 |

**"框外过拟合"的三种形态**（三条都要防，缺一条就会静默发生）：

1. **输入泄漏** —— 隐藏量以任何形式进了输入（红证①②）；
2. **奖励泄漏** —— 用过程隐藏量塑造奖励/优势（红证③）；
3. **分布捷径** —— 训练数据的隐藏结构有偏（对手永远是自己上一代、座位/亲家/局不均衡）⇒
   模型学出评测里不成立的伪相关（§7.5 + §8.2 的族间报告）。

### 7.5 场外分配必须平均（硬约束）

**定义**：**场外因素** = 不进 obs、但会改变样本分布的一切。它们**必须分层均衡**，
不能"随机了就算公平" —— 随机只在期望上平衡，小样本下会留下系统偏差，而**偏差会被模型学成伪特征**
（例如"我坐庄时才遇到这个对手"⇒ 把对手与庄家绑在一起）。

| 场外因素 | 均衡要求 | 判据 |
| --- | --- | --- |
| 座位（4 席） | 每策略每座位**各 1/4 场次**（`--rotate`，既有） | 逐策略逐座位计数，偏差 ≤ 1% |
| 学生占席形态（2 席时） | "相邻"与"对家"两种形态**各半** | 两形态场次相等 |
| 亲家（庄家） | 每策略坐庄次数相等（连庄也按场平均） | 逐策略庄家次数偏差 ≤ 1% |
| 场风·局·本场 | 所有样本来自同一套半庄结构（東1→南4），不挑局 | 逐局场次分布偏差 ≤ 1% |
| 对手身份 | 显式 `--opponents` 时各对手总场次相等；联赛采样时**每对手总配额受控** | 对手场次 CV ≤ 5% |
| 对手 × 座位 | 每个对手在 4 个座位上的分布同样平均 | 交叉表偏差 ≤ 1% |
| 牌山种子 | 配对实验两臂**同一副牌山**；不同臂/不同消融**同 seed 基** | seed 集合逐场一致 |
| 起始点数 / 供託 | 固定 25000 / 0（做变起点实验时必须分层平均） | 起始值直方图 |
| 训练/验证切分 | **按整场**切分（既有）**且按对手族分层**（各族占比一致） | 分层比例差 ≤ 1% |
| 小局结局类型 | 不控（规则决定），但**必须报告** train/val 分布（流局/自摸/荣和/被飞） | 分布表 + 差异告警 |

**用法（判据，不是报告）**：

- 每轮采集完输出**均衡报告** `league/<label>/balance.json`：逐因素计数表 + 最大偏差 + 卡方 p；
- **超阈即失效**：座位/亲家/局这类离散因素偏差 > 1%、对手配额 CV > 5% ⇒ 该轮**不得用于判据**
  （可以当训练数据，但要记录在案），先修采样再重跑；
- **消融矩阵（§8.3）与 2+2 配对（§8.1）必须在均衡场次上做**，否则差异可能来自分配不均；
- `selfcheck.py` 钉住实现：喂一批**故意不均衡**的合成计数，必须报警（负向对照）。

⚠ 这条不是形式主义：`NOTES.md` §6.5 已实测过同类坑 —— `g05` 的 2+2 单跑"相邻"是 +1.10、
单跑"对家"是 +4.23，合计才 +2.66。**只看一种座位关系就会把未采样偏差读成强度**；
"场外分配平均"就是把那次教训推广到**所有**场外因素。

## 8. 评价体系（重新设计）

### 8.1 三层判据

| 层 | 协议 | 判什么 | 阈值/样本量 |
| --- | --- | --- | --- |
| **L-主** | **2+2 同牌山配对**（`A,A,B,B` 与 `A,B,A,B` 两种座位配置，不同 seed 基，合并一个总 Δ），指标 = **顺位点** | **G1（强于 teacher）** | 预注册：**Δ ≥ +2 顺位点且 CI 排除 0**；`sd(Δ)≈53` ⇒ **≈5,200 场/臂**（80% 功效，`eval.required_n`） |
| **L-阶** | Elo 阶梯（Plackett-Luce，一次联合拟合 10+ 策略，含 `first`/`random`） | 种群趋势、是否退化（对脚本基线不掉） | 每代 1200 场；θ−teacher CI 排除 0；**CI 含 0 一律写"证不出差别"** |
| **L-证** | **消融矩阵**（逐块关掉，同种子配对） | G3：每块信息值多少 | 每块 2000 场（同一批牌山）⇒ Δ 的分辨率 ~±2.3 顺位点；**只对"关掉后变差且 CI 排除 0"的块下结论** |

⚠ **禁止**：混合桌自对弈汇总当判据（学生探索 vs 对手 argmax，不可比）；单座位配置的配对当判据（`NOTES.md` §6.5
的采样偏差实测：`g05` 相邻 +1.10 / 对家 +4.23）。

### 8.2 校准（头级别，不是"直觉"）

| 头 | 指标 | 达标线（暂定，P1 结束后标定） |
| --- | --- | --- |
| 分布价值头 | CRPS、分位覆盖率（50/80/95%）、MAE、逐点/小局 ρ | CRPS 优于标量基线；覆盖率与标称差 ≤3pp |
| 信念头（对手听牌） | Brier、ECE、AUC | ECE ≤ 0.05；AUC ≥ 0.75 |
| 危险头 | Brier、ECE、按"是否立直/几副露"分层的可靠性曲线 | ECE ≤ 0.05 |
| 牌效头 | 向听 MAE、进张枚数 ρ | MAE ≤ 0.15；ρ ≥ 0.90 |
| 策略 | top-1 与 teacher 的一致率（**只作诊断，不作判据**） | 不设阈值（避免"越像老师越好"的诱导） |

**实测（2026-09-28，`python -m mahjong_ml.v4 value-audit`；判据口径 = 该权重训练时的值头目标；
括号里是同粒度基线；数据 = 各自的 val 切分）**：

| 权重（数据） | 值头目标 | CE / 边缘基线 | **EV** | MAE（常数） | CRPS（气候学） | 覆盖 50/80/95% | ρ（逐点/小局） |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `v4-bc-004`（bc-003） | 整场 | 3.53 / 3.62 | **0.44** | 8.81（12.34） | 6.27（8.51） | 47/83/95% ✅ | 0.665 / 0.566 |
| `v4-p3-001`（sp-002） | 整场 | 3.46 / 3.62 | **0.57** | 10.10（16.88） | 7.42（11.78） | 44/73/84% ❌ | 0.764 / 0.443 |
| `v4-ppo-001`（sp-003） | 整场 | 3.51 / 3.75 | 0.46 | 9.92（14.12） | 7.32（10.04） | 46/73/87% ❌ | 0.682 / 0.575 |
| `v4-ppo-002`（sp-004） | **rtg** | 3.65 / 3.67 | **0.006** ⛔ | — | 11.47（11.08）⛔ | 32/61/82% ❌ | 0.157 / −0.04 |

三条读数：① **整场口径的值头"弱但真"**（EV 0.44–0.57、ρ 0.66–0.76、CRPS 好 25–38%）；
② **分布形状一直不对** —— 只有 `v4-bc-004` 在**它自己的** val 上三条覆盖率都在 3pp 内，
自对弈口径下 95% 区间只覆盖 82–87% ⇒ §8.2 的"≤3pp"**目前不通过**；
③ ⛔ **`rtg` 口径的值头是塌的**（CE 只剩 0.019 nats、预测的逐点标准差 1.66 vs 目标 15.15、EV 0.006），
而且**目标侧本身就不合适**：`Var(value−V)=238 > Var(rtg)=229.5`
⇒ "整场值头 − 已滚入"这种构造**数学上就赢不过 0 EV**。
⇒ **PPO 在修好 critic 之前不要再放量**（`NOTES.md` §6.5 第十二轮）。

**第十三轮：修 critic 的实测（2026-09-28，`--freeze-trunk --only-heads value`）**：

| 实验 | 目标 | CE / 边缘基线 | **EV** | 备注 |
| --- | --- | --- | --- | --- |
| 冻主干 + 只训值头，6 epoch | 整场 | 3.504 / 3.661 | **0.4115** ✅ | 新 ckpt `v4-critic-final-001`（覆盖率仍不达标 46/72/85%） |
| 冻主干 + 只训值头，6 epoch | `rtg` | 3.710 / 3.667 | **0.002** ⛔ | 连边缘基线都够不到 |
| **不冻主干** + 只训值头，3 epoch | `rtg` | 3.656 / 3.667 | **0.010** ⛔ | 表示动得了也学不到，教师一致率 0.882 → **0.546**（把策略头带坏） |

**参照（`value-audit --ceiling`：引擎真值线性读出，train 拟合 / val 计量）**：
**本小局收支 `delta` EV 0.632** · `rtg` 0.090 · 整场 `value` 0.059。
⚠ **这个 0.632 在第十九轮被推翻**：它把 `win_flag`（本小局结局本身）与 `opp_*`（别家隐藏真值）
一锅端进了所谓"state 参照" —— 那是**作弊上界**。合法列的线性天花板只有 **0.035–0.069**（§14.8）。
⇒ 但同批数字里 **"`delta` ≫ `rtg`（0.632 vs 0.090）"这个对比仍然成立**（两栏用的是同一批作弊列），
所以"可学的粒度是这一小局、不是剩下的整场"这条结论不变。

⇒ **结论：`rtg`（多手后缀和）这个 critic 目标停掉** —— PPO 的 λ=1 GAE 目标正是它，
critic 学不到就等于"原始回报减常数"，没有 baseline。改用**小局级**目标（仓库已有的 RWR/AWR
就是"本小局收支"的回报加权）；真要 critic 就做两段分解（`本小局收支 + 其后的后缀`）
并先过**合法天花板的比例闸门**（⚠ 原文写"EV ≥ 0.4"，第十九轮证明**任何合法口径都到不了 0.4**，
闸门已改成"EV ≥ 0.8 × 合法天花板 + 覆盖率 ≤3pp"，见 §14.8）。
细节见 `NOTES.md` §6.5 第十三轮 / 第十九轮。

### 8.3 消融矩阵（新增，回答"这条特征值不值"）

```
            Δ(顺位点) vs 全量    95% CI       结论
关 evt.order          −3.2      [−5.0,−1.4]   时序信息**必须**
关 til.per_opp        −4.6      [−6.5,−2.7]   逐家聚合是主力
关 ctx.riichi_turn    −0.4      [−2.2,+1.4]   证不出差别（**可以砍**）
关 derived.danger     −1.1      [−3.0,+0.8]   与信念头功能重叠（待定）
```

- 每块都用**同一批牌山**（同一 seed 基）⇒ 逐场配对，避免"换一批牌局就变号"。
- 这张表就是规范 §7 消融开关的**唯一用途**，也是"信息平价"从口号变成证据的地方。

### 8.4 决策相关指标（比 MAE 更接近目标）

- **押し引き开关**：在"他家立直且我方无听"的局面子集里，量"平均放铳率"与"顺位点"的联合变化
  （期望：放铳率下降而顺位点不降）。
- **终局顺位**：在最后一局/接近听牌分界的子集里量"平均顺位"。
- **价值头用于决策**：把价值当风险敏感效用（`U = E[score_delta] − λ·Var` 或顺位期望），
  在固定的策略上做"决策改变率 vs 顺位点变化"的扫描 —— 只有当它**正向**时才允许进上线路径。

### 第二轮：分阶段训练 + 掩码事件重建（2026-09-27，辅助头收敛）

第一轮暴露的问题：**辅助头不收敛**（`value` 的 CE 不降反升 3.87 → 6.63）—— 典型的**多任务权重冲突**
（策略头的梯度把共享主干拉向另一边）。这一轮按计划三件事一起做：

1. **数据放大**：150 → **400 场**（262,095 训练 / 14,965 验证，val = 20 场）；采集 384 s（12w）+
   派生 116 s + **并行数据集构建 75 s**（8 进程，与串行**逐字节相同**）。
2. **分阶段训练**（`--stage-a 0.25 --stage-b 0.35`，头 lr = 主干 ×3）：
   **a** 只训 `policy`+`effect`（主干先学会"打哪张"）→ **b 冻结主干**只训各头（新头在固定表示上收敛）
   → **c** 联合微调（注册权重全开 + 余弦降 lr）。
3. **P1 的掩码事件重建**（pretext，`--mask-frac 0.15 --ssl-weight 0.2`）：把真实事件 token 置 0，
   用事件塔的输出重建**事件类型**（8 类）；pretext 头**只训练**，不进 `inference_heads()`。

**三条结论**（判据都在表里）：
1. **分阶段奏效**：`b` 段（冻主干只训头）一步就把三个辅助头从"没收敛"拉到"收敛"
   （`bt 0.591 → 0.373`、`danger 0.889 → 0.301`、`value 4.39 → 3.73`），`c` 段再把 `bt` 压到 **0.140**。
   ⇒ "先让主干学会打牌，再让头在固定表示上收敛，最后联合微调"这条路线**可复用**（P2 的退火也照它）。
2. **策略头仍在涨**（0.608 → 0.619，`policy` CE 1.19 → 1.10），且**数据翻 2.7 倍只换来 +0.011** ——
   与 v3 的经验一致：**BC 一致率的天花板不是算力**（teacher 自己的取舍里有大量近似平局的动作，
   学生不可能逐条复现）。要再往上必须换目标（自对弈回报，P3）。
3. ⚠ **pretext 太容易**：掩码事件类型一致率 **0.968**（chance 0.125）—— 事件类型几乎由上下文决定，
   对表示学习**几乎没贡献**。P1 若还要自监督，得换更难的掩码目标（连 `tile_kind` 一起重建、
   或掩码整段时间窗），否则这条损失只是白占权重。
4. ⚠ **别跨阶段比 train loss**：`b` 段的 train loss 反而涨（2.5 → 3.65）—— 那是辅助头的随机初始化
   被算进总损失了；**只有 val 的逐头曲线可以跨阶段比**（表里就是这个口径）。

**下一步（P1 正式化的收尾）**：① 换更难的 pretext（或按结论 3 直接砍掉，把权重让给 policy）；
② `harness.balance` 的 §7.5 均衡审计（座位/对手族分层）**还没跑过** —— 判据⑩要求它；
③ 放量（P3 的 6M 决策规模）时数据集构建要再压（现在 8 进程 ≈3,500 决策/s）；
④ v4 前向的 Java/C++ 落地（P5）之前，checkpoint 只能离线评估。

### 第三轮：把 `cand` 的派生段接上 + 阶段 c 的学习率（2026-09-27，教师一致率 0.619 → 0.903）

**这一轮不是"调参"，是两个真 bug 的收口**（都是"训练照跑、指标照出"的那一类）：

1. **`cand[88:128]` 整整 40 列一直是 0**（实测 `compact/v4-bc-002`：逐列 `maxabs = 0`）。
   根因两条一起：① `v4/traces.sidecar_dict` 只带了逐家四段位图/危险度，**没带逐候选 C 段**，
   于是 `blocks.cand_matrix` 走"per_cand is None"那条路**静默填 0**并只记了个 `degraded`；
   ② `v4/dataset._write_file` **从不检查 `Tensors.degraded`**。
   ⇒ 修法（两处都要）：`sidecar_dict` 带上 `cand`（按 `offsets` 切片 + 与 `nLegal` 对账），
   `_write_file` 遇到非空 `degraded` **直接报错**（"降级 = 静默换任务"）。
   **顺带**：`cand[96:99]`（v4 新 3 维）与预留 29 列**仍是 0**（离线侧与实时侧一致，不构成漂移；
   填它们要 sidecar 段长 +1 版 —— 欠账记在 `FEATURES-V4.md` §4.3）。
2. **阶段 c（联合微调）会把策略头练塌**：`--stage-c-lr-mult 1.0`（= 主干 1e-3）时，
   `c` 段第一步就 `top1 0.837 → 0.165`（= 首合法基线）、策略 CE 恒定 1.897 ⇒
   融合输出 ReLU 全死、logits 变成常数（argmax 恒取第 0 条）。加 `--stage-c-lr-mult`（乘在 a/c 基准
   lr 上）后 `0.1` 就正常。

### 第四轮：P3 开局 —— 自对弈 + RWR（2026-09-27，**结果：证不出改进**）

**这一轮的目标**：把"教师模仿"换成"自己的对局 + 回报加权"，第一次让**回报**（而不是老师的动作）
影响策略。同时把设计里一直没跑过的 **§7.5 场外均衡审计**（判据⑩）做掉。

**采集**（策略串 `net:<上一代>#1.0` = 带温度探索的学生，占 1 席）：

| 轮次 | 生产者 | 场数 / 决策 | 用途 |
| --- | --- | --- | --- |
| `raw/v4-sp-001` | C++ 24 workers | **400 场 / 292,724 决策**（250 s） | **§7.5 均衡审计**（C++ 快，但它**不产 `aux.npz`**） |
| `raw/v4-sp-002` | Java 12 workers `--aux` | **200 场 / 143,612 决策**（256 + 54 s） | 数据集（信念/危险头要标签侧） |

**§7.5 均衡审计（判据⑩，首次执行）**：`v4-sp-001` → `--expect` 座位场核对 →
**座位最大偏差 0.000%**（阈值 1%）、配席 net/teacher/random = 400/800/400 与声明一致 ⇒
**均衡 ✓ 可用于判据**、`balance.json` 落盘。⚠ 首跑其实报了**假绿**：审计把"决策行"判成
"没有 `type` 字段"（老形状），而真轨迹写 `"type":"decision"` ⇒ 一条决策都没读到、
`seat_deviation`/`opponent_cv` 全是 0。修法三条：① 两种形状都认；② **空数据/无配席一律判不均衡**；
③ 夹具改成真形状（见 `NOTES.md` §6.5 第八轮）。**教训**：判据的"输入为空"必须自己变成红。

**数据集**（`compact/v4-sp-002`，129,176 训练 / 14,436 验证）：新增两列 ——
`is_student`（`--student <上一代的**确切**策略串>` 判定）与 `delta`（本小局该家收支）。
实测**学生行占比 26.1%**（33,691/129,176）—— 与"四席里一席是学生"完全吻合；
不遮的话这 3/4 的**对手/老师动作会被算进策略损失**（v3 踩过同一个坑：学生行占比 0.75 而非 0.25，静默）。

**训练**（10 epoch / 470 s）：学生掩码 + **RWR**（`--rwr-beta 8` 千点，权重 `exp(clip(delta/1000/β,-2,2))`
→ 实测 min 0.135 / mean 1.208 / max 7.389）+ 阶段 c `--stage-c-lr-mult 0.1` +
**关掉饱和的掩码重建**（`--mask-frac 0`，理由见第三轮的 0.968 结论）。

| 指标 | ep3 [b] | ep10 [c] |
| --- | --- | --- |
| val top1（**全部行**，即"和实际动手那家的动作一致率"） | 0.605 | 0.681 |
| val top1（**学生行**，即"预测自己采样出来的动作"） | 0.763 | **0.847** |
| value / belief_tenpai / danger | 3.96 / 0.336 / 0.480 | 3.46 / 0.245 / **0.677** ⚠ |

⚠ **danger 头的损失反而涨了**（0.48 → 0.68）：因为 RWR 权重一开始也加在危险头上，
而"赢的小局"多半没放铳 ⇒ 概率被系统性压低。**修法**：RWR 只作用于 `policy`/`effect`，
`danger` 只吃学生掩码（`value`/`placement`/`belief_*` 两个都不吃）—— 下一轮生效（本轮权重已训完）。

**结论（2+2 同牌山配对，n=800 场 / 每策略 1,600 席，C++ 24 workers）**：

| 对比 | Δ（顺位点，正 = 前者更好） | 95% CI | p | 胜/负/平 |
| --- | --- | --- | --- | --- |
| `v4-p3-001` vs **teacher** | **−1.96** | [−5.59, +1.69] | 0.358 | 386/413/1 |
| `v4-p3-001` vs **`v4-bc-004`**（上一代） | **−3.08** | [−6.71, +0.69] | 0.322 | 385/414/1 |

⇒ **两条都"证不出差别"**（CI 都跨 0），点估计还略偏负。**这一轮 RWR 没有可测的改进** ——
按 `sd(Δ)=52.8` 算，要检出 Δ=2.0 需要 **≈5,500 场**（本机 24 workers、2 席网络 ≈ 2 小时）。
它至少说明两件事：① 上一代（`v4-bc-004`，教师一致率 0.903）**已经站在 teacher 水平**；
② 200 场 / 3.4 万条 on-policy 行 + 无 critic 的 RWR，推动不了这个水平的策略。

**下一轮要改的三处（按性价比）**：
1. **量级**：一轮 **1,000–2,000 场**（Java + `--aux` 24 workers ≈ 2,600 s/千场；C++ 更快但不产标签侧
   —— 要用 C++ 就得先把 "aux 只覆盖部分行" 的掩码做出来）；
2. **目标**：把值头当 critic 的 **PPO**（`λ=1`、优势只按学生行归一化）取代"整小局回报"的 RWR；
   或退一步做"只学赢的小局 / 只学不放铳的决策"的过滤版，作为可解释的对照臂；
3. **评估预算**：一次对比 **≥2,000 场**，并把"要检出多大的 Δ"写进预先注册（本轮实测给了 `sd(Δ)`）。


### 第五轮：P3 加强版 —— 1,000 场自对弈 + PPO（2026-09-27）

**动机**（第四轮的结论）：200 场 / 3.4 万条 on-policy 行 + 无 critic 的 RWR 推不动"已经到 teacher 水平"的网。
这一轮把三处一起改：**量级 ×5**、**目标换成 PPO（值头当 critic）**、**评估预算 ≥1,000 场**。

**采集**（`raw/v4-sp-003`，Java + `--aux`，24 workers）：**1,000 场 / 689,693 决策**（自对弈 1,602 s + 派生 273 s），
配席 = **学生 2 席**（`net:<上一代>#1.0` 温度探索）+ **teacher 2 席**，`--rotate`。
⚠ 采集期自身就暴露了探索的代价：同一批对局里学生 **−3.78** 顺位点 vs teacher **+3.78**
（贪心的上一代与 teacher 基本持平 ⇒ **T=1.0 的探索让行为策略明显变弱**，on-policy 数据因此更"歪"）。

**§7.5 均衡审计**：座位最大偏差 **0.000%**、配席（座位场）net = 2,000 / teacher = 2,000 与声明一致、
逐座位各 500 ⇒ **均衡 ✓**、`balance.json` 落盘。

**数据集**（`compact/v4-sp-003`）：**654,414 训练 / 35,279 验证**（950 + 50 场），lmax 29，学生行占比 **50.0%**。

**PPO 落地**（`v4/pretrain.py` 的 `--objective ppo`，三条口径都有硬约束）：

1. **`log π_old` 现场重算**（`_behaviour_logprobs`）：前向是确定性的，所以只要给出
   ①采集用的权重（`--behaviour <ckpt|net.bin>`）与 ②采样温度（从数据集的 `student` 串里解析 `#T`，
   缺省 1.0），就能把当时采样用的分布逐行重算出来 —— 这是"离线做 PPO"的前提（不必在轨迹里存 log-prob）。
   ⚠ 缺 `--behaviour` 或缺学生掩码 ⇒ **直接退出**（不猜）。
2. **优势**（`_advantages`）：`A = R − E[V(s)]`，`R` = 数据集里的 `value`（整场收支，千点，与值头**同一个量**）、
   `E[V(s)]` = 值头 51 分箱的期望；**归一化只在学生行上做**（设计 §7.4 的硬口径），非学生行优势置 0。
3. **截断替代项**：`ρ = exp(logπ_new − logπ_old)`、`−min(ρA, clip(ρ,1±0.2)A) + 0.01·H(π)`，
   **只算学生行**；`danger` 只吃掩码（不吃任何回报加权 —— 第四轮踩过）。
   `--init <上一代 net.bin>` 从上一代权重起步，`--stage-a 0 --stage-b 0`（不从零训，直接联合微调）+ `lr 1e-4`。

③ **离线指标向好 ≠ 变强**：学生行 CE 0.861 → 0.601、top1 0.845 → 0.886，而强度是 −3.54 ——

**逐决策信用**（在 Java/C++ 侧按小局记 reward-to-go，才能算 GAE）→ 再谈放大场次。

### 第六轮：逐决策 reward-to-go —— 让 λ=1 的 GAE 目标可算（2026-09-28）

**动因**：第五轮判负的两条主因里，第二条是**优势的信用分配只到整场**（`A = R_整场 − E[V(s)]`）。
在线 PPO 的 GAE(λ=1) 要的是"**从这个局面起**的回报 − V(s)"，而离线数据当时只有整场结果 ⇒
同一场里所有决策共用一个 `R`，优势里没有"这一手之后发生了什么"。

**改动（契约 + 三端，一处口径）**：轨迹的每条 `decision` 行新增 **`reward_to_go`**（点）：

```
R(h, s) = Σ_{h' ≥ h} delta[h'][s] + 终局余棒[s]
```

- **含本小局**（打出去就结算了），**不含之前的小局**（那是已经实现的收益，不该再算进"从这里起"）；
- **加终局余棒**：末局结算后供託里那批立直棒按规则归末局第 1 位（`AGENTS.md` §6.4 ②）。
  不加它的话第 0 小局的回报会比 `final_scores − 起点` 少一个 0~3000 点的常数，值头目标与旧口径就对不上；
- ⇒ **不变式**：第 0 小局的 `reward_to_go == final_scores[seat] − start_score`（点）、
  末局 `== 末局 delta[seat] + 余棒`、且**真的逐决策**（多局时至少有一行 ≠ 整场结果）。

| --- | --- | --- |
| 契约 | `docs/PROTOCOL.md` §8.4（决策行字段表 + 三条不变式） | 三处一起改（`TraceRecorder` / PROTOCOL / `selfplay-check`） |
| Java | `TraceRecorder.rewardToGo`（后缀和，按 `hand_no` 对齐）+ `finish()` 在 `final_scores` **之前**写键 | `SelfTest.rewardToGoTests` 6 项；L1 **1429/0** |

⚠ **三条不许省的判断**（都是这一轮特意钉的）：
① **老轨迹写 NaN，不写 0**：`rtg` 缺席时填 0 会让优势变成 `0 − V(s)`（训练照跑、回报没了）——
所以数据集写 NaN + `--value-target rtg` 在 NaN 数据上**硬拒**；② **整体平移看不见**：优势在学生行上
归一化（减均值）⇒ 把 `R` 整体加一个常数不改变优势，判"换源有没有生效"的夹具必须让**逐行差不是常数**
（自检里同时钉了这两条）；③ **C++/Java 必须逐字同口径**：同一颗种子两份轨迹**逐字节相同**是唯一判据
（"两边都记了 reward_to_go"不算 —— 差一个 `>=` 就是偏差）。

#### 第六轮踩到的真 bug：温度只作用一侧 ⇒ 一个 step 整网 NaN（2026-09-28）

第一次用 `#0.5` 跑 PPO，**表面上跑完了 4 个 epoch**（还落盘了一份 checkpoint），实际：

```
epoch 1 [c]: train nan | val top1 0.156 = 首合法基线 | … policy nan value nan … | KL nan clip 0.004 |A| nan
```

**根因**：采集侧 `net:…#T` 抽的是 `softmax(logits/T)`，而 `logp_new` 是按 `T=1` 算的 ——
`logp_old` 到 **−70.5**、`logp_new ≈ 0` ⇒ `ρ = exp(65) ≈ 2·10^15`、策略损失 **2.5·10^11**
⇒ 一个 step 之后全参数 NaN。⚠ **`--behaviour-temp` 缺省 1.0 时这个 bug 完全不可见**
（`logits/1.0 == logits`），所以它在上几轮里一直没暴露。

| 交付 | 内容 |
| --- | --- |
| 修 | `_policy_logits(out, T)` 一处实现；`compute_loss(..., policy_temp=T)`；`train()` 把 `p_temp` 传下去；熵奖励也用同一份 logits |
| 闸门 ①（口径） | `assert_behaviour_consistency()`：初始化时 **π_new 必须就是 π_old**（同权重 + 同温度），`KL > 1e-2` ⇒ 退出 |
| 闸门 ②（发散） | 训练循环里 loss 非有限 ⇒ `SystemExit("训练发散…")` —— ⛔ 绝不落盘"跑完了"的废 checkpoint |
| 诊断 | `train_parts["logp_gap"]` = `\|log π_new − log π_old\|` 最大值（正常 ≲ 1，事故里 65）；epoch 行也打印 |
| 温度权威 | `--behaviour-temp` 与数据集 `student` 串里的 `#T` 冲突 ⇒ 退出；缺省从 meta 解析 |
| 自检 | `selfcheck` **488/0**（+9）：一致时 ρ≡1、`logp_gap≈0`、**有量级 logits 的红证**（ρ=e²⁰）、闸门正/负证、发散即停 |

⚠ **夹具的天花板也要写下来**：这套自检夹具是"未训练网 + 两个只在派生段不同的候选"，
逐候选 logits 差 ~1e-9（实测 `KL(seed1‖seed2) ≈ −2e-6`）⇒ **温度在这套夹具上量不出来**
（差 ~1e-5 < 阈值）。所以温度红证改用**有量级的合成 logits**（`[20,0]` + 标签落在尾部），
闸门负证改用"直接改错 `logp_old`" —— **写清楚"夹具量不出什么"比写一条永远为真的断言强**。
真数据上的量级（`compact/v4-sp-004` 前 64 行、训练过的 p3-001）：`logp_gap = 3.54`、`ratio ≤ 34.5`。

#### 第二个 NaN（完全不同）：非学生行的 `inf × 0`（第 757 步）

修完温度口径后**仍然**在第 757 步 NaN，但指纹完全两样：`parts["policy"] = nan` 而
`kl` / `clip_frac` / `logp_gap` **全是有限**、`|θ|max` 纹丝不动 ⇒ 不是参数发散，是**一批里的算术**。

**机制**：非学生行的动作是 teacher / 随机 选的，在**学生网**下几乎必然是零概率（网的 logits 幅度到
563，`#0.5` 再翻倍 ⇒ `logp_new` 到 −1000 量级）⇒ `ρ = exp(logp_new − logp_old)` **溢出成 inf**；
而优势在非学生行上的定义值**正是 0** ⇒ `inf × 0 = NaN` 污染整个加权求和。

**修法（两道保险）**：① `log ρ` 夹在 `±LOG_RATIO_CLAMP = ±4`（ρ∈[0.018, 54.6]；ε=0.2 的截断区间
远在界内 ⇒ **正常样本逐位无影响**；同时界住 `A<0` 的**悲观支** `ρA` 的无界增长 —— dual-clip 的动机）；
② 替代项在**未选中的行上显式置 0**（`where` 是选择、不是乘法）。
**判据**：`selfcheck` 手工算未夹取版**必须是 NaN**（机制成立）+ `compute_loss` 同批有限。

✅ **修完之后的训练（`v4-ppo-002`，4 epoch / 685 s）**：`train 2.4412 → 2.3314`、
`val top1(教师一致) 0.867 → 0.879`、**学生行 top1 0.888 → 0.900**、学生行 CE 0.653 → 0.583、
**KL 0.0657 → 0.0105**、截断 0.171 → 0.059、`logp_gap` 2.60 → 1.04 ⇒ 全程有限、稳在信任域内。

| 权重文件 | ≤8 MB fp32 / ≤2 MB int8 | 精度敏感层保 fp32（LayerNorm、softmax 前） |

> 只记实测：服务端单线程 **22.50 ms/决策**（含特征；L2 增量缓存后，`tools.V4Probe --cache`）。

### 10.1 `compact` 相（`python -m mahjong_ml.v4.dataset build`）：**3.7~5.2×**，产物逐字节不变（2026-10-05）

`compact` 原本是训练回路里最大的一块（≈450 s/代，占 55%）。**四条纯提速**改造，判据是
**同一份 raw / 同一组参数下 49 个列文件（+`meta.json`）的 SHA256 全同** —— 不是"看起来一样"：

| # | 改哪（文件:函数） | 为什么 |
| --- | --- | --- |
| ① | `v4/dataset.py:_write_file` —— `tk.advance(evts[:max(0,n-K)])` | `h0(n) = carry(events[0, n-K))` 是**前缀函数** ⇒ 窗口内那 K 条对 `h0` 没有任何影响。原来每次决策都把整手事件重放一遍，于是 96% 的决策（一手事件数 ≤ `K_EVT`=60）白跑 `event_matrix`→`enc`→`GRUCell` |
| ② | `v4/dataset.py:pin_torch_threads` + `_spawn(env=CHILD_ENV)` | 逐事件递推是 `[1,C]×[C,d]` 的小 GEMM：`num_threads=24` 实测 **115 µs/步**、`=1` **52 µs**；`--workers 12` 时是 12×24 个线程抢 32 个逻辑核（`compact` 的每个子进程都要跑 torch，`v3.dataset.CHILD_ENV` 那套纪律这里原来漏了） |
| ③ | `v4/blocks.py`（`tile_matrix` / `event_matrix` / `cand_matrix`） | 7 列静态牌性提成模块级数组；牌码→kind、动作键→基础候选向量、dora 集合→列 **记忆化**；`put()` 闭包换成按 `TILE_OFF` 的直接切片；三家"打牌事件"**只筛一遍**（原来每家各扫一遍全事件流） |
| ④ | `v4/dataset.py:_game_start_score` / `_rank_points_of` | 只读文件尾取 `start_score`；`summary.json` 按 **(路径, mtime, 大小)** 记忆（1000 场原来要把同一个 446 KB 的文件解析 1000 遍 ≈ 450 MB） |

> ⚠ **这条记忆的键有个 Windows 陷阱，2026-10 修**：文件时间戳分辨率 ≈ 时钟 tick（~15.6 ms）
> ⇒ **同一个 tick 内、字节数不变**地重写同一个 `summary.json` 会算出**完全一样的键**，
> 读回**旧表**（实测：背靠背两次 `write_text`，**90% 命中**；隔 >1 ms 才不命中）。
> 生产路径不受影响（`summary.json` 是采集时一次写成的、从不原地改），但
> `python/selfcheck.py` 的负向对照恰恰要"改坏再读一次" ⇒ 它原来**静默空转**（测的是缓存，
> 不是被测代码；而且 flaky：第一次 659/1、重跑 659/0）。修法两条一起：
> ① `v4.dataset.clear_rank_points_cache()` —— 显式清记忆表（直击根因，不赌 tick）；
> ② 负向对照的夹具值 `-15.0 → -1.0`（**少一个字节** ⇒ 即使记忆表被重新引入，键也不同）。
> 判据：该负向对照**把被测代码改坏必须变红**（见 §15.7.3 末的红证），且 `selfcheck` 连跑三次 659/0。

实测（i9-14900HX / 32 逻辑核；raw = `raw/v4-league8-g04`，`--aux --student net:<v4-league-g08>/net.bin@0#0.5`）：

| 工况 | 改前 | 改后 | 倍数 |
| --- | --- | --- | --- |
| 20 场 × `--workers 1`（before/after **交错各 3 次**取中位） | 22.66 s | **5.96 s** | 3.80× |
| 200 场 × `--workers 12` | 90.5 s | **21.9 s** | 4.13× |
| 1000 场 × `--workers 12` | 453 s（2026-10-04 联赛实测） | **85.7 / 87.8 / 128.8 → 中位 87.8 s** | ≈5.2× |

cProfile（20 场 / 1 worker）：函数调用 **2887 万 → 1599 万**；`torch.gru_cell` **44,789 → 1,378** 次
（3.44 s → 0.07 s）、`torch._C._nn.linear` **89,578 → 2,756** 次（2.52 s → 0.04 s）、
`dict.get` 943.7 万 → 880.5 万、`numpy.asarray` 95.2 万 → 49.0 万、`numpy.array` 11.7 万 → 掉出前 45（<0.06 s）。

**判据（必须成对）**：① 49/49 个 `.npy` + `meta.json` 的 SHA256 **全同**（串行 20 场：交错 3 对比对
+ 另一组 `--student` 各一次；并行 200 场 ×1 组）；② `h0` 的**非全 0 行占比**不变
（train 3.88% / val 0.95%，`meta.h0_nonzero_frac` 一致）。
例：`train.h0.npy` = `CAD092FA…BCEBB1`、`val.h0.npy` = `FA4B2E9C…C760BB`（改前改后同一个哈希）。
⛔ **没有改任何口径**：`h0` 仍是"**窗口之前**的整手 carry"、仍是**学生网**算、仍是构建期冻结 ——
这一改只是**不再算用不上的那一段前缀**。谁要拿 `CarryTracker` 取"当前 carry"（`tracker.h`），
就必须把 `advance` 的参数改回全量事件（`_write_file` 里那条注释写着同一句）。
⚠ 测速**必须交错**（before/after 交替各 3 次）：raw 在 `S:` 上，页缓存被大文件挤掉时同样的一次
构建会从 6 s 变成 **17 s**（实测踩到过，差点把 IO 抖动读成回归）。

## 13. 一页速查

- **信息上界 = 人类玩家**（不是 teacher）；**teacher = 起点 + 对手 + 基准**。
- **输入**：`tile[34,48]` + `evt[60,96]` + `ctx[64]` + `cand[n,128]`，块可关（消融）。
- **架构**：三塔 → 关键张注意力 + 事件注意力 → 状态/增量**两轮双向** → 多头（策略 + 分布价值 + 信念/危险 + 牌效）。
- **性能**：增量缓存 + 循环推理 ⇒ 每决策 O(新增)，1.5 M 参数；**实测** 38.12 → 22.50 ms/决策
  （**不设时间指标**，`FEATURES-V4.md` §8）。
- **封闭（训练期也要）**：引擎上帝视角**只写标签** —— 输入不碰、**奖励不碰**、辅助头不回喂；三条红证
  （删标签→logits 逐位不变 / 改隐藏量→obs 逐字节不变 / 奖励不含过程隐藏量）。
- **场外因素必须分层平均**（seat / 亲家 / 局 / 对手×座位 / 种子 / train-val 切分）：每轮出 `balance.json`，
  超阈的轮次**不得当判据**；消融与 2+2 只在均衡场次上做。
- **判据**：主判据是 **2+2 配对 vs teacher（Δ≥+2、CI 排除 0、≈5,200 场/臂）**；消融矩阵回答"哪块信息值多少"。
- **阶段**：P0 冻结契约 → P1 自监督 → P2 teacher 只做冷启动 → **P3 打到强于 teacher** → P4 押し引き → P5 上线。
- **PPO/多头的重新规划**（2026-09-28，依据 = 实测）：**先量（消融 + 校准）→ 换回报与信用分配（小局级 GAE）
  → 补 PPO 口径 → 再动多头/架构**；细节与优先级见 **§14**。

## 14. PPO 与多头：重新规划（2026-09-28）

> 本节的出发点**不是设计直觉，而是这一轮量出来的数**：`rtg` critic 三次尝试都学不出来（EV 0.002–0.010）、
> 整场值头 EV 0.44–0.57 但覆盖率不达标（95% 只盖 82–87%）、推理端**只消费策略头**。
> ⚠ 那 0.44–0.57 在第十九轮被查清：**大部分是 `ctx.points` 的恒等式**（`legit_ctx` 单独就有
> EV(`value`)=0.446，见 §14.8.1），不是"读得懂局面"；小局收支 `delta` 的**合法**天花板是 **0.069**
> （旧文档里的 0.632 是把本小局结局 `win_flag` 算进去了，属于作弊上界）。
> 逐条证据在 `NOTES.md` §6.5 第十二/十三/十四轮与 §8.2 的实测表。

### 14.1 现状体检（六条，全部有数）

| # | 事实（实测） | 后果 |
| --- | --- | --- |
| ① | `A = R − V̂(s)`，`R` = `rtg`（多手后缀和）时 **EV 0.002/0.006/0.010** | **critic 没有 baseline** ⇒ "PPO" ≈ 无基线的 REINFORCE；第五/六轮"只到打平"与它一致 |
| ② | 同一批数据、同一表示：小局收支 **EV 0.632**（引擎真值 10 列线性）、`rtg` 0.090、整场 0.059 | **可学的粒度是"这一小局"**；多手后缀和基本是运气。⚠ 第十九轮：0.632 是**作弊上界**（含本小局结局列），**合法**天花板 0.069；但"`delta` ≫ `rtg`"的**对比**仍成立（§14.8.1） |
| ③ | `Var(value)=410.7`、`Var(rtg)=229.5`、`Var(value−V)=238 > Var(rtg)` | "整场值头 − 已滚入"这种构造**数学上赢不过 0 EV** ⇒ 换口径不是调参能救的 |
| ④ | 值头分布欠覆盖（95% → 82–87%，50% → 44–47%），且是**单层 Linear(192→51)**（9.8k 参数） | 欠覆盖可用 loc-scale 校准修（§14.7）；⚠ 第十九轮证明**加宽/加深读出头没用**（池化与 2×256 MLP 都试过，见 §14.8.2）—— 这条的"形状表达不足"判断**已被推翻** |
| ⑤ | 危险头只在**实际打出的那一张**上算 BCE（1/L 监督）；`effect`/`belief_hand` 纯诊断；推理端**一个都不读** | 梯度花在无用/极稀疏的地方；押し引き就算要上线也没有可信的概率 |
| ⑥ | 训练回报 = 点数差，**评测口径 = `rank_points`（顺位点）**；PPO 缺 `grad-clip`/KL 早停；优势每步重算（移动基线）+ 批内 z-score | **目标与度量不一致**；数值闸门比 v3 少；优势尺度语义被破坏 |

### 14.2 重新规划（三层）

**第一层 · 回报与信用分配**（决定"能不能学"，最高优先）
- **奖励换成"小局收支 + 顺位点"**：`r = delta/1000 + w_rank·1[终局]·rank_points`（v3 的 `--rank-weight` 有先例）。
  理由：评测读的是 `rank_points`，而现在的回报只有点数差 ⇒ 训练在优化另一个量纲。
- **手级 GAE（λ<1 + bootstrap）**：把**小局**当时间步 ——
  `δ_t = r_t + γV(s_{t+1}) − V(s_t)`、`A_t = Σ_k (γλ)^k δ_{t+k}`；`s_{t+1}` = **同座下一小局的第一个决策**
  （`game/hand_no/seat` 已在数据集里，`next_index` 可免费构造），末小局 bootstrap 0（或顺位点项）。
  ⇒ V 的目标变成 **TD(λ) 回报**，不再要求"预测之后所有小局"；这正是②给出的可学口径。
- **V 目标分解**：`V = 已知已滚入（ctx 里的点数差）+ 残差头`——把③里那 167.8 的已知方差**结构化地减掉**，
  只让网络学剩下那块。

**第二层 · critic 与 PPO 口径**（决定"学得稳不稳"）
- 值头容量与校准：`Linear` → `Linear→GELU→Linear`（三端改动，见 P4）+ **温度缩放**（一个标量，Python-only）
  修覆盖率；判据 = §8.2 的"覆盖率与标称差 ≤3pp"。
- **优势冻结**：一个 epoch 内 `A` 用行为策略时的 V 算**一次**（现在每步重算 = 移动基线）；值损失照常更新 V。
- 补 `--grad-clip`（0.5）与 KL 早停（0.03），与 v3 对齐。
- 优势标准化改**全局 running 统计**（现在的批内 z-score 让 clip 的 ε 失去绝对含义）。
- `objective=ppo` 时**断言禁 RWR 权重**（否则优势被再乘一次权重，口径混乱）。
- 双口径 KL：训练分布 `softmax(z/T)` vs 部署 `argmax`（T=1）——把 off-policy gap 显式化。

**第三层 · 多头分层**（决定"算力花在哪"）
1. **上线层**：`policy`（现在唯一被消费的）；将来 `value` 接风险敏感、`danger`/`belief_tenpai` 接押し引き。
2. **训练信号层**：`value`（critic）、`danger`、`belief_tenpai`。
3. **诊断层**：`belief_hand`、`effect`、`placement` —— **按消融结果降权或停用**（v3 已证明"辅助头更准 ≠ 更强"）。
4. **危险头稠密化**：用 sidecar 的逐家逐张危险度做**全候选蒸馏**（每样本 L×3 个标签），真实放铳 BCE 只作校准项；
   判据 = §8.2 的 ECE ≤0.05 + 押し引き消融。

⇒ **读出头不是瓶颈，P4-lite 取消。** 一个 51 箱的分布头拿到 80% 的合法线性天花板，
在这个目标上是**正常且接近最优**的表现；`pred_std 1.30` vs 真值 `5.21` 也**不是 bug** ——
低信息目标下"收缩到均值"正是最优解。

#### 14.8.3 基线尺度对齐（`--baseline-fit`，缺省 `scale`）：把 2.671× 修回 0.998×

判据：**基线只要是状态（动作无关）的函数，任何线性变换都不改梯度期望、只改方差** ⇒
在**学生行**上按最小二乘拟合 `α + β·V` 就是同一族里方差最小的那个（`β=0` 是它的嵌套特例，
所以**不可能**比"只减均值"更差 —— 自检把这条钉成红证 + `SystemExit` 守卫）。
P1b 的 `V_old` 来自 `v4-p3-001`（值头目标是**整场**收支，`std 12.392` 千点），而奖励是小局收支
（`std 5.047`）⇒ `β` 应当 ≈0.08 而不是 1。重标定后 `std(A_raw)/std(delta)`：
**2.671× → 0.998×**（`--baseline-fit none` 时日志仍并列打印这个对照）。

#### 14.8.4 判据修订（**闸门从"绝对 EV ≥ 0.4"改成两条可测的**）

| 原判据 | 为什么废 | 新判据 |
| --- | --- | --- |
| `EV ≥ 0.4` | **构造上不可达**：`delta` 合法天花板 0.069、`rtg` 0.014、整场 `value` 的 0.44 是 `ctx.points` 恒等式 | ① **EV ≥ 0.7 × 合法天花板**（`--ev-ref legit` 现算，随数据集滚动） |
| `std(A) 明显下降` | 未说明相对谁 | ② `std(A_raw)/std(目标) < 1.0`（`--baseline-fit scale` 下**必然**满足，不满足即报错） |
| 覆盖率 ≤3pp | **保留**（这是唯一"能做也能测"的一条） | ③ 50/80/95% 覆盖率与标称差 ≤3pp（loc-scale 校准后已到 2.8/3.4/2.2pp） |

**比例为什么取 0.7**（不是 0.8、也不是 0.9）：参照本身是**线性**岭回归、val 上 n=3.5 万 ⇒
抽样噪声约 ±0.005（相对 ±7%），且非线性上限可能略高。0.7 能把两件事分开：
**"学到了这一口径的信号"**（实测 `v4-hand-001` = **0.80 ×**、`v4-hand-003` = **0.72 ×**）与
**"塌成均值"**（EV ≈ 0.02 ⇒ **0.3 ×**）。取 0.8 就会在噪声里判生死 —— `v4-hand-003` 实测 0.0496
（0.72 ×）正好卡在 0.8 的门外，那次 FAIL **不是**信息。

⇒ 用新闸门复判这两轮（`--target delta --strict --ev-ref legit`）：**值头已到天花板**，
`v4-hand-003` 的覆盖率三档全过（2.1/2.5/1.6pp）、CE 与 CRPS 都低于基线。

⚠ 判据①的推论：**在 `delta`/`rtg` 这类"实现值"目标上，critic 最多只能买到 ~5% 的优势方差削减。**
想让 critic 真正有用，得换**信息更密的时间尺度**（逐决策的牌效/进张变化，即 shaping 奖励），
而不是继续在"小局收支"上抠读出头 —— 这属于路线上取舍，见 `docs/HANDOVER.md` §3。

### 14.9 第二十轮：**逐决策 shaping 也救不了 critic**（potential-based shaping 实测 + 定理，2026-09-28）

> 用户选定的路线 A = "换更密的时间尺度"。按 §14.8 的纪律，**先量再写代码**：新加
> `value-audit --shaping`（势函数 × θ 扫描），判据不是"shaping 目标的 EV 多高"（那会被**状态已知**
> 成分刷高 —— `ctx.points` 那次的教训），而是**绝对量纲**下的残差比 `std(y − ŷ)/std(R_c)`，
> 其中 `ŷ` = 用合法特征在 train 上闭式拟合的最优线性 critic。

#### 14.9.1 口径

`r'_t = r_t + θ·(γ^{n_t}Φ_end − Φ_t)`（`Φ` = 势函数，只用**公开且决策时能算**的引擎量：
`aux_own_shanten_after` 或 `aux_own_tenpai`；`n_t` = 到本小局末还剩几步）。
`Σ_t γ^t r'_t = Σ_t γ^t r_t + θ(γ^n Φ_end − Φ_0)` —— **望远镜相消**（自检红证），
所以 θ 取任何值都**不改变最优策略**（Ng 1999），选 θ 只是选方差。

#### 14.9.2 实测（`compact/v4-sp-004`，train 40,000 / val 20,000 行，`std(R_c)` = 5.174 千点）

| θ（千点/每单位势） | `shanten` 残差比 | `tenpai` 残差比 |
| --- | --- | --- |
| −8 | 1.401 | 1.024 |
| −4 | 1.039 | 0.933 |
| **−2** | 0.956 | **0.933** ← 两个势函数的最小值 |
| −1 | **0.948** ← 最小值 | 0.945 |
| −0.5 | 0.953 | 0.954 |
| **0（现状）** | 0.965 | 0.965 |
| +0.5 | 0.981 | 0.977 |
| +1 | 1.004 | 0.991 |
| +2 | 1.063 | 1.024 |
| +4 | 1.231 | 1.108 |
| +8 | 1.683 | 1.327 |

- 残差比在 **θ≈0 附近取最小、两侧都变差**；最好的组合（`tenpai`、θ=−2/−4）也只到 **0.933**，
  即"优势噪声降 3.2%" —— 与我预设的"值得进训练回路"门槛（<0.8）**差得远**；
- shaping 目标的 `legit_ev` 会随 |θ| 涨（`shanten` θ=−8 时到 0.400）—— 但那是**状态已知成分**
  （`Φ_t` 本身就在合法特征里）被读出来了，**不等于**优势更好。这正是 §14.8 那个 `ctx.points`
  恒等式的同一条陷阱，探针的判据（绝对残差）就是为了绕开它。

#### 14.9.3 为什么必然如此（定理，自检有数值红证）

**PBRS 不改变优势函数**：`Q'(s,a) = Q(s,a) − Φ(s)`、`V'(s) = V(s) − Φ(s)`
⇒ `A'(s,a) = Q' − V' = Q − V = A`。自检用一个 5 状态 × 3 动作的随机 MDP 做值迭代，
断言 `max|ΔA| < 1e-9`（实测 7.1e-15）。既然优势**逐项不变**，那么
"用 shaping 让 critic 有东西可学 ⇒ 优势方差下降"这条路**在原则上就不成立**：
唯一能省下的只是近似误差，而实测那点收益（≤3%）被"回报里多出来的未来势 `Φ_end` 方差"吃掉了。

#### 14.9.4 ⇒ 结论与剩下的选项

- ⛔ **路线 A（potential-based shaping）判死**：定理 + 实测双向一致。`P4-lite`、`--shaping-*` 都**不做**；
- 但仍然可以在**明确知道会改变目标**的前提下做**偏置 shaping**（`r = 小局收支 + w·逐决策牌效进展`，
  w 非 0 且不做终局对齐）：它**不是** PBRS ⇒ 会改变 A ⇒ 才是真能降方差的那一类，
  代价是**最优策略被改**（可能变保守/变激进），只能靠**对局强度**判成败，不能靠 EV 判。
  探针工具已经就位（`--shaping` 的 θ 轴 + 残差比），要再往前走就是"选一个 w、跑一轮、打 2+2"；
- 另一条完全不碰 critic 的路：**补 PPO 数值口径**（`grad-clip`、KL 早停、全局优势标准化、禁 RWR）
  与**样本量**（`sd(Δ)≈53` ⇒ 检出 Δ=2 要 ~5,400 场）。`docs/HANDOVER.md` §3 已按这两条改写。

### 14.10 第二十一轮：PPO 数值口径（用户选定的路线 B）—— 量级问题比预想的大

§14.1③ 的体检说 v4 缺 `grad-clip` 与 KL 早停（v3 有 0.5 / 0.03）。这一轮补齐，并在
`compact/v4-sp-004` 上跑一轮 `v4-hand-004`（其余开关与 P1b 完全一致，只加数值口径）：

| 开关 | 缺省 | 作用 |
| --- | --- | --- |
| `--grad-clip` | 0.5（v3 口径） | 按**总范数**裁剪；日志里的 `\|g\|` 是**裁剪前**的范数（不砍与砍的 loss 逐位相同，只看 loss 看不出来） |
| `--kl-early-stop` | 0.03（v3 口径） | `KL(π_old‖π_new)` 越过阈值就**停整轮**（离线单轮 1~2 epoch，"离行为策略太远"跨 epoch 只会更严重） |
| `--kl-min-steps` | 100 | 早停生效前至少跑多少步（第一批的 Monte-Carlo KL 噪声大） |
| `--rwr-beta` × `--objective ppo` | **硬拒** | 优势已是回报加权，再乘 `exp(回报/β)` = 对同一份回报**二次加权**（静默失真） |
| 双口径 KL | 恒开 | `kl` = `KL(π_old‖π_new)`；`kl_inv` = `E_old[ρ·log(π_new/π_old)]` = `KL(π_new‖π_old)` |
| 优势归一化 | 手级路径 = **全局一次** | `adv_tr` 已在 `_hand_advantage` 里按学生行全局 z-score ⇒ 训练里 `norm="none"`（**绝不二次归一化**）；遗留的 V 每步重算路径才是批内 |

**实测（`v4-hand-004`，与 `v4-hand-003` 同数据/同行为策略/同 lr，只加数值口径）**：

| 量 | `v4-hand-003`（无数值口径） | `v4-hand-004`（本轮的） |
| --- | --- | --- |
| 实际训练步数 | 5144（2 epoch 跑满） | **102**（KL 早停在 step 101） |
| `\|g\|`（裁剪前） | 未记录 | **6.33** ⇒ 每步都被裁到 0.5（**12.7×**） |
| `KL`（学生行） | epoch 级 0.0619 → 0.0198 | 触发步 **0.0707**；101 步均值 0.0375 |
| `kl_inv` | 未记录 | 触发步 **−0.0116**（101 步均值 +0.0290） |
| 学生行 val top1 | 0.897（结束时） | **0.893**（**102 步就到**） |

两条读数（都指向"之前的 PPO 轮次跑得远超预算"）：
1. **KL 早停在第一处生效点（step 101）就炸了**：单批 `KL=0.0707 > 0.03` —— 也就是说前几轮的
   5144 步里，**绝大部分是在 v3 早就该停的地方之后继续跑**。而 **102 步就把学生行 top1 推到
   0.893**（P1b 跑满 5144 步是 0.897）⇒ 那些多出来的步数买不到一致率，只在扩大与行为策略的距离；
2. **裁剪前的梯度范数是 6.33**（上限 0.5）：没有 `grad-clip` 时每一步的实际步长是设定值的
   **十几倍**，这也解释了历史上"KL 从 0.062 掉到 0.020 却把策略带歪"（`v4-critic-rtg` 那种
   top1 0.882 → 0.546）那类现象为什么反复出现。
   ⚠ `kl_inv` 在触发步是**负的**（−0.0116）⇒ 那次移动由**少数行**的大 `ρ` 主导 ——
   只看 `kl` 会以为"整体只挪了 0.07"，双口径正是为这种情形加的。

⇒ **口径改成"多轮 × 每轮短"**：既然 100 步就到 KL 预算，一轮的价值不在"epoch 数"而在
"**重新采一批**"（新轨迹 = 新行为策略的分布）。这与 `docs/HANDOVER.md` §3 的"在线多轮"合并：
`v4 loop --no-java` 每轮采→训（~100 步）→换行为策略，比"一轮跑 5,000 步"更符合 PPO 的假设。

### 14.11 第二十六轮：对**现任**的 KL 锚（W3）与验证集早停（2026-10-04）

**要解决的问题**（`NOTES.md` §6.5 第六十二轮）：联赛每轮从现任 `g08` 起步，PPO **只走 66/600 步**
（`--kl-early-stop 0.03` 触发）⇒ 候选只是现任的**微小扰动**；而验收闸门在 n=2000 时的分辨率只有
**±2.35 顺位点**（行为等价的候选都测出 −0.13）⇒ **看不见进步也证不出退步**。用户的决定：
**不加算力**，改成"让每轮真的能动（放宽 KL 预算）+ 让方向可靠（对现任加 KL 锚）+ 用廉价低噪的
验证量当第一读数 + 防过拟合"。

#### 14.11.1 对现任的 KL 锚（`--ref` / `--ref-beta`）

| 开关 | 缺省 | 作用 |
| --- | --- | --- |
| `--ref <net.bin \| model.pt \| ckpt 目录>` | `--init` 那一份（= **现任**） | 锚的参考策略 π_ref；只在 `--ref-beta > 0` 时被读取/载入 |
| `--ref-beta <β>` | **0** | `loss += β·KL(π_θ(·\|s) ‖ π_ref(·\|s))`；**0 = 与加这个功能之前逐位相同**（连参考网都不建） |
| `v4 loop --ref-beta` | 0 | 回路里的锚**就是 `--init`**（= 本轮的现任网），所以只转发 β；β=0 时命令与以前**逐字相同** |

损失项的三条口径（都在 `pretrain.compute_loss` 里，一眼可见）：
① **只在学生行上算** —— 与策略损失同一个 `row_keep`（对手/老师的行不是"我们要训的那个策略"）；
② **同一把温度尺子** —— `softmax(logits/T)`，与 `_policy_logits()` 逐字一致（温度只作用一侧
会让 `ρ` 炸到 1e15，见 §14.10 的那条坑）；③ **π_ref 冻结** —— `requires_grad_(False)` + `eval()`
+ `no_grad` 预算 logits（`_ref_logits` 一次性算完；每 batch 现算是 `epochs ×` 的浪费）。
每个 epoch 行打 `ref_kl=<值>（β=…，占总损失 …%）`；`train()` 返回 `ref_beta` / `ref_kl` /
`ref_kl_mean` 进台账。

**为什么是 `KL(π_θ‖π_ref)`（反向 KL）而不是 `KL(π_ref‖π_θ)`**：
`KL(π_θ‖π_ref) = E_{π_θ}[log π_θ − log π_ref]` 是 **mode-seeking** —— π_ref **低概率**的地方只要
π_θ 也低就不受罚，于是它鼓励 π_θ 比 π_ref 更尖、把质量挪到 π_ref 的几个峰上（"别自作聪明地偏离
现任"）；正向 `KL(π_ref‖π_θ)` 是 **mass-covering** —— π_ref 有质量的地方 π_θ 必须也有，会逼 π_θ
覆盖 π_ref 的整个支撑集（尾巴摊平），与"单调精修"的目标相反。W3 的设计文档写的就是前者。
两者的 logits 梯度也长得不一样（写进注释与判据里）：反向 `∇_z = π_θ ⊙ (log π_θ − log π_ref − KL)`
（在每个 `π_θ=0` 的格子上恒为 0），正向才是 `π_θ − π_ref`。

**判据（临时脚本，跑完即删；不往 `python/selfcheck.py` 里加）**：
· `ref_kl_term(logits, ref_logits, mask) == 0` **恰好**（不是 ≈0）当 `logits == ref_logits` 逐位
（含两侧都有 `masked_fill(-inf)` 的真实形状）；
· 梯度与解析式对拍（`|Δ|max = 3.3e-17`），且按 `−∇` 走一步后 `KL(π_new‖π_ref)` **下降**
（`0.084285 → 0.083781`）；非学生行的梯度**恰好 0**；`softmax(logits/T)` 口径与手算一致；
· **β=0 逐位等价**：同一个进程里把 **HEAD 那份 `pretrain`** 与本份新代码各跑一遍
`--max-steps 2 --epochs 1`，比较 ckpt 的 `state_dict`（`model` + `ssl_head`）**逐位相同**、
`history` 逐字段相同（实测：不同张量数 **0**）；
· β>0 时该项**真的在动**：总损失的增量恰好等于 `β·KL`（实测 `0.0477061` vs `0.0477061`），
同样跑一步后带锚的那次离 π_ref **更近**（`0.44095 → 0.24307`）。
⚠ 造"非零 KL 的 π_ref"时**别只扰动 `heads.policy`**：它是 `Linear(d→1)`，改它的 w/b 只给整行加
一个**与候选无关**的常数 ⇒ softmax 逐位不变、KL 恒 0（本轮的判据脚本第一版就踩了这条，靠
"C0 扰动后必须不是同一个分布"那条前置判据抓出来）。用**随机初始化**的网当 π_ref 也会假绿：
v4 的随机网常常落在 **ReLU 死区**（实测逐候选 logits 全是 `0.0361`）⇒ 分布与候选无关。

#### 14.11.2 验证集早停（`--val-every` / `--val-patience`）

| 开关 | 缺省 | 作用 |
| --- | --- | --- |
| `--val-every <步>` | 0（关） | 每多少步在**固定子集**上读一次 train/val 的 policy CE |
| `--val-patience <次>` | 3 | val CE 连续这么多次没有改善（相对**最好值**，容忍 `1e-4`）就**停这一轮** |
| `v4 loop --val-every/--val-patience` | 0 / 3 | 只在 `--val-every > 0` 时进训练命令 |

· 读数**复用现成的 `evaluate()`**（`ce_probe`；`evaluate` 新增 `rows=` 参数按行子集评），取
`loss_policy` —— 与 epoch 行的 `policy {val_loss_policy}` **同一个口径**，不另写一份指标；
· 行子集由 `probe_rows()` **固定**（同种子抽一次、升序）：每次换样本的话，两次之差里混着采样噪声，
"val CE 有没有抬头"就判不出来；
· 日志**同时**打两条（`[val] step N: train CE … | val CE …（最好 …，连续 k 次未改善）⇒ 还在学/
可能开始记数据`），epoch 行也带上最后一条读数 —— 一眼看出是"还在学"还是"**开始记数据**"；
· 早停是**正常收尾**：只置 `stop_reason` 后 break，照常 `evaluate` / 追加 `history` / 写 ckpt

### 14.12 第二十七轮：**逐候选引擎标签**（W4 第一步，稠密低噪的监督信号）2026-10-04

> ⛔ **先读这条：本节下面的读数已被后续实测证伪成"进步"**（`§14.12.6`）——
> 引擎牌效标签**不含打点/押し引き**，优化它必然把这两样换掉：一季第 1 代 `engine_top1` 涨了
> **+6.95pp**，同一代闸门却是 **−12.65 顺位点**（CI 半宽 2.25，越界 5 倍；和了率 24.1%→20.8%、
> 平均打点 7037→6010）。⇒ **`engine_top1` 不是"强不强"的读数，禁止当进步判据**；
> `--il-weight > 0` **不得**单独当训练目标。`--il-weight 0`（缺省）与 `--ref-beta` 的行为不变。

**为什么要换信号**（`NOTES.md` §6.5 第六十二轮）：RL 这条路已被证明"**看不见自己的进步**"——
每轮从现任 `g08` 出发，PPO 只走 100~150 步（`--kl-early-stop` 用满也只有 0.05 nats），而验收闸门
在小算力下的分辨率是 **±2.35 顺位点**（一个**行为等价**的候选都测出 −0.13）⇒ 效应小于尺子的刻度。
**唯一可测的进步只有"验证集 policy CE 的小幅下降"，而那是"更贴合行为数据"、不是"打得更好"。**
⇒ 需要**信息密度更高、噪声更低**的信号。这一轮做的是其中最便宜的一条：

> **引擎本来就在每一行给出"逐候选"的牌效量**（打后向听 / 进张枚数 / 听牌形）——它无采样噪声、
> 无 critic、**不花一格闸门算力**，而且**每一份现有紧凑集里都有**（不需要新采集、不需要新生产者、
> 不新增列）。

**标签的判据**（`engine_best_index` 的 docstring 就是契约，逐条有单测）：

1. **整行 0 的候选排第一**：`tsumo`/`ron` 是终局动作，引擎对它们直接 `return new int[8]`（全 0）——
   "能和就和"是这一行唯一的答案。⚠ 反过来也成立且**实测 214/214 成立**：真实候选不可能整行 0
   （听牌行 `wait_types ≥ 1`、未听牌行 `shanten ≥ 1`），所以这条不会误吞普通候选。
2. 本行最好向听 == 0（有候选听牌）⇒ 键 `(听牌枚数, 良形枚数, 听牌种数, 良形种数)`；

3. 键全平 ⇒ 取**最小下标**（= `legal` 顺序；`dataset` 在 build 期已硬校验两者逐条对齐）。
4. ⚠ `dora_count` **不参与**：宝牌是"打点"不是"牌效"，塞进平局判据会让这个标签的性质变掉。
5. ⚠ 只给 3 列（老的 `effect` 列）时听牌行**退化成下标序**（那 3 列里没有听牌形）⇒
   `pretrain` 用的是 `cand.derived` 的 **8 列**（实测这样才把听牌那 ~20% 的行也标对）。

   "只用 `effect`"的地方，理由与实测都在 §14.12.4。

**两个边界 bug 是单测抓出来的**（写进 `_lex_best` 的注释，别改回去）：① 不淘汰"已在前一个键上
输掉"的候选 ⇒ 字典序退化成"最后一个键说话"；② 取"第一个更大的候选"而不是"这一键的最大者" ⇒

**建议 1（对原计划的判决）：`--danger-weight` 不做，标签一列都不加。**

**建议 2（若还想要"稠密、反事实、低噪"的押し引き标签，换来源与换通道）：**

| 项 | 建议 |

四条容易写错、已写进纯函数单测的口径：

1. **和率/铳率的分母是「座位·小局」不是「场」**。生产者的 `win_rate = wins / seat_hands`（`SelfPlay.PolicyStat`），
   同一个人坐 4 个座位就是 4 个样本 —— 与"每场"口径差 11~12 倍，报告里必须点名。
2. **`和了巡目` 只认真正和了的那一家**。一次荣和会给多家发 `ron` 询问，被压过 / 见逃的那些**也记成了
   `chosen:"ron"`**（实测多 ≈1%），不筛就会把"没和"当成"和了"，覆盖率还会 >100%（实测 101.4%）。
3. **「取不到」与「真的是 0」必须显示不同**（`—` vs `0.00%`）。空分母一律走 `safe_div` 回 `0.0`，
   **不填 NaN**，但"整块轴缺席"（如没有决策行 ⇒ 行为轴）走 `None` ⇒ 表里画 `—`。
4. **庄家座次要自己派生**（2026-10-05 修正，§15.4 的旧数字因此作废）：`hand` 行的 `round` 子对象
   **只有** `bakaze / kyoku / honba / riichi_sticks`（PROTOCOL §8.4），**没有 `dealer`** —— 而
   `连庄率` 与**打点分档（亲 12000 / 子 8000）**都要它。旧实现直接读 `round.dealer` ⇒ 恒 `-1` ⇒
   两个症状：① `连庄率` 整列画 `—`；② **每一手都按子家阈值分档**（亲家的 12000 落"跳満"而不是
   "満貫"）⇒ `跳満率`/`倍満率`/`三倍満率`/`役満以上率` **整体虚高**、`満貫以上率` 虚高。
   修法：**报文里有 `dealer` 就以它为准**（引擎真值，权威），没有才按 `(kyoku − 1) % 4` 派生。
   判据 = `v4 profile --self-check` 的「庄家」两组（8 项）。

### 15.2 打点怎么"反推"（不改任何契约）

`hand` 行的**打点**没有直接给（`yaku`/`han`/`fu` 是从 2026-10 起才有的，见 §15.5），
但四家收支是精确的：

- 荣和：`delta[loser] = −(打点 + 300 × honba)` ⇒ `打点 = −delta[loser] − 300 × honba`；
- 自摸：`Σ_{非和了家} delta = −(打点合计 + 300 × honba)`（本场棒三家各 100，合计仍是 300）；
- **立直棒两边抵掉**（宣言 −1000、和了 +1000×n）⇒ 反解**不需要**知道桌上有几根棒。
  附带一条可断言的不变式：`Σ delta ≡ 0 (mod 1000)`（= `1000 × (本小局收棒数 − 本小局立直宣言数)`；
  实测的 `0-4-0` 那一手就是"三家听牌家各立直 −1000、各收 1000 罚符 ⇒ 净 0，只有不听那家付 3000"）。
- **分档按实际收到的点数**：子 満貫 8000 / 亲 12000，跳満 ×1.5、倍満 ×2、三倍満 ×3、役満 ×4
  ⇒ 切り上げ満貫与累计役満**自动落对档**，不需要知道番符。**亲/子这件事本身要派生**（见上面第 4 条）：

  > `dealer = (kyoku − 1) % 4`。依据三条：① **每个风位恰好 4 个小局**，引擎里
  > `kyoku = dealer + 1`（`Table.playGame` 非连庄时 `nd = (dealer+1) % 4`；`nd == 0` 换风且
  > `kyoku = 1`，否则 `kyoku = nd + 1`）⇒ 该式对**东/南/西任一风**都成立（南 1 的庄家仍是 0 号，
  > 不是"接着东 4 往后数"）；② **连庄不改 `kyoku`**（只 `honba += 1`）⇒ 同一个庄家连续几把都用
  > 同一个 `kyoku`，式子天然对连庄成立（所以 `honba` **不参与**这个式子）；③ 与 `v4/harness.py`
  > 的 `dealer_seat = (kyoku - 1) % 4` **同一把尺子**。`kyoku ∉ 1..4` ⇒ `-1`（未知，照旧画 `—`）。

#### 15.7.3 ✅ `profile` 的**逐场序列撞键**陷阱（本轮实测 → **2026-10-05 已修**）

**现象**：`per_game[i].seed` 是**墙 seed**，只由 `(seed_base, 场次下标)` 决定 —— 实测
`gate/p1-17g24/s20261020` 与 `gate/p1-10g01/s20261020` 的 `game0.seed` **完全相同**。
而 `PolicyStat.add_series` 是 `series[度量][seed] = 值`（**后写覆盖**）。
⇒ 一次 profile 传多个 run、且这些 run **共用同一批 seed**（正是"跨模型可比"的必要条件）时，
**现任的逐场序列被最后一个 run 覆盖**。

**为什么"数字看起来正常但事实错误"**：候选 X 的序列来自 run X，而现任的序列来自**最后一个 run**
—— 同一个墙 seed 上，现任当时面对的是**别的候选**（2+2 结构里另两席是谁），却被当成"对 X 的配对"。
红证（改前的调用，`rank_points` / `avg_win_score`）：

| 调用 | 17g24 的 `avg_win_score` | 17g24 的 `rank_points` |
| --- | --- | --- |
| 单 run（正确） | **+120.2 [−158.2, +399.8] 分不出** | −4.152 [−8.950, +0.682] 分不出 |
| 两 run `[17g24, 10g01]` | **+436.8 [+181.2, +691.1] 更好（假的）** | −8.067 [−11.439, −4.641] 更差（假的） |
| 两 run `[10g01, 17g24]`（对调） | +120.2 [−158.2, +399.8]（这次轮到 10g01 被污染） | −4.152 [−8.950, +0.682] |

⚠ **两边都会被污染**，只是幅度差得远：`avg_win_score` 只在"该家这一场真的和过牌"时才写
（`if a["wn"]`）⇒ 后一个 run 只覆盖它**写过的**那些 seed，其余 seed 留着前一个 run 的值。
实测 `[17g24, 10g01]` 里 10g01 的 `avg_win_score` = **−1033.0**（它自己的真值是
**−1036.9 [−1291.4, −788.2]**）；而 17g24 那边被整片覆盖 ⇒ 偏差高达 **+316 点/和了**
（+436.8 vs +120.2）。所以判据不能是"看哪个数离谱"——**只有"单 run == 混跑逐位相同"** 才抓得住。

**后果（本轮实际发生）**：全 15 tag 一次跑的配对表里，**唯一一个显著为正的格子（`14g05` 的打点
`+327.0 [+55.1,+602.4]`）被抹成 `+65.7 [−193.0,+329.1] 分不出`** ⇒ 会**凭工具 bug 丢掉本轮唯一的专家**。

**修法（选了"修键 + 明确配对域"，**不是**硬报错）**：

1. **逐场序列的键 = `(墙 seed, run 序号)`**（`PolicyStat.add_series`）——
   `eval.paired_test` 取的是 `set(a) & set(b)` ⇒ **配对天然只在同一个 run 内成立**
   （该 run 里 X 与现任同场同墙），跨 run 不会配成对；
   ⚠ **偏移放第二格不是笔误**：`paired_test` 按 `sorted(交集)` 取样本，而自助法把**固定 RNG 流**
   按数组顺序映射 ⇒ 顺序一变 CI 就在第三位小数上抖。seed 在前 ⇒ 单 run 的顺序与改前逐位相同
   ⇒ **改前已发布的单 run 读数逐位复现**（这正是"改后（单 run）== 改前（单 run）"这条判据的前提）。
2. **跨 run 的合并没有新写一份统计**：这就是 `gate.pooled_diffs` 那套"**加键偏移 + 池化**"的同一个
   构造（偏移落在元组第二格），CI/p 仍旧出自 `eval.paired_test`（经 `arena.judge_pair`）。
   ⛔ 本模块**不做**跨 `--run` 的台面合并 —— 要判决请走 `v4.gate`（它按 `--seed` 逐套墙算 + 池化）。
3. **`--incumbent` 表加了 `run` 列**（`r0-7` / `r8-15` 这种压缩写法）+ 表尾一行
   "配对用到 N 个 run"，序号 → 目录见开头那张 `[rN]` 表 ⇒ **"这次配对用了哪几个 run"一眼可见**
   （否则"跑 16 个 run、实际只有 8 个进了这一行"看不出来）。
4. **"牌山一致性"改成正确的判据**（原来那条是**假警报**）：`gate/<tag>` 展开成 8 个 `s<seed>/`
   子 run，**每个子 run 的 seed 集合天然不同** ⇒ 旧判据（`all(set(rd.seeds) == 首个 run)`) 在 gate
   场景下**恒报"不可比"**。现在逐 run 问"**同一个 run 内部**各策略打的是不是同一批墙 seed"
   （`check_walls`），并顺手点名两类真问题：某策略**少打了几副墙**、某场**没有 4 个策略标签**
   （后者会被 `reduce_run` 的 `len(labels) != 4: continue` **静默丢掉**）。

**修后红证**（`zfix-*` = 用同一批 8 套墙重采的 17g24/10g01，`wall_deltas` 与当年
`gate/p1-*` **逐位相同** ⇒ 复现是可信的）：

| 调用 | 17g24 `avg_win_score` | 17g24 `rank_points` | 17g24 `run` 列 |

| 单 run | +120.232 [−158.217, +399.766] p=0.648 n=479 | −4.152 [−8.950, +0.682] | `r0-7` |
| 混跑 `[17g24, 10g01]` | **逐位相同** | **逐位相同** | `r0-7` |

⇒ 10g01 那两行同样与它自己的单 run 逐位相同（**两边都不再被污染**）。
**全 15 tag 一次跑**（`p1-*`，这些 run 只剩 `summary.json` ⇒ 只能看 `rank_points`）：

## 16. 阶段 4 可行性判定：**理想抉择器（oracle chooser）的收益上界**（2026-10-06）

### 16.2 口径（先说清楚，再报数）

- **桶（触发条件）**：正在行动的那个座位看到什么 —— 由该座位**逐条决策的 `obs`** 决定：
  巡目（1-6 / 7-12 / 13+）× 他家立直数（0 / 1 / 2+）× 自家向听（0 / 1 / 2 / ≥3，取 sidecar
  `danger[:, 68]`）× 自家是否已立直。**只用现成公开字段，不新造**。
- ⚠ **不能取"该座位的第一条决策"当桶**：实测那一条**恒是本局第一次摸牌**（`player_draws=1`）
  ⇒ 桶退化成 1~2 格。改成**决策级加权**：一手牌里该座位落进桶 `b` 的决策占比 `w_{h,b}`
  （`Σ_b w_{h,b} = 1`），该小局的结果按比例摊给桶。
- ⛔ **口径必须对称**：四位专家**各按自己面对的局面**分桶、只统计**自己**的收支，再减 `g08` 在
  同一桶里的均值。⛔ **不能**按"`g08` 座位的状态"分桶再做同局配对差分 —— 那有**系统性偏差**
  （`Σ_seat delta ≡ 0` ⇒ 按基线自己的状态分桶会让另外三家机械虚高），实测给出 `+7.9 顺位点/场`
  这种荒谬上界。推导与红证见 `NOTES.md` §6.5 第六十七轮。
- **聚类**：同场多小局不当独立样本 ⇒ 先按场求桶内加权均值，再**按场配对** `e vs g08`，
  统计量全部复用 `mahjong_ml.eval.paired_test` / `random_effects`（本模块**不另写统计**）。
- **顺位点换算**：`rank_points = (终局点数 − 30000)/1000 + 馬点[50,10,−10,−30]` ——
  工具在**4,000 场的每一条 `per_game` 上逐行验证**这个式子（**最大残差 0.00e+00**）。
  收益分两条通道：**分数通道**（`Δscore/1000`，恒等式，精确）与**顺位通道**
  （点数平移后与另外三家的实测终局点数**重新排位**算馬点 —— 反事实）。
- **桶与样本量**：45 个原始格 → **凝聚式合并**（把稀格并进同族最大的桶，判据是**合并后实测**
  的桶大小）⇒ **22 个桶**（全部 4 特征）。每桶·每专家的决策加权手数
  `min 438 / p25 627 / 中位 913 / max 10,159`；每桶决策数 `16,568 ~ 566,413`。
  整手丢弃只有 **4 手**（判据对称：四位里只要有一位在该小局没有决策就整手丢）。

### 16.3 判据 ①②：oracle 上界（两个口径）

| 口径 | 点/小局 | **顺位点/场（只分数通道）** |
| --- | --- | --- |
| **样本内上界**（`max_e` 用全部数据选，**已知会高估**） | +68.5 | **+0.780** |
| **诚实① 留一牌山**（专家由其余 7 套选，在第 8 套评估） | +28.7 | **+0.327** |
| 诚实① 的逐套读数 | −39.7 / +117.4 / +54.1 / +81.0 / −5.7 / −94.7 / +40.5 / +76.9 | 极差 **212 点/小局** |
| **诚实② CI 规则**（只在该桶 CI 排除 0 且跨牌山一致时才切换） | +13.3 | **+0.151** |

含**顺位通道**的反事实读数（同一次留一）：`+0.755 顺位点/场`，但**牌山随机效应 CI [−0.249, +1.735] 跨 0**；
只走分数通道时 `+0.355`，RE CI [−0.183, +0.892]，**同样跨 0**。
⚠ **顺位通道基本是反事实的噪声偏差**：同一套反事实把逐场 Δ 在**同套牌山内打乱**（安慰剂）
得到 **+0.750** —— 与"含顺位通道"的 `+0.755` 几乎一样。⇒ **顺位点结论一律以分数通道为准。**

### 16.4 判据 ③：负向对照（**这条决定结论**）

把四位专家的标签**在桶内随机置换**，跑 **K=20** 次量出**零分布**（不是只跑一次看它是否"≈0"）：

| 置换口径 | 留一 点/小局 均值 ± sd | 最大 | 顺位点/场 均值 ± sd | 最大 | CI 规则误判桶数（均 / 最大） |
| --- | --- | --- | --- | --- | --- |
| `bucket_wall`（每个 (桶, 牌山) 一个置换） | −2.8 ± **64.3** | +111.1 | −0.068 ± **1.513** | +2.854 | 1.6 / 5 |
| `bucket_hand`（每手一个置换，最严） | +1.5 ± **41.6** | +102.4 | +0.098 ± **1.008** | +2.422 | 0.6 / 5 |
| **真实数据** | **+28.7** | — | +0.755 | — | **1** |

⇒ **真实读数相对 `bucket_hand` 零分布 z = +0.65**（零分布最大 +102.4）；
顺位点 z = +0.65（零分布最大 +2.422）。**都没有超出纯置换噪声。**
⇒ CI 规则的"1 个可切换桶"对比**纯噪声下平均 0.6 个（最多 5 个）** ⇒ 那份清单**基本是假阳**。

### 16.5 判据 ②：可切换桶清单

22 个桶里只有 **1 个**通过（牌山 RE CI 排除 0 且为正 + 跨牌山 7/8 一致）：

| 桶 | 专家 | 点/小局 | 占局面 | 顺位点/场 | 跨牌山 | p | 牌山 RE CI |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 巡7-12 / 他家立直0 / 向听0 / 未立直 | atk2 | +630.5 | 2.1% | +0.151 | 7/8 | <0.0001 | [+314.3, +917.5] |

⚠ **但这一个落在噪声的假阳率之内**（§16.4：纯置换下平均就有 0.6 个、最多 5 个）
⇒ **不能当成门控的学习目标**。

### 16.6 决定性的那一项：**门控本身**值多少

把"按桶切换"和"干脆只选一位全局最强的专家、所有局面都用它"放在**同一把尺子**上（都用留一）：

| 策略 | 留一 点/小局 | 顺位点/场 |
| --- | --- | --- |
| 不门控 · 只选一位全局最强（**`atk2`**） | **+43.3** | **+0.493** |
| 按桶切换（oracle chooser） | +28.7 | +0.327 |
| **门控本身的增量** | **−14.6** | **−0.166** |

⇒ **"按局面切换风格专家"在诚实口径下比"只挑一位全局最强的专家"还差 0.166 顺位点/场。**
即：这份收益**根本不需要门控**，而且门控还在往里加噪声。
（22 个桶 × 3 位专家 = 66 次选择：选出来的东西没有跨牌山稳定性，于是留一评估时被扣回去。）

**稳健性：换一套桶方案，结论不变**（桶粒度是被测者自己的选择，必须验证结论不是它挑出来的）：

| 桶方案 | 桶数 | 样本内上界 | 诚实① 留一 | **门控本身** | CI 规则桶数 |
| --- | --- | --- | --- | --- | --- |
| 主口径（每桶·每专家 ≥400 手，≤60 桶） | 22 | +0.780 | **+0.327** | **−0.166** | 1 |
| 粗（`--max-buckets 12`） | 12 | +0.640 | **+0.361** | **−0.053** | 0 |
| 细（`--min-per-expert 800 --max-buckets 40`） | 15 | +0.674 | **+0.261** | **−0.205** | 1 |

⇒ 三种粒度下诚实上界都在 **+0.26 ~ +0.36**、门控增量**全为负**、可切换桶 **0~1 个**。

### 16.7 结论（逐条对着 §16 开头的判据）

1. **oracle 上界（诚实口径）= +0.327 顺位点/场**（分数通道；含顺位通道 +0.755，但安慰剂显示
   那部分基本是反事实噪声）；**样本内上界 = +0.780 顺位点/场**（已知高估）。
   ⇒ 两个口径都**落在"< ~0.5 ⇒ 门控不值得训"**那一侧；样本内那个也没到 1.5。
2. **可切换桶清单**：22 个桶里 1 个（占局面 **2.1%**、**+0.151 顺位点/场**）——
   且与纯噪声的假阳率同量级 ⇒ **拿不出可用的门控学习目标**。
3. **负向对照**：真实读数 z=+0.65（零分布 sd = 41.6 点/小局 = **0.47 顺位点/场**）
   ⇒ 这套估计量的**噪声底本身就有 ~0.47 顺位点/场**，而样本内上界只有 0.78。
4. **门控本身 = −0.166 顺位点/场**（比只选一位全局最强还差）。
5. ⇒ **阶段 4 判定：门控不值得训。多风格路线按判据正式收口。**
   ⚠ 补充一条同样重要的读数：**"只换一位专家（不门控）"也没什么可拿** ——
   最强的 `atk2` 也只有 **+0.163 [−1.357, +1.502]**（8 套配对，胜 4 负 4）。
   ⇒ 多专家架构的**两条路（择优 / 抉择）在这批专家上都没有收益**；要走的不是"怎么选"，
   而是"先把专家练到**显著更强**"（`NOTES.md` §6.5 第六十六轮第 2 条的"买分辨率"已被否决，
   所以那条路要先解决"尺子看不见"）。
