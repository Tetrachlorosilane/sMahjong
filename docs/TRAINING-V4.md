## 1. 目标与非目标

### 1.1 目标（按优先级）

| # | 目标 | 可判据的表述 |
| --- | --- | --- |
| **G1** | **强于内置 teacher** | 2+2 同牌山配对（相邻 + 对家两种座位配置）vs `teacher`：**Δ ≥ +2 顺位点且 95% CI 排除 0**；阶梯 θ−teacher 的 CI 同样排除 0；对 `first`/`random` 不退 |
| **G2** | **信息平价**：人类能看到的全都有，看不到的全都没有 | `docs/FEATURES-V4.md` §1 的两张清单，逐项有自动化判据（§9 判据①②） |
| **G3** | **每块信息的价值可证** | 消融矩阵：逐块关掉，同种子配对 CI 说出"这块值多少"（§8.3） |
| **G4** | **能上线**：纯 Java 手写前向、增量推理、单决策 ≤ 2 ms 特征 + ≤ 1.5 ms 网络 | `FEATURES-V4.md` §8 的预算表 + 基准脚本 |
| **G5** | **可复现**：同种子产物逐字节相同；增量 == 全量重算 | §8.6 的两条硬闸门 |
| **G6** | **训练期封闭 + 场外均衡**（防"框外过拟合"） | 规范 §1.4 三条红证全绿（标签不进输入 / 隐藏量不进 obs / 奖励不含过程隐藏量）；每轮 `balance.json` 无超阈，**超阈轮次不得进判据**（§7.4、§7.5） |

### 1.2 非目标（明确不做，免得跑偏）

- ❌ **不追求"输入与 teacher 同口径"**。v3 的立直宣言巡目、牌河顺序、副露来源都是**刻意**不做的
  （`NOTES.md` §6.5 审计条目③），v4 全部要做 —— 代价是换标签源（§2.2）。
- ❌ **不做搜索**（MCTS/CFR 类）当主方法：Java 侧要纯手写前向，搜索会让自对弈慢一个量级。
  搜索**最多**当离线标签源（`docs/TRAINING.md` §10 的第 2 条未决问题）。
- ❌ **不引入新的第三方 ML 依赖到服务端**（Maven/ONNX/PyTorch 一律不进 `server/`）。
- ❌ **不改规则引擎的判定逻辑**：v4 只动"观测 → 输入"与"训练侧"，`Round`/`Evaluator` 的行为不变。

### 1.3 保留的硬限制（不可协商）

| 项 | 上限 | 出处 |
| --- | --- | --- |
| 参数量 | ≤ 3 M（目标 1.0–1.5 M） | `docs/TRAINING.md` §3.3 |
| GPU | ≤ 80% 占用、≤ 4.5 GB 显存 | `docs/TRAINING.md` §0.1.3 |
| CPU | ≤ 24 workers | `docs/TRAINING.md` §0.1.2 |
| 数据根 | `S:\mahjong-training`，总配额 200 GB、分项配额、自动回收 | `docs/TRAINING.md` §0.1.1 |
| 一处决策漏斗 | 仍然只有 `Table.decideBot(seat, Decision)` | `AGENTS.md` §6.5 |
| 反作弊 | 训练侧只实现 `ActionPolicy`（拿不到 `Round`） | `AGENTS.md` §6.5 |

## 2. 为什么重做（不是"想更 fancy"）

### 2.1 v3 的三条硬伤（实测，见 `FEATURES-V4.md` §2）

牌河只剩按牌种计数（顺序、摸切手切、立直宣言张全丢）；副露只剩种类/牌种计数（`from`/被鸣那张/巡数全丢）；
立直只剩一个布尔（宣言张与宣言巡数没有）。**这不是"精度不够"，是"信息不对称"**：
人类玩家在牌桌上能看见的时序与来源，网络一样也看不见。

### 2.2 "口径分裂"的根因：把 teacher 同时当标签源与信息上界

v3 当年拒绝加"立直宣言巡目"，理由是"补了会造出**特征比老师更聪明**的口径分裂，反而让标签对不上"。
这个担心**是对的**，但根因不在特征，而在**把 teacher 当成了唯一标签源**：

```
v3：输入信息 ≈ teacher 的视野    标签 = teacher 的动作   ⇒ 一旦输入更全，动作标签就不再是"最优"
v4：输入信息 = 人类玩家的视野    标签 = 引擎真值 + 自对弈结果 ⇒ 输入再全也不会与标签冲突
```

自对弈时**引擎是上帝视角**（它知道所有人的手牌、牌山、结局），所以"向听/进张/听牌/对手手牌/放铳/终局得分"
这些**都可以是标签**（`FEATURES-V4.md` §5.2），而它们恰好是 teacher 只能靠启发式猜的东西。

### 2.3 现状证据（为什么不能靠"再滚几代"）

| 事实 | 数值 | 出处 |
| --- | --- | --- |
| 三代自对抗续训合计增益 | **Δ = +0.01 顺位点 [−0.99, +1.02]，n=10,400** | 本会话实测（release v1.11.0 说明） |
| 步长不是瓶颈 | 满轮 6.0M 行时 `KL` 在 epoch 2 撞 0.03 墙，**仍无增益** | 同上 |
| 只有一代的 2+2 CI 排除 0 | `g05` **+2.66 [+0.14, +5.18] p=0.068**（边缘） | `docs/TRAINING.md` §4 P4 |
| 价值头变好 ≠ 变强 | val MAE 5.39 → 5.08 → 5.05，强度不动 | 同上 |

⇒ "每代只挪 2–3% 决策"这条路已到平台；**换表示**（而不是加算力/调步长）是唯一还没试过的轴。

## 3. 设计思路总览

```
                    ┌──────────── obs v3（人类可见的全部）────────────┐
                    │ tile[34,48]   evt[60,96]   ctx[64]   cand[n,128] │
                    └───────┬───────────┬──────────┬──────────┬───────┘
                            │           │          │          │
                     逐牌种编码器   事件流编码器   上下文MLP   候选编码器
                     (共享MLP)     (GRU+小Transformer)         (MLP)
                            │           │          │          │
                            └──► 双向状态-增量管理（state ⇄ delta，两轮）◄──┘
                                        │
                                  d_model = 192 的融合表示
                                        │
        ┌───────────┬───────────┬───────┴────┬───────────┬──────────┐
     策略头       价值头       顺位头      信念头      危险头      牌效头
   (候选打分)  (分布价值)   (1..4)   (对手手牌/听牌) (放铳概率)  (向听/进张)
                                        │
                            运行期只用：策略头（+ 可选 信念/危险 做风险敏感）
```

三条设计主线（对应你点名的三项技术）：

| 主线 | 解决什么 | 一句话实现 |
| --- | --- | --- |
| **关键张注意力** | 候选动作与"哪些牌/哪些事件与它有关"的**动态关联**（筋、壁、现物、宝牌、他家牌河的一段） | 候选向量当 **query**，34 个牌种 token + 最近 K 条事件 token 当 **key/value**，多头交叉注意力 |
| **增量缓存 + 循环推理** | v3 每次决策重算一切；实际状态只变了 1–2 个牌种 | `tile` 行增量更新；`evt` 只追加；隐状态 `h_t = GRU(h_{t-1}, 新事件)` ⇒ 每决策 O(新增) 而不是 O(全局) |
| **状态与增量双向管理** | 只给"当前快照"会丢历史，只给"事件流"会丢聚合（剩几张、谁立直了） | 状态塔与增量塔**互相调制**两轮：delta→state 门控写回；state→delta FiLM 偏置 |

## 4. 输入框架的类设计（可组合、可消融、三端镜像）

目标：**加一个信息块 = 写一个类 + 注册**，不要动主干；且"关掉一个块"是配置而不是改代码
（规范 §7 的消融 id 就是这么来的）。

```python
# python/mahjong_ml/v4/spec.py —— 唯一注册表（块 id / 宽度 / 顺序 / 版本）
@dataclass(frozen=True)
class Block:
    bid: str            # "tile.per_opp" 之类，消融开关用的就是这个
    width: int          # 该块在所属张量里的通道数
    requires_obs: tuple[str, ...]   # 依赖的 obs 字段（缺字段=报错，不填 0）
    derived_version: int | None      # 需要 sidecar 的哪个版本

class BlockRegistry:
    def tensor_of(self, bid) -> str: ...      # 这个块属于 tile/evt/ctx/cand 哪个张量
    def assemble(self, obs, sidecar, *, ablate=()) -> Tensors: ...
    def fingerprint(self) -> str: ...          # 块清单指纹 → 写进 net.bin（格式 2）

# 编码器 / 融合 / 头 都是可替换组件
class Encoder(Protocol):    def __call__(self, x) -> Tensor: ...
class Fusion(Protocol):     def __call__(self, state, delta, cand) -> Tensor: ...
class Head(Protocol):
    name: str; loss_weight: float
    def __call__(self, fused) -> Tensor: ...
```

- **组合**：`Model(spec, encoders, fusion, heads)`；换塔/换融合/加头都不改主干。
- **镜像**：Java 侧 `server/.../ai/v4/` 与 C++ 侧 `trainer/src/v4/` 各有一份**同 id 同宽**的实现，
  靠 `FEATURES-V4.md` §9 判据③（四个张量逐元素）钉住。
- **价值**：① 消融矩阵（G3）变成配置而非分支代码；② 三端一致有单一事实来源（规范 + 注册表）；
  ③ 未来 v5 只改注册表与编码器，不动训练编排。

## 5. 网络架构

### 5.1 塔（宽度 / 深度）

| 塔 | 输入 | 结构 | 输出 | 参数量 |
| --- | --- | --- | --- | --- |
| **Tile 塔** | `[34,48]` | 共享 MLP `48→64→64`（逐牌种，权重共享） + 2 层自注意力（4 头，d=64） | `[34,64]` tokens + 池化向量 `[192]` | ~120 k |
| **Event 塔** | `[60,96]` | MLP `96→192` + 类型/副露嵌入 + 巡目正弦位置编码 + **GRU(192)** + 2 层 Transformer（4 头） | 最近窗口 token `[60,192]` + 循环状态 `h[192]` | ~520 k |
| **Ctx 塔** | `[64]` | MLP `64→192→192` | `[192]` | ~50 k |
| **Cand 塔** | `[n,128]` | MLP `128→192→192` | `[n,192]` queries | ~90 k |
| **融合** | 三塔输出 | 见 §5.2（两轮双向 + 关键张注意力） | `[n,192]` | ~300 k |
| **头** | `[n,192]` / `[192]` | 见 §6 | 见 §6 | ~400 k |
| **合计** | | | | **≈1.5 M**（上限 3 M） |

深度取舍：**浅而宽**（每塔 ≤2 层注意力，d=192）。理由：Java 要手写前向且单决策有 1.5 ms 预算；
34×48 的输入没有"深"的必要，**信息与时序**才是瓶颈。

### 5.2 关键张注意力 + 状态/增量双向管理

```
# ① 候选 → 牌种（关键张注意力）：候选自己的那张、其筋牌、宝牌、他家牌河里的同牌种
q  = W_q · cand[i]                         # [192]
kv = TileTokens                            # [34, 64]
a  = softmax(q·W_k(kv)^T / √d + bias(bid)) # bias 可学：同牌种/同筋/宝牌位给先验偏置
u_tile = a · W_v(kv)

# ② 候选 → 事件（近因注意力）：最近 K 条事件里与这个候选相关的
u_evt = MHA(q, EventTokens, EventTokens + turn_pos)

# ③ 双向：delta → state（门控写回） 与 state → delta（FiLM 偏置）
g      = sigmoid(W_g · [u_evt, u_tile])       # 该候选"值得看历史"的程度
state' = state + g ⊙ W_s(u_evt)               # delta 写回状态（第 1 轮）
evt'   = evt ⊙ (1 + γ·tanh(W_f(state')))      # 状态调制历史（第 2 轮，FiLM）
u      = [u_tile, u_evt', u_ctx] → MLP → [192] （再与 state' 拼接）
```

- **为什么两轮而不是一次拼接**：状态与增量是**互相定义**的（"他立直了"是状态，"哪张是宣言牌"是增量；
  反过来"这张是现物"要同时看牌河计数与那段事件）。两轮是"互信息来回"的最小实现。
- **位置编码只用相对量**：事件 token 用"距当前决策几巡/几条"的正弦编码 + 相对方位偏置；
  **不做绝对座位编码**（沿用 v3 的"旋转到自己为 0"的纪律）。
- **参数量小、算子全在白名单里**（`FEATURES-V4.md` §8），Java 手写可行。

### 5.3 增量缓存与循环推理（性能与正确性）

**两级缓存**（Java/C++/Python 三端同语义）：

| 级 | 缓存什么 | 何时失效 |
| --- | --- | --- |
| L1 张量级 | `tile[34,48]` 的行（只改变化的牌种）+ `ctx` 的派生部分 | 舍牌 → 1 行 + 四家计数器；鸣牌 → 1–2 行 + `meld_count`；**杠/翻宝牌 → 相关行 + `dora_indicator` 行**；立直 → 立直家全部行的 `river_before/after` 分区 |
| L2 表示级 | Tile 塔 token `[34,64]`（逐行可缓存）、Event 塔隐状态 `h`（只吃新事件）、Ctx 向量 | 事件追加 → 只算新 token 并推进 `h`；**跨局 reset**（`h` 不跨小局，除非显式开启"跨局 carry"做实验） |

- **循环推理**：`h_t = GRUCell(h_{t-1}, 新事件 tokens)` ⇒ 每决策 O(新增事件数)，与"这一局已经打了多久"无关。
- ⚠ **可复现性冲突**：状态化会破坏"同种子同轨迹"（`AGENTS.md` §6.5 的硬要求）。
  三条纪律：① 隐状态**每小局开头清零**且**每局一份策略实例**（沿用 `PolicyFactory`）；
  ② 任何缓存都必须能从**当前决策的 obs + h** 完整重建（判据④）；
  ③ 提供 `--no-cache`/`--stateless` 开关，自检与对拍**永远用无缓存路径**做基准。
- ⚠ **最危险的失败模式是"缓存陈旧但结果看起来正常"**：所以唯一判据是
  `增量 == 全量重算`（逐元素 ≤1e-5，覆盖舍牌/鸣牌/杠/翻宝/立直/流局/连庄七类事件）。

### 5.4 与"搜索"的边界

暂不做搜索。如果 P4 之后还需要推力，优先试：**把价值头当搜索的叶子评估**（只在小规模、离线标签生成上），
而不是线上搜索 —— 线上搜索会让自对弈慢一个量级（`docs/TRAINING.md` §10）。

## 6. 多头体系

| 头 | 形状 | 监督来源（**全部来自引擎/自对弈，不来自 teacher**） | 损失 | 权重（退火） | 推理期 |
| --- | --- | --- | --- | --- | --- |
| **策略头** | `[n]` logits（掩码 softmax） | PPO 的优势（自对弈回报） | PPO-Clip（λ=1、优势只在学生行归一化） | 1.0 | ✅ **主力** |
| **分布价值头** | `[51]` 分箱（HL-Gauss，范围 ±30k 点） | 本局 `final_scores − 起点` | 交叉熵（分布） | 0.5 → 0.25 | ✅（critic / 风险敏感决策） |
| **顺位头** | `[4]` logits | 本场终局 `placement` | 交叉熵 | 0.3 | 可选（终局取舍） |
| **信念头：对手手牌** | `[3,34]` 概率 | 自对弈真值 `opp_hand[3][34]` | 交叉熵（逐家、逐牌种） | 0.2 → 0.05 | ❌（**训练信号/诊断**） |
| **信念头：对手听牌** | `[3]` | 真值 `opp_tenpai[3]` | BCE | 0.2 | ✅（押し引き输入） |
| **危险头（放铳概率）** | `[n,4]`（候选 × 打到谁手上） | 自对弈结果 `opp_dealin[3]` + 他家听牌真值 | BCE | 0.3 | ✅（与信念头一起驱动押し引き） |
| **牌效头** | `[n,3]`：打后向听 / 进张枚数 / 听牌形 | `HandEval.afterDiscard`（引擎，**免费**） | 回归/分类 | 0.3 → 0.1 | ❌ |
| **听牌头（自家）** | `[1]` | 引擎真值 | BCE | 0.1 | ❌ |
| **teacher 模仿头** | `[n]` logits | **仅在 P2 冷启动期**用 teacher 动作 | 交叉熵 | 0.3 → **0**（20k 步退火到 0） | ❌ 退火后删除 |

设计判据：

1. **只有策略头与价值头是"上线必需"**；其余是训练信号或可选诊断 —— 保证推理路径短（判据：删掉非必需头后
   `net.bin` 仍能加载并打牌）。
2. **teacher 只出现在一个可退火到 0 的头**里。这是"teacher 只做初始收敛"的实现方式：
   P2 之后它自动消失，不存在"偷偷以老师为上界"的通道。
3. **belief/danger 头是"用公开信息预测隐藏信息"**，训练用真值（自对弈）、推理只用公开输入 ——
   与作弊面的分界线写在 `FEATURES-V4.md` §1.2。
4. **价值头改成分布**（不是标量 MSE）：v3 的价值头 MAE 一路变好而强度不动，一部分原因是标量均值
   丢掉了尾部风险；顺位点/押し引き恰恰关心尾部。指标见 §8.4。

## 7. 训练工作流（尽量复用既有编排）

### 7.1 数据管线（三套文件，物理分离）

```
raw/<label>/g*.jsonl        obs v3 + 动作（协议）        ← 采集（C++ 生产者，候选 3× 吞吐）
raw/<label>/g*.feat.bin     输入派生 sidecar v3（§5.1）   ← --features（引擎算）
raw/<label>/g*.aux.npz      标签（§5.2，训练专用）        ← --selfplay **--aux**（Java 生产者；C++ 显式报错）
compact/<label>/            紧凑数组（tile/evt/ctx/cand + 标签列）
```

- `dataset build` 增 `--aux`（把 `aux.npz` 并成标签列）；**推理路径只读 `feat.bin`**（判据⑥）。
  ✅ 已落地（2026-09-27）：`python -m mahjong_ml.dataset build <dir> <out> --aux` → 6 个 `aux_*` 列；
  缺 `g*.aux.npz` **报错**（不填 0）；`python -m mahjong_ml.auxlabels check <dir>` 逐文件核对版本/行数/obs 版本。
- 复用：`budget.py`（时间预算/缓存档闸门）、`paths.py`（配额 + 自动回收）、`producer.py`（java/cpp 切换）。

### 7.3 对手池与联赛

- **对手**：历史快照（滑动窗口）+ teacher + 脚本基线（`first`/`random`/`pass`）+ **v3 的最强代**（作为"旧世代基准"）。
- **联赛**：沿用 Plackett-Luce Elo + "谁克我就多跟它打"的加权采样（`league.py`）；
  防循环相克：对手池里永远保留 teacher 与脚本基线（它们是"锚"，不会随种群漂移）。
- ⚠ **采集那桌的顺位点/收支不是判据**（只有学生在探索采样）—— 这条口径沿用 `NOTES.md` §6.5。

### 7.4 自对弈期的封闭性（硬约束）

**一句话**：自对弈时引擎是上帝视角，但**上帝视角只许写标签，不许进输入，也不许进奖励**。

| 判据 | 具体做法 | 防的是什么 |
| --- | --- | --- |
| **输入只来自 obs** | 前向只吃 obs v3 的四个张量；训练侧只实现 `ActionPolicy`（拿不到 `Round`） | 上帝视角一进输入，"封闭"就只剩口号 |
| **标签与输入物理分离** | `feat.bin`（输入派生）/ `aux.npz`（隐藏真值标签）两套文件、两套列名 | 防"顺手带进去"（规范 §1.4） |
| **红证①：撤标签，输出不变** | 删掉 `aux.npz` 后重新前向，**logits 逐位不变** | 证明标签真的没进输入（比读代码强） |
| **红证②：obs 不含隐藏量** | 改 `Round` 隐藏量（别家手牌/牌山/里宝）后同一座位 `Observation.toJson()` **逐字节相同**；塞一个隐藏字段进 obs 必须让测试**红** | "以为没进、其实进了"（v2→v3 的 `kuitan` 恒 0 是同类静默） |
| **红证③：没有框外中间量奖励** | 奖励/优势只由**对局结果**（`hand_delta` / `placement` / 放铳事件本身）构成；⛔ 不用"对手是否听牌""牌山下一张"这类**过程隐藏量** | 用框外中间量做奖励 = 让模型学推理时拿不到的信号 |
| **辅助头不回喂** | 信念/危险/牌效头输出**只进损失**；推理时可整块删除 | 防"自己预测自己吃"的循环泄漏 |
| **对手族分层** | 信念/危险头必须在**训练池之外的族**（teacher / 脚本基线 / 未参训历史代）上单独报指标 | 自对弈的隐藏结构来自"自己的旧版本"⇒ 同族内评测会高估 |

**"框外过拟合"的三种形态**（三条都要防，缺一条就会静默发生）：

1. **输入泄漏** —— 隐藏量以任何形式进了输入（红证①②）；
2. **奖励泄漏** —— 用过程隐藏量塑造奖励/优势（红证③）；
3. **分布捷径** —— 训练数据的隐藏结构有偏（对手永远是自己上一代、座位/亲家/局不均衡）⇒
   模型学出评测里不成立的伪相关（§7.5 + §8.2 的族间报告）。

### 7.5 场外分配必须平均（硬约束）

**定义**：**场外因素** = 不进 obs、但会改变样本分布的一切。它们**必须分层均衡**，
不能"随机了就算公平" —— 随机只在期望上平衡，小样本下会留下系统偏差，而**偏差会被模型学成伪特征**
（例如"我坐庄时才遇到这个对手"⇒ 把对手与庄家绑在一起）。

| 场外因素 | 均衡要求 | 判据 |
| --- | --- | --- |
| 座位（4 席） | 每策略每座位**各 1/4 场次**（`--rotate`，既有） | 逐策略逐座位计数，偏差 ≤ 1% |
| 学生占席形态（2 席时） | "相邻"与"对家"两种形态**各半** | 两形态场次相等 |
| 亲家（庄家） | 每策略坐庄次数相等（连庄也按场平均） | 逐策略庄家次数偏差 ≤ 1% |
| 场风·局·本场 | 所有样本来自同一套半庄结构（東1→南4），不挑局 | 逐局场次分布偏差 ≤ 1% |
| 对手身份 | 显式 `--opponents` 时各对手总场次相等；联赛采样时**每对手总配额受控** | 对手场次 CV ≤ 5% |
| 对手 × 座位 | 每个对手在 4 个座位上的分布同样平均 | 交叉表偏差 ≤ 1% |
| 牌山种子 | 配对实验两臂**同一副牌山**；不同臂/不同消融**同 seed 基** | seed 集合逐场一致 |
| 起始点数 / 供託 | 固定 25000 / 0（做变起点实验时必须分层平均） | 起始值直方图 |
| 训练/验证切分 | **按整场**切分（既有）**且按对手族分层**（各族占比一致） | 分层比例差 ≤ 1% |
| 小局结局类型 | 不控（规则决定），但**必须报告** train/val 分布（流局/自摸/荣和/被飞） | 分布表 + 差异告警 |

**用法（判据，不是报告）**：

- 每轮采集完输出**均衡报告** `league/<label>/balance.json`：逐因素计数表 + 最大偏差 + 卡方 p；
- **超阈即失效**：座位/亲家/局这类离散因素偏差 > 1%、对手配额 CV > 5% ⇒ 该轮**不得用于判据**
  （可以当训练数据，但要记录在案），先修采样再重跑；
- **消融矩阵（§8.3）与 2+2 配对（§8.1）必须在均衡场次上做**，否则差异可能来自分配不均；
- `selfcheck.py` 钉住实现：喂一批**故意不均衡**的合成计数，必须报警（负向对照）。

⚠ 这条不是形式主义：`NOTES.md` §6.5 已实测过同类坑 —— `g05` 的 2+2 单跑"相邻"是 +1.10、
单跑"对家"是 +4.23，合计才 +2.66。**只看一种座位关系就会把未采样偏差读成强度**；
"场外分配平均"就是把那次教训推广到**所有**场外因素。

## 8. 评价体系（重新设计）

### 8.1 三层判据

| 层 | 协议 | 判什么 | 阈值/样本量 |
| --- | --- | --- | --- |
| **L-主** | **2+2 同牌山配对**（`A,A,B,B` 与 `A,B,A,B` 两种座位配置，不同 seed 基，合并一个总 Δ），指标 = **顺位点** | **G1（强于 teacher）** | 预注册：**Δ ≥ +2 顺位点且 CI 排除 0**；`sd(Δ)≈53` ⇒ **≈5,200 场/臂**（80% 功效，`eval.required_n`） |
| **L-阶** | Elo 阶梯（Plackett-Luce，一次联合拟合 10+ 策略，含 `first`/`random`） | 种群趋势、是否退化（对脚本基线不掉） | 每代 1200 场；θ−teacher CI 排除 0；**CI 含 0 一律写"证不出差别"** |
| **L-证** | **消融矩阵**（逐块关掉，同种子配对） | G3：每块信息值多少 | 每块 2000 场（同一批牌山）⇒ Δ 的分辨率 ~±2.3 顺位点；**只对"关掉后变差且 CI 排除 0"的块下结论** |

⚠ **禁止**：混合桌自对弈汇总当判据（学生探索 vs 对手 argmax，不可比）；单座位配置的配对当判据（`NOTES.md` §6.5
的采样偏差实测：`g05` 相邻 +1.10 / 对家 +4.23）。

### 8.2 校准（头级别，不是"直觉"）

| 头 | 指标 | 达标线（暂定，P1 结束后标定） |
| --- | --- | --- |
| 分布价值头 | CRPS、分位覆盖率（50/80/95%）、MAE、逐点/小局 ρ | CRPS 优于标量基线；覆盖率与标称差 ≤3pp |
| 信念头（对手听牌） | Brier、ECE、AUC | ECE ≤ 0.05；AUC ≥ 0.75 |
| 危险头 | Brier、ECE、按"是否立直/几副露"分层的可靠性曲线 | ECE ≤ 0.05 |
| 牌效头 | 向听 MAE、进张枚数 ρ | MAE ≤ 0.15；ρ ≥ 0.90 |
| 策略 | top-1 与 teacher 的一致率（**只作诊断，不作判据**） | 不设阈值（避免"越像老师越好"的诱导） |

### 8.3 消融矩阵（新增，回答"这条特征值不值"）

```
            Δ(顺位点) vs 全量    95% CI       结论
关 evt.order          −3.2      [−5.0,−1.4]   时序信息**必须**
关 til.per_opp        −4.6      [−6.5,−2.7]   逐家聚合是主力
关 ctx.riichi_turn    −0.4      [−2.2,+1.4]   证不出差别（**可以砍**）
关 derived.danger     −1.1      [−3.0,+0.8]   与信念头功能重叠（待定）
```

- 每块都用**同一批牌山**（同一 seed 基）⇒ 逐场配对，避免"换一批牌局就变号"。
- 这张表就是规范 §7 消融开关的**唯一用途**，也是"信息平价"从口号变成证据的地方。

### 8.4 决策相关指标（比 MAE 更接近目标）

- **押し引き开关**：在"他家立直且我方无听"的局面子集里，量"平均放铳率"与"顺位点"的联合变化
  （期望：放铳率下降而顺位点不降）。
- **终局顺位**：在最后一局/接近听牌分界的子集里量"平均顺位"。
- **价值头用于决策**：把价值当风险敏感效用（`U = E[score_delta] − λ·Var` 或顺位期望），
  在固定的策略上做"决策改变率 vs 顺位点变化"的扫描 —— 只有当它**正向**时才允许进上线路径。

### 8.5 反作弊与复现性审计

| 审计 | 判据 |
| --- | --- |
| 推理路径无标签 | 删掉 `aux.npz`，推理/评测/对拍仍全部通过（判据⑥） |
| 信息封闭 | obs 白名单 + `OBS_KEYS` + `features.py` 只读 obs；`SelfTest` 带红证 |
| **训练期封闭（红证）** | 删 `aux.npz` 前后 logits **逐位相同**；改隐藏量后 obs **逐字节相同**（规范 §1.4） |
| **奖励封闭** | `rewards.py` 不读任何隐藏量；**负向对照**：往奖励里注入一个"对手听牌"项必须让测试红 |
| **辅助头不回喂** | 输出只进损失；删掉非必需头后 `net.bin` 仍能加载打牌 |
| **场外分配均衡** | `balance.json` 逐因素偏差 ≤1%、对手配额 CV ≤5%；**超阈的轮次不得用于判据**（§7.5） |
| **对手族分层** | 信念/危险头报族间指标；训练池之外的族（teacher / 脚本 / 未参训代）必须各有一行 |
| 信息上限诊断（**只做诊断**） | 把"对手听牌真值"临时接进输入，强度应显著上升 —— 若不上升说明"头没学到"，是 bug 信号；**这条路径永不进发布** |
| 复现性 | 同种子自对弈产物逐字节（`trainer-selfplay-parity`）；增量==全量（判据④） |
| 三端一致 | 四个张量逐元素 golden（Java↔Python）、同种子逐字节（C++↔Java） |

### 第二轮：分阶段训练 + 掩码事件重建（2026-09-27，辅助头收敛）

第一轮暴露的问题：**辅助头不收敛**（`value` 的 CE 不降反升 3.87 → 6.63）—— 典型的**多任务权重冲突**
（策略头的梯度把共享主干拉向另一边）。这一轮按计划三件事一起做：

1. **数据放大**：150 → **400 场**（262,095 训练 / 14,965 验证，val = 20 场）；采集 384 s（12w）+
   派生 116 s + **并行数据集构建 75 s**（8 进程，与串行**逐字节相同**）。
2. **分阶段训练**（`--stage-a 0.25 --stage-b 0.35`，头 lr = 主干 ×3）：
   **a** 只训 `policy`+`effect`（主干先学会"打哪张"）→ **b 冻结主干**只训各头（新头在固定表示上收敛）
   → **c** 联合微调（注册权重全开 + 余弦降 lr）。
3. **P1 的掩码事件重建**（pretext，`--mask-frac 0.15 --ssl-weight 0.2`）：把真实事件 token 置 0，
   用事件塔的输出重建**事件类型**（8 类）；pretext 头**只训练**，不进 `inference_heads()`。

`chi 0.09（23）`。成本：**851 s**（10 epoch × 2,047 步，RTX 5060）。

**三条结论**（判据都在表里）：
1. **分阶段奏效**：`b` 段（冻主干只训头）一步就把三个辅助头从"没收敛"拉到"收敛"
   （`bt 0.591 → 0.373`、`danger 0.889 → 0.301`、`value 4.39 → 3.73`），`c` 段再把 `bt` 压到 **0.140**。
   ⇒ "先让主干学会打牌，再让头在固定表示上收敛，最后联合微调"这条路线**可复用**（P2 的退火也照它）。
2. **策略头仍在涨**（0.608 → 0.619，`policy` CE 1.19 → 1.10），且**数据翻 2.7 倍只换来 +0.011** ——
   与 v3 的经验一致：**BC 一致率的天花板不是算力**（teacher 自己的取舍里有大量近似平局的动作，
   学生不可能逐条复现）。要再往上必须换目标（自对弈回报，P3）。
3. ⚠ **pretext 太容易**：掩码事件类型一致率 **0.968**（chance 0.125）—— 事件类型几乎由上下文决定，
   对表示学习**几乎没贡献**。P1 若还要自监督，得换更难的掩码目标（连 `tile_kind` 一起重建、
   或掩码整段时间窗），否则这条损失只是白占权重。
4. ⚠ **别跨阶段比 train loss**：`b` 段的 train loss 反而涨（2.5 → 3.65）—— 那是辅助头的随机初始化
   被算进总损失了；**只有 val 的逐头曲线可以跨阶段比**（表里就是这个口径）。

**下一步（P1 正式化的收尾）**：① 换更难的 pretext（或按结论 3 直接砍掉，把权重让给 policy）；
② `harness.balance` 的 §7.5 均衡审计（座位/对手族分层）**还没跑过** —— 判据⑩要求它；
③ 放量（P3 的 6M 决策规模）时数据集构建要再压（现在 8 进程 ≈3,500 决策/s）；
④ v4 前向的 Java/C++ 落地（P5）之前，checkpoint 只能离线评估。

### 第三轮：把 `cand` 的派生段接上 + 阶段 c 的学习率（2026-09-27，教师一致率 0.619 → 0.903）

**这一轮不是"调参"，是两个真 bug 的收口**（都是"训练照跑、指标照出"的那一类）：

1. **`cand[88:128]` 整整 40 列一直是 0**（实测 `compact/v4-bc-002`：逐列 `maxabs = 0`）。
   根因两条一起：① `v4/traces.sidecar_dict` 只带了逐家四段位图/危险度，**没带逐候选 C 段**，
   于是 `blocks.cand_matrix` 走"per_cand is None"那条路**静默填 0**并只记了个 `degraded`；
   ② `v4/dataset._write_file` **从不检查 `Tensors.degraded`**。
   ⇒ 修法（两处都要）：`sidecar_dict` 带上 `cand`（按 `offsets` 切片 + 与 `nLegal` 对账），
   `_write_file` 遇到非空 `degraded` **直接报错**（"降级 = 静默换任务"）。
   **顺带**：`cand[96:99]`（v4 新 3 维）与预留 29 列**仍是 0**（离线侧与实时侧一致，不构成漂移；
   填它们要 sidecar 段长 +1 版 —— 欠账记在 `FEATURES-V4.md` §4.3）。
2. **阶段 c（联合微调）会把策略头练塌**：`--stage-c-lr-mult 1.0`（= 主干 1e-3）时，
   `c` 段第一步就 `top1 0.837 → 0.165`（= 首合法基线）、策略 CE 恒定 1.897 ⇒
   融合输出 ReLU 全死、logits 变成常数（argmax 恒取第 0 条）。加 `--stage-c-lr-mult`（乘在 a/c 基准
   lr 上）后 `0.1` 就正常。

那时 `cand` 是残缺的，瓶颈不在数据量而在**输入缺了 40 列**。

### 第四轮：P3 开局 —— 自对弈 + RWR（2026-09-27，**结果：证不出改进**）

**这一轮的目标**：把"教师模仿"换成"自己的对局 + 回报加权"，第一次让**回报**（而不是老师的动作）
影响策略。同时把设计里一直没跑过的 **§7.5 场外均衡审计**（判据⑩）做掉。

**采集**（策略串 `net:<上一代>#1.0` = 带温度探索的学生，占 1 席）：

| 轮次 | 生产者 | 场数 / 决策 | 用途 |
| --- | --- | --- | --- |
| `raw/v4-sp-001` | C++ 24 workers | **400 场 / 292,724 决策**（250 s） | **§7.5 均衡审计**（C++ 快，但它**不产 `aux.npz`**） |
| `raw/v4-sp-002` | Java 12 workers `--aux` | **200 场 / 143,612 决策**（256 + 54 s） | 数据集（信念/危险头要标签侧） |

**§7.5 均衡审计（判据⑩，首次执行）**：`v4-sp-001` → `--expect` 座位场核对 →
**座位最大偏差 0.000%**（阈值 1%）、配席 net/teacher/random = 400/800/400 与声明一致 ⇒
**均衡 ✓ 可用于判据**、`balance.json` 落盘。⚠ 首跑其实报了**假绿**：审计把"决策行"判成
"没有 `type` 字段"（老形状），而真轨迹写 `"type":"decision"` ⇒ 一条决策都没读到、
`seat_deviation`/`opponent_cv` 全是 0。修法三条：① 两种形状都认；② **空数据/无配席一律判不均衡**；
③ 夹具改成真形状（见 `NOTES.md` §6.5 第八轮）。**教训**：判据的"输入为空"必须自己变成红。

**数据集**（`compact/v4-sp-002`，129,176 训练 / 14,436 验证）：新增两列 ——
`is_student`（`--student <上一代的**确切**策略串>` 判定）与 `delta`（本小局该家收支）。
实测**学生行占比 26.1%**（33,691/129,176）—— 与"四席里一席是学生"完全吻合；
不遮的话这 3/4 的**对手/老师动作会被算进策略损失**（v3 踩过同一个坑：学生行占比 0.75 而非 0.25，静默）。

**训练**（10 epoch / 470 s）：学生掩码 + **RWR**（`--rwr-beta 8` 千点，权重 `exp(clip(delta/1000/β,-2,2))`
→ 实测 min 0.135 / mean 1.208 / max 7.389）+ 阶段 c `--stage-c-lr-mult 0.1` +
**关掉饱和的掩码重建**（`--mask-frac 0`，理由见第三轮的 0.968 结论）。

| 指标 | ep3 [b] | ep10 [c] |
| --- | --- | --- |
| val top1（**全部行**，即"和实际动手那家的动作一致率"） | 0.605 | 0.681 |
| val top1（**学生行**，即"预测自己采样出来的动作"） | 0.763 | **0.847** |
| value / belief_tenpai / danger | 3.96 / 0.336 / 0.480 | 3.46 / 0.245 / **0.677** ⚠ |

⚠ **danger 头的损失反而涨了**（0.48 → 0.68）：因为 RWR 权重一开始也加在危险头上，
而"赢的小局"多半没放铳 ⇒ 概率被系统性压低。**修法**：RWR 只作用于 `policy`/`effect`，
`danger` 只吃学生掩码（`value`/`placement`/`belief_*` 两个都不吃）—— 下一轮生效（本轮权重已训完）。

**结论（2+2 同牌山配对，n=800 场 / 每策略 1,600 席，C++ 24 workers）**：

| 对比 | Δ（顺位点，正 = 前者更好） | 95% CI | p | 胜/负/平 |
| --- | --- | --- | --- | --- |
| `v4-p3-001` vs **teacher** | **−1.96** | [−5.59, +1.69] | 0.358 | 386/413/1 |
| `v4-p3-001` vs **`v4-bc-004`**（上一代） | **−3.08** | [−6.71, +0.69] | 0.322 | 385/414/1 |

⇒ **两条都"证不出差别"**（CI 都跨 0），点估计还略偏负。**这一轮 RWR 没有可测的改进** ——
按 `sd(Δ)=52.8` 算，要检出 Δ=2.0 需要 **≈5,500 场**（本机 24 workers、2 席网络 ≈ 2 小时）。
它至少说明两件事：① 上一代（`v4-bc-004`，教师一致率 0.903）**已经站在 teacher 水平**；
② 200 场 / 3.4 万条 on-policy 行 + 无 critic 的 RWR，推动不了这个水平的策略。

**下一轮要改的三处（按性价比）**：
1. **量级**：一轮 **1,000–2,000 场**（Java + `--aux` 24 workers ≈ 2,600 s/千场；C++ 更快但不产标签侧
   —— 要用 C++ 就得先把 "aux 只覆盖部分行" 的掩码做出来）；
2. **目标**：把值头当 critic 的 **PPO**（`λ=1`、优势只按学生行归一化）取代"整小局回报"的 RWR；
   或退一步做"只学赢的小局 / 只学不放铳的决策"的过滤版，作为可解释的对照臂；
3. **评估预算**：一次对比 **≥2,000 场**，并把"要检出多大的 Δ"写进预先注册（本轮实测给了 `sd(Δ)`）。


### 第五轮：P3 加强版 —— 1,000 场自对弈 + PPO（2026-09-27）

**动机**（第四轮的结论）：200 场 / 3.4 万条 on-policy 行 + 无 critic 的 RWR 推不动"已经到 teacher 水平"的网。
这一轮把三处一起改：**量级 ×5**、**目标换成 PPO（值头当 critic）**、**评估预算 ≥1,000 场**。

**采集**（`raw/v4-sp-003`，Java + `--aux`，24 workers）：**1,000 场 / 689,693 决策**（自对弈 1,602 s + 派生 273 s），
配席 = **学生 2 席**（`net:<上一代>#1.0` 温度探索）+ **teacher 2 席**，`--rotate`。
⚠ 采集期自身就暴露了探索的代价：同一批对局里学生 **−3.78** 顺位点 vs teacher **+3.78**
（贪心的上一代与 teacher 基本持平 ⇒ **T=1.0 的探索让行为策略明显变弱**，on-policy 数据因此更"歪"）。

**§7.5 均衡审计**：座位最大偏差 **0.000%**、配席（座位场）net = 2,000 / teacher = 2,000 与声明一致、
逐座位各 500 ⇒ **均衡 ✓**、`balance.json` 落盘。

**数据集**（`compact/v4-sp-003`）：**654,414 训练 / 35,279 验证**（950 + 50 场），lmax 29，学生行占比 **50.0%**。

**PPO 落地**（`v4/pretrain.py` 的 `--objective ppo`，三条口径都有硬约束）：

1. **`log π_old` 现场重算**（`_behaviour_logprobs`）：前向是确定性的，所以只要给出
   ①采集用的权重（`--behaviour <ckpt|net.bin>`）与 ②采样温度（从数据集的 `student` 串里解析 `#T`，
   缺省 1.0），就能把当时采样用的分布逐行重算出来 —— 这是"离线做 PPO"的前提（不必在轨迹里存 log-prob）。
   ⚠ 缺 `--behaviour` 或缺学生掩码 ⇒ **直接退出**（不猜）。
2. **优势**（`_advantages`）：`A = R − E[V(s)]`，`R` = 数据集里的 `value`（整场收支，千点，与值头**同一个量**）、
   `E[V(s)]` = 值头 51 分箱的期望；**归一化只在学生行上做**（设计 §7.4 的硬口径），非学生行优势置 0。
3. **截断替代项**：`ρ = exp(logπ_new − logπ_old)`、`−min(ρA, clip(ρ,1±0.2)A) + 0.01·H(π)`，
   **只算学生行**；`danger` 只吃掩码（不吃任何回报加权 —— 第四轮踩过）。
   `--init <上一代 net.bin>` 从上一代权重起步，`--stage-a 0 --stage-b 0`（不从零训，直接联合微调）+ `lr 1e-4`。

**训练**（4 epoch / 2,556 步每轮 / 776 s，RTX 5060）：

| 指标（val 35,279 条，学生行 17,636） | ep1 | ep2 | ep3 | **ep4** |
| --- | --- | --- | --- | --- |
| val top1（全部行） | 0.851 | 0.881 | 0.890 | **0.892** |
| **学生行 top1** | 0.845 | 0.877 | 0.884 | **0.886** |
| **学生行 policy CE** | 0.861 | 0.648 | 0.609 | **0.601** |
| **KL（学生行均值）** | 0.0685 | 0.0676 | 0.0334 | **0.0206** |
| **截断比例** | 0.135 | 0.123 | 0.089 | **0.062** |
| value / danger / effect | 3.52 / 0.334 / 0.019 | 3.51 / 0.334 / 0.019 | 3.51 / 0.334 / 0.018 | **3.51 / 0.334 / 0.018** |

⇒ 重要性比一直待在信任域里（KL 单调降到 0.02、截断比例降到 6%），辅助头没有被带坏。

⚠ **一条必须记住的读数陷阱**：`random` 那 1/4 行的动作在训练过的网看来**几乎是零概率**
（实测逐行 CE 中位 0.05 / 90 分位 24 / **最大 672**）—— 不遮罩时"策略 CE"会被它带跑
（同一个模型在纯 teacher 数据上 CE 中位 0.004）。所以：**混合阵容的数据集上，策略类指标只在学生行上有意义**
（`evaluate` 现在支持 `row_keep`，输出里同时给"全部行"与"学生行"两个数）。

**判决（3 路同场配对：新 / 旧 / teacher / random，`--rotate`，1,200 场；同一副牌山按场配对）**：

| 对比 | Δ（顺位点，正 = 新更好） | 95% CI | p | 胜/负/平 |
| --- | --- | --- | --- | --- |
| `v4-ppo-001` vs `v4-bc-004`（上一代） | **+0.66** | [−3.52, +4.84] | 0.908 | 601/596/3 |
| `v4-ppo-001` vs teacher | **+1.47** | [−2.68, +5.68] | 0.583 | 609/589/2 |
| （参照）`v4-bc-004` vs teacher | +0.81 | [−3.07, +4.81] | 1.000 | 599/599/2 |
| （肯定性对照）`v4-ppo-001` vs `random` | **+77.17** | [+74.40, +79.97] | <0.001 | 1129/71/0 |

⇒ **方向翻正了**（第四轮 RWR 是 −1.96 / −3.08，这一轮是 +1.47 / +0.66），但 **CI 仍跨 0 ⇒ 还证不出差别**；
`vs random` 的 +77 说明度量与座位分配都没问题。⚠ **一条采样教训**：这个"四路各占一席"的设计 `sd(Δ)=73–74`，
比 2+2 设计（`sd(Δ)≈53`）**噪声大 ~2 倍** ⇒ 同样的场次预算下，**2+2 比 4 路同场更能分辨小效应**
（检出 Δ=2.0 分别要 ~10,000 场 vs ~5,500 场）。

**预先注册的主判据（2+2 同牌山配对，2,000 场，PPO×2 vs teacher×2）**：

| 对比 | Δ（顺位点） | 95% CI | p（符号检验） | 胜/负/平 | sd(Δ) |
| --- | --- | --- | --- | --- | --- |
| `v4-ppo-001` vs teacher | **−3.54** | **[−5.84, −1.24]** | 0.283 | 975/1024/1 | 52.75 |

⚠ **两个口径给出相反的结论，必须一起读**：`CI` 是**均值**的自助法区间（这里**排除 0** ⇒
"平均每场比 teacher 低 ~3.5 顺位点"），`p` 是**符号检验**（975 胜 / 1024 负 ⇒ 不显著）。
这是本仓库一贯的口径（v3 也有过 `+2.66 [+0.14,+5.18] p=0.068` 这种组合），但这次分歧最大 ——
说明**输的次数略多、且输的时候输得更多**。以 2,000 场的精度看：
**这一轮 PPO 把网从"与 teacher 持平"（上一代 +0.81 [−3.07,+4.81]）推成了"略低于 teacher"（−3.54 [−5.84,−1.24]）。**

**结论（第五轮）**：**PPO 这套配置没有带来改进，更强的测量说它略微变差了。** 三条自证的线索：
① **行为分布被探索污染**：采集期 `#1.0` 的学生比 teacher 低 7.6 顺位点（贪心上一代与 teacher 持平）；
② **优势太粗**：`A = R_整场 − E[V(s)]` 是"整场回报 + 值基线"，没有**逐决策**的信用分配
（在线 PPO 的 λ=1 / GAE 要有 rollout 才能算；离线这份数据只有整场收支）⇒ 方差极大（`sd(Δ)=52.8`）；
③ **离线指标向好 ≠ 变强**：学生行 CE 0.861 → 0.601、top1 0.845 → 0.886，而强度是 −3.54 ——
"拟合自己的探索分布"与"贪心时更强"是两件事。
**下一轮**（按预期收益排序）：**降温度**（`#0.5` 或贪心 + 噪声，先在采集期就把行为策略拉回 teacher 水平）→
**逐决策信用**（在 Java/C++ 侧按小局记 reward-to-go，才能算 GAE）→ 再谈放大场次。

## 13. 一页速查

- **信息上界 = 人类玩家**（不是 teacher）；**teacher = 起点 + 对手 + 基准**。
- **输入**：`tile[34,48]` + `evt[60,96]` + `ctx[64]` + `cand[n,128]`，块可关（消融）。
- **架构**：三塔 → 关键张注意力 + 事件注意力 → 状态/增量**两轮双向** → 多头（策略 + 分布价值 + 信念/危险 + 牌效）。
- **性能**：增量缓存 + 循环推理 ⇒ 每决策 O(新增)，1.5 M 参数、≤1.5 ms 网络。
- **封闭（训练期也要）**：引擎上帝视角**只写标签** —— 输入不碰、**奖励不碰**、辅助头不回喂；三条红证
  （删标签→logits 逐位不变 / 改隐藏量→obs 逐字节不变 / 奖励不含过程隐藏量）。
- **场外因素必须分层平均**（seat / 亲家 / 局 / 对手×座位 / 种子 / train-val 切分）：每轮出 `balance.json`，
  超阈的轮次**不得当判据**；消融与 2+2 只在均衡场次上做。
- **判据**：主判据是 **2+2 配对 vs teacher（Δ≥+2、CI 排除 0、≈5,200 场/臂）**；消融矩阵回答"哪块信息值多少"。
- **阶段**：P0 冻结契约 → P1 自监督 → P2 teacher 只做冷启动 → **P3 打到强于 teacher** → P4 押し引き → P5 上线。
