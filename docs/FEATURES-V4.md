## 1. 第一原则：信息平价（human-parity）

规则只有两条，**任何一条被违反都是 bug**，不是"取舍"：

| # | 判据 | 含义 |
| --- | --- | --- |
| **① 完备** | 人类玩家在牌桌上**能看到**的一切，v4 输入**必须都有**（可以是编码后的形式，但不能缺） | 少一项 = 给网络人为设了天花板 |
| **② 封闭** | 人类玩家**看不到**的一切，v4 输入**绝不能有** | 多一项 = 作弊面 |

⚠ **这条原则高于"与 teacher 同口径"**。v3 是按"贴着 `Bot`（teacher）的视野"设计的（见 §2 的账），
v4 改成**贴着人类玩家的视野**：teacher 只在训练初期当**起点**，不再当**信息上界**。

### 1.1 允许清单（逐项都要在输入里有落点）

| 人类看得到的东西 | v4 落在哪 | v3 有吗 |
| --- | --- | --- |
| 自家暗手牌（计数）+ 赤五标记 + **刚摸到的那张**（牌码，含赤） | TILE 塔自家通道 + CTX | ✅（`hand`/`hand_red`/`drawn`） |
| 自家副露（种类/牌/赤）+ 自家门前状态 | TILE 塔 + CTX | ✅ 部分（无赤、无 `from`） |
| 自家立直 / 一发 / **自家振听** | CTX | ✅ |
| 四家点数、座次（自风）、庄家、场风、局、本场、**供託立直棒** | CTX（含顺位与分差） | ✅（v3 起有 `points/5`） |
| **表**宝牌指示牌（含杠后新翻） | TILE 塔（逐牌种 + 顺序） + EVT（翻牌事件） | ✅ 计数 |
| 四家牌河：**哪家、哪张、第几巡、摸切/手切、是否立直宣言张** | EVT 事件流（逐张，有序）+ TILE 塔（聚合计数） | ❌ **只有按牌种计数**（顺序/摸切/宣言张全丢） |
| **立直宣言发生在第几巡**、四家立直与否、一发 | CTX（`riichi_turn[4]`）+ EVT | ❌ 只有布尔 |
| 四家副露：**种类、牌、被鸣那张、吃了谁、第几巡鸣的、赤** | EVT + TILE 塔 | ❌ **只留种类计数 + 牌种计数**（`from`/`called_tile`/巡数全丢） |
| 余牌数、岭上余数、总舍张、杠数、有没有人鸣过、海底/河底/岭上 | CTX | ✅ |
| 当前询问上下文：自家摸打还是鸣牌询问、谁打的、**被鸣那张**、能不能和（`win_note`）、合法动作集合 | CTX + CAND | ✅ |
| 由已知信息**简单算得出**的辅助量（可见牌/剩余/可摸、危险度、向听/进张/听牌形/打点粗估） | 派生段（引擎算，见 §5） | ✅ 部分（v3 是 71 + 8 维） |

### 1.2 禁止清单（与 `docs/PROTOCOL.md` §8.2 的"绝不出现"同一条纪律）

| 绝不允许进输入 | 为什么 |
| --- | --- |
| 别家暗手牌（`Round.hand[other]`） | 隐藏信息 |
| 牌山顺序 / 牌山内容（`Wall.debugAllTiles()`） | 隐藏信息（且直接决定摸牌） |
| **里宝指示牌**（`Round.uraIndicators()`） | 只有和牌者才看得到 |
| 别家振听（`furitenTemp/Perm[other]`） | 临时振听等价于"他听牌了" |
| 别家手牌/听牌/向听的**真值**（形状、进张） | 隐藏信息 —— ⚠ **只在训练时当"标签"用**（§5.2），绝不在推理时进输入 |
| 未翻开的杠宝牌、牌山剩余顺序、别家的摸切意图等 | 同上 |
| "场外"设定（局数上限、uma、食替…）中**人类看不到**的部分 | 与 `NOTES.md` §10 的既有已知限制同源 |

⚠ **`belief`（对手手牌/听牌预测）是"头"，不是"输入"**：网络可以**预测**别家手牌分布，但预测的**原料**
只能是公开信息；训练时用自对弈真值当标签（§5.2），推理时绝不读真值。这是 v4 与"作弊模型"的分界线。

### 1.3 三个消费端必须一致

同一份输入规格要在**三处**实现，且逐元素对拍（沿用既有 `trainer-*-parity` 体系）：

| 端 | 角色 | 判据 |
| --- | --- | --- |
| `python/mahjong_ml/`（训练） | **规格来源**：`features.py` 打印分段偏移 | Python 侧是"唯一真值" |
| `server/.../ai/`（Java 上线） | 纯手写前向 + 特征拼装 | 与 Python **逐元素**（golden 夹具） |
| `trainer/`（C++ 采集） | 自对弈产特征（吞吐 ×3） | 与 Java **逐字节**（同种子产物） |

新增任何一个通道 = **五处一起改**：① 本文件（规范）② `PROTOCOL.md` §8.2（obs 字段）
③ Java `ObsFeatures`/`Features` ④ Python `features.py` ⑤ `selfcheck.py` + `SelfTest` + `selfplay-check.mjs` 的判据。
漏一处就是静默漂移（v2→v3 那次的经验：`kuitan` 位重算出来恒 0）。

### 1.4 训练期同样封闭：**标签可以来自框外，输入与奖励不行**（硬约束）

自对弈时引擎是上帝视角（知道所有人的手牌、牌山、结局）—— 这个视角**只允许用来产生标签**。
**任何"框外量"都不许进输入、不许进奖励、不许回喂**，否则模型会去拟合它推理时根本拿不到的信号
（= "对框外信息过拟合"）。三条**红证**（每条都要有负向对照）：

| # | 红证 | 具体判据 | 防的是什么 |
| --- | --- | --- | --- |
| **①** | **撤掉标签，输出不变** | 删掉 `aux.npz` 后重新前向，**logits 逐位不变** | 标签偷偷进了输入（比"读代码确认"强） |
| **②** | **obs 不含隐藏量** | 改动 `Round` 的隐藏量（别家手牌 / 牌山顺序 / 里宝）后，同一座位的 `Observation.toJson()` **逐字节相同**；故意塞一个隐藏字段进 obs 必须让这条测试**红** | "以为没进、其实进了"（v2→v3 的 `kuitan` 恒 0 就是同类静默） |
| **③** | **奖励只来自对局结果** | 奖励/优势只能由 `hand_delta` / `placement` / **放铳事件本身**（放铳是玩家自己看得见的结果）构成；⛔ 禁止用"对手当时是否听牌""牌山下一张""别家手牌形状"这类**过程隐藏量**塑造奖励 | 用框外中间量做奖励 ⇒ 学出推理时拿不到的最优信号 |

另外两条配套纪律：

- **辅助头只进损失、不回喂**：信念/危险/牌效头的输出绝不进下一层或下一决策的输入，推理时可**整块删除**
  （判据：删掉非必需头后 `net.bin` 仍能加载并打牌）。
- **对手族分层评测**：自对弈数据的"对手隐藏结构"来自**自己的旧版本** ⇒ 信念/危险头必须在
  **训练池之外的对手族**（teacher / 脚本基线 / 未参与训练的历史代）上单独报一行指标，
  否则"同族内的高准确率"是自对弈版的框外过拟合。

## 2. 为什么必须有 v4：v3 的三条硬伤（实测）

| # | 硬伤 | 实测/证据 | v4 怎么解 |
| --- | --- | --- | --- |
| ① | **牌河只有按牌种计数** | `river/4×34`（`features.py:191-196`）。同一份输入对应的可能牌河有天文数字种；"他第 3 巡手切 3m、第 7 巡摸切 5p"这种**时序**信息全丢 | EVT 事件流（逐张、有序、带属性） |
| ② | **副露只留 kind 计数 + 牌种计数** | `meld_kind/4×5` + `meld_tiles/4×34`；obs 里明明有 `from`/`called_tile`/`aka`/巡数，特征层全丢 | EVT 事件流 + TILE 塔的 per-家通道 |
| ③ | **立直只有布尔**：宣言张、宣言巡数、宣言前后牌河的分层都没有 | `riichi/4` + `ippatsu/4`；审计条目③（`NOTES.md` §6.5）当年**刻意**不加"立直宣言巡目"，理由是"怕特征比老师更聪明 ⇒ 口径分裂" | 立直巡数进 CTX，立直前后分层进 TILE/EVT；**并同时解掉"口径分裂"**（§3） |

**"口径分裂"的根因与解决**：v3 的担心是"输入信息 > 标签源（teacher）的视野 ⇒ 学出来的东西对不上"。
根因是**把 teacher 同时当成了标签源和信息上界**。v4 把两者拆开：

- **标签源换成引擎与自对弈**：向听/进张/听牌/危险度/对手手牌信念/终局得分，**引擎自己就能给真值**
  （自对弈时它是上帝视角）⇒ 输入信息再丰富也不会与标签冲突；
- **teacher 降级**为：① 冷启动的模仿来源（小权重、会退火到 0）② 联赛里的一个对手（且是**基准**）③ 评测对象。
  它**不再是**信息上界，也**不再是**最终目标。

## 3. 张量布局总表

一次决策的输入 = **4 个张量**（外加 1 张掩码）。所有张量 float32 落盘、fp16/bf16 训练可选。

| 张量 | 形状 | 每个决策都要重算吗 | 语义 |
| --- | --- | --- | --- |
| `tile` | `[34, 48]` | **增量**（§4.4） | 逐**牌种**的属性通道（自家、三家、全局） |
| `evt` | `[K=60, 96]` | **增量**（只追加） | 公开**事件流**的最近 K 条（有序） |
| `ctx` | `[64]` | 每次重算（便宜） | 全局标量：场次/点数/顺位/计数/自家状态/询问上下文 |
| `cand` | `[n_legal, 128]` | 逐候选 | 候选动作的编码（§4.3） |
| `mask` | `[n_legal]` | — | 合法掩码（`legal` 的下标序） |

> **为什么是"逐牌种矩阵"而不是"逐张牌序列"**：牌种是**定长 34**（不用 padding），且"同一牌种的不同张"
> 在规则上完全等价；把 4 张的差异（哪张是赤、哪张在谁手里）用通道表达即可。**顺序**信息交给 EVT 流。

### 4.2 `evt`：K × 96（有序事件流）

每条公开事件一个 token（**只追加**，天生支持增量与循环推理）。字段（96 = 8+34+1+34+1+4+4+5+1+1+1+1+1）：

| 字段 | 宽 | 编码 |
| --- | --- | --- |
| `type` | 8 | one-hot：`draw` / `discard` / `meld` / `riichi` / `kan` / `dora_flip` / `agari` / `ryuukyoku` |
| `tile_kind` | 34 | 该事件的主牌（one-hot 牌种） |
| `tile_aka` | 1 | 主牌是不是赤五 |
| `called_kind` | 34 | 鸣牌的**被鸣那张**（非鸣牌事件全 0） |
| `called_aka` | 1 | 被鸣那张是否赤 |
| `actor` | 4 | 谁做的（**相对方位**：0=自己/1=下家/2=対面/3=上家） |
| `from` | 4 | 被鸣那张来自谁（相对方位） |
| `meld_kind` | 5 | 吃/碰/暗杠/加杠/大明杠 |
| `turn` | 1 | 该事件发生在第几巡 `/18` |
| `tsumogiri` | 1 | 舍牌是否摸切（**只有 discard 事件有意义**） |
| `sideways` | 1 | 是否立直宣言那张（横置） |
| `rip_phase` | 1 | 该事件是否发生在"该 actor 立直之后" |
| `seq_delta` | 1 | 距上一条事件隔了几条 `/8`（噪声/丢包容错） |

- **编码落点（2026-09，obs v3 已落地）**：JSON 侧是 `Observation.events[]`（字段表见 `PROTOCOL.md` §8.2，
  Java 是权威实现）。三条**实现口径**（三端镜像时必须一致）：
  ① `type` 里 `kan` = **三种杠**（`meld_kind` 再分 ankan/kakan/daiminkan）、`meld` **只**用于吃/碰；
  ② `draw` / `agari` / `ryuukyoku` 三个槽位**服务端不发**（理由见 `PROTOCOL.md` §8.2 的语义判据 3）
  ⇒ 训练侧永远读到 0，**不要**据此反推"没有摸牌"；
  ③ `seq_delta` 本实现**恒缺省（=1）**：日志完整、不抽样，白占一个常量通道 —— 留作将来"只发尾部/丢包"的容错位。
- **窗口 K = 60**：一个半庄单局的事件 ≤ ~100 条（实测服务端发的五类事件 ~80 条/小局），取最近 60 条进注意力；
  更早的信息由循环状态 `h` 承担 —— 这是"**状态与增量双向管理**"的接口。
- ⚠ **`h` 的两端口径（W1，第六十轮，已统一）**：`h_evt` = "**本小局从 0 起、逐事件推进全部真实事件**"
  的 GRU 隐状态，经 `fusion.mem` 的**逐维门控**（`g = 1 + tanh(W·h_evt + b)`，零初始化 ⇒ 旧网恒等）
  乘在**逐候选**的 `u_i` 上。三个量必须分清：
  ① **`h0`（进来）** = **窗口之前**的 carry（= 重放 `events[0, n-K)`）：生产端由缓存槽/整手重放给出，
     离线端由数据集 `h0` 列给出（用**学生网**算，见 `TRAINING-V4.md` §5.3 ④）；
  ② **`h_evt`（出去）** = 窗口之后的 carry = `EventTower.forward(evt, h0)[1]` —— 它才是喂进融合的那个；
  ③ 两者都**只喂真实事件行**，窗口前部的**零 padding 不喂**（`GRUCell(0,h) ≠ h`，喂了就是静默偏移）。
  ⛔ **别把它做成"拼接"或"逐行常数"**：那对 policy 是数学空操作（softmax 不变、梯度恒 0，
  第五十轮踩过，见 `NOTES.md` §6.5 第四十八~五十四轮）。
- **编码器**：`MLP(96 → 192)` + 可学习 `type`/`meld_kind` 嵌入 + **相对巡目位置编码**（sin/cos，16 维）
  + 相对方位偏置。事件 token **不做** absolute seat 编码（一律相对自己）。

### 4.3 `cand`：n × 128（= 基础 88 + 派生 11 + 预留 29）

| 段 | 宽 | 内容 |
| --- | --- | --- |
| 基础（沿用 v3，逐字不变） | 88 | `type/9` + `tile/37`（含赤槽位）+ `tiles/37`（取法）+ `tsumogiri/1` + `kan_kind/3` + `noarg/1` |

## 6. 版本与兼容（硬拒绝，不静默）

| 版本号 | 含义 | 放在哪 |
| --- | --- | --- |
| `obs v` | **obs 格式**版本（v4 起 = **3**：新增 `events[]`/`riichi_turn[]`/逐张属性） | obs JSON 的 `v` 字段 |
| `FEATURE_VERSION` | 张量布局版本（v4 = **4**） | `features.py`、Java `Features`、C++ |
| `derived_version` | 派生段版本（v4 = **3**） | sidecar 头部 |
| `net.bin 格式` | 权重文件版本（v4 = **格式 2**：带**块清单**） | `net.json` + 头部 |

**三条硬判据**（违反就报错退出，不许"尽力而为"）：

1. 权重头部的 `FEATURE_VERSION != 当前` → **构造期拒绝**（沿用 v3 的行为：
   `权重维度 … != 本服务端特征维度 …`）。
2. sidecar 头部 `derived_version`/段长不符 → `dataset build` **报错**（不许当 0 填）。
3. `net.bin` 格式 2 的**块清单**必须与当前注册表**逐块匹配**（块 id + 宽 + 顺序）——
   允许"注册表有、权重没用到"的块缺失（= 消融，§7），但**绝不允许宽度或顺序不符**。

### 6.1 `net.bin` 格式 2 的逐字段布局（P5 落地，2026-09）

⚠ **魔数与 v3 相同（`MJNN`），靠 `format` 区分**：v3 是 `format=1`（定长 MLP，无块清单），
v4 是 `format=2`。拿错了两边都在**构造期**报错（不是对局里算出奇怪动作）。

```
头部（64 B，小端）：
  magic u32 "MJNN" · format u32 = 2 · featureVersion u32 = 4 · obsVersion u32 = 3
  · derivedVersion u32 = 3 · dModel u32 · tileD u32 · nHeads u32 · valueBins u32
  · nBlocks u32 · nTensors u32 · fingerprint 16 B（ASCII 的 16 个十六进制字符） · params u32
块清单（nBlocks 条，按注册表顺序；子集 = 消融）：
  idLen u16 · id(utf8) · width u32
张量表（nTensors 条，**名字升序**，名字 = PyTorch `state_dict()` 的键）：
  nameLen u16 · name(utf8) · ndim u8 · dims u32×ndim · 数据 f32（行主序、紧凑、无对齐）
```

- **拓扑固定、宽度可变**：只有 `dModel / tileD / nHeads / valueBins` 四个宽度进头部（与 v3 的
  `hidden/head/trunk_layers` 同一思路）⇒ golden 夹具能用**小网络**（32/16/2/5，~200 KB）进仓库，
  而上线照跑 192/64/4/51（1,360,168 参数、5.4 MB）。
- **加载期校验（三端各自做，缺一不可）**：① 魔数/格式号/特征版本/obs 版本；② 每个块的 id 已注册、
  宽度相等、**注册表下标严格递增**（顺序或重复不对也算错）；③ **指纹**（`[[id,width],…]` 的 sha256
  前 16 位十六进制）与"按文件里那份清单重算"逐字符相同，全量清单还要与注册表指纹相同；
  ④ **每一层要用的张量都取一遍**并按 `[rows,cols]` 核对形状，最后断言"文件里的张量名没有一个是
  没人读的"（少张量 / 多张量 / 改名 / 形状不符全在构造期炸）；⑤ 尾部多字节也算错。
- **位图与布尔**：`hand_red` / `riichi` / `ippatsu` 在 obs JSON 里是**布尔数组**（不是计数）——
  三端都必须按真值读（2026-09-27 的实测漂移，见 `NOTES.md` §6.5 第 7 轮）。
- **两处"可缺张量"（旧网没有它也不许报错）**：`heads.policy_gate.*`（第五十五轮）与
  `fusion.mem.*`（W1，第六十轮）。契约用"**可缺 + 形状**"两种写法表达（`((1,dm),(1,dm+3))` 是
  **多候选形状**、`(None,(dm,dm))` 是**可缺**；只有元组里**每个元素都是元组或 None** 才算候选串 ——
  搞混会让**所有**张量都报形状不符）。加载点**必须统一走 `export.normalize_state`** 补 0
  （补 0 = 恒等，旧网前向**逐位不变**）；抄漏一处的症状是"某些旧权重能载、某些不能"，**实测踩过两次**。
  ⚠ 对应的"没人读"校验必须在**绑定期**标记 `used`，不能等前向（实测症状：
  `权重里 1 个张量没有任何参数读取它：[heads.policy_gate.bias]`）。
- **golden 夹具的格式 2（W1）**：`magic u32 · format u32 = 2 · nCases u32 · netLen u32 · net`，
  每 case = `obs · nLegal · keys · **h0 f32[dModel]** · tile · evt · ctx · cand · logits · value ·
  beliefTenpai · danger · **h_evt f32[dModel]**`。零初始化的张量在夹具里**必须被显式扰动**
  （现在是通用规则：`state_dict` 里 `max|·| == 0` 的参数一律 `normal_(0,0.5)`），否则那条路径
  三端都没被测到。夹具还自带三条**空转闸门**（归零 `fusion.mem` 必须改变策略头 / 长事件流用例上
  扰动 `h0` 必须改变策略头 / 策略头组内极差 > 1e-4），见 `docs/VALVES-AND-FIXTURES.md` §3 W1。

| 权重文件 | **≤ 8 MB** fp32（可 int8 量化到 ≤ 2 MB） | 打包与加载速度 |

**实测（2026-09-28，Java 单线程，`tools.V4Probe --bench/--cache`，721 条真实决策）**：
特征 **3.55 ms/决策** + 前向 **34.69 ms/决策**（无缓存）⇒ 合计 **38.12 ms/决策**；
上了 L2 增量事件缓存（`V4Policy.forwardCached`）之后 **22.50 ms/决策（1.70×）**，
前向本身 34.7 → ~18.9（1.83×）。剩下的不可复用部分（注意力 + FFN + 融合投影）见
`docs/TRAINING-V4.md` §5.3「落地实况」的归因。

**Java 算子白名单**（纯手写前向必须能实现，不许出现别的）：

```
Dense(Linear) · LayerNorm/RMSNorm · GELU/ReLU · Softmax · MatMul · 加法/乘法/拼接
· GRUCell · 逐元素门控（sigmoid/tanh）· argmax / top-k 采样
```

⛔ 不允许：卷积、转置卷积、任何依赖第三方库的算子、动态形状的 op（Java 侧要求**形状静态**）。

## 10. 一页速查

```
obs v3 ──► tile[34,48]  ← 增量（只改 1~2 行 + 四家计数器）
        ├► evt [60,96]  ← 只追加（K 窗口 + 循环状态 h 承担更早）
        ├► ctx [64]     ← 每次重算（便宜）
        └► cand[n,128]  ← 逐候选（引擎派生 **11** 维；其中 ①–⑧ 由 sidecar C 段填入）
                    │
        ┌───────────┴────────────┐
        │  Teacher 只在初期当起点 │  信息上界 = 人类玩家，不是 teacher
        └────────────────────────┘
```

- **完备**：人类能看到的，这里都有（牌河顺序/摸切手切/宣言张/副露来源/立直巡数，v3 全丢的那批）。
- **封闭**：别家手牌、牌山、里宝、别家振听 —— 永远不进；对手信息只能"预测"（belief 头）。
- **训练期也封闭**：引擎上帝视角**只写标签**；输入不碰、奖励不碰、辅助头不回喂（§1.4 三条红证）。
- **可证**：每个块能单独关掉，值不值由消融矩阵说话；三端逐元素对拍 + 增量==全量两条硬闸门。
