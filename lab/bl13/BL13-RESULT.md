## 3 ⭐ 一等发现：「重叠」与「每轮新鲜」不可兼得

`pair` 重叠把 `collect(D_{i+1})` 与 `train(D_i)` **同刻**起跑，而 collect 命令行在 train **起跑前**定死 ⇒ 只能拿到 **θ_i**。实测（被杀掉的 D_2）`g0.jsonl` 首行：
```json
"policy":"net:C:\\...\\tools\\build\\v4-expert-defrep-g10\\net.bin@0#0.5"        ← θ_0（不是 θ_1）
```
改"先训后采"顺序版后的 D_2：`"policy":"net:C:\\...\\tools\\build\\bl13-A-r1\\net.bin@0#0.5"`（θ_1）。
**含义**：BL-14 买到的是**算时利用率**（省 27.5%），代价是**数据落后一轮**；BL-13 要的"每轮新鲜"必须**串行**。
**取舍**：① 默认走 BL-14 重叠，把 off-policy 用 `behaviour_id` + 有界 ρ + 陈旧度预算**记账化**；② 只当"新鲜度本身是被检验的自变量"时改串行；③ ⛔ 预注册必须明写"本轮 collect 用 θ_i"，否则结论被静默污染（本次靠 `policy=` 原文才发现）。

## 4 `ceiling-gate.py` 为何不适用 + 替代前置
它的对象是**已存在的候选网**；两臂**只在训练后才存在** ⇒ 无可喂的 `net.bin`，硬套 = 跑空。**替代（跑前 ≤2 min）**：① recipe 指纹核对（4 枚网 + `trainer.exe` sha256 与 BL-14 `G4` pin 逐字一致）；② `--init` == 数据生成策略（闸门当场验，`KL=+1.11e-07`）；③ 分片完好（`meta.json` 可读 + `behaviour.table` 逐项 `verified`）；④ 闸门预演 `overlap-orchestrator check`（fail-closed 枚举自检 + G1–G5 全绿）。
