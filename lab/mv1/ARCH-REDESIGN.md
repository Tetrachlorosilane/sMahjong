### 2.3 事件塔真正接入主干（回应①⑤）：两条机制 + 一个判据
1. **同一 joint attention**：`[34 tile tokens; 60 evt tokens; 1 mem token]` + 段嵌入 ⇒ tile↔evt **天然双向**（不再是"两条独立 MHA 各看各的"，`model.py:265-266`），cand 只在**一个** joint memory 上做一次 cross-attn；**相对巡目位置编码**（sin/cos，0 参数）加在 evt token 上。
2. **`h_evt` 当第 95 个 token**：现在 `e_tokens` 对窗口内顺序**完全置换等变**，顺序只藏在 `h_evt` 里、而 `h_evt` 被零初始化门控乘 0 ⇒ 打乱只变 **0.78%**（审计 §7③）。⚠ 必须走"token 进注意力"，**不能**拼在候选后面或作逐行常数——那对 softmax/argmax 是**数学空操作**、那几列梯度恒 0（红证 NOTES §6.5 第四十八~五十四轮）。
3. **判据**：打乱 60 行窗口 ⇒ **`argmax` 变化率 ≥5%** 且 `KL(π_shuf‖π) ≥0.02`（现 0.78% / 0.00000）。⚠ **不可由初始化达成**：σ=1e-3 只 **0.0108%**、σ=3e-2 也只 **0.32%**、训练后 0.37%（第一百零二轮）⇒ 必须由上面两条给。
### 2.4 降稀疏 / 提连接性（回应①）：结构与机检一一对应
去 `fusion.out` ReLU（C1）· 全塔 **pre-LN + 残差**（tile 现为 post-LN，ctx/cand 无归一化）· **GELU** 替 ReLU（无硬零）· 门控小非零初始化（C3）· 恒等/死维不进首层。**机检**：`frac(u==0)`（78.5%→**<10%**）· `u` 非零维（41→**>120**/192）· 有效秩（§4-2）· 每层激活 std（>0、不随深度塌到 1e-3）· **梯度到达率**（\|grad\|>0 的参数占比 ≥95%，判"有没有层在空转"）。

## 4 验收判据（全部可机检，逐条）

1. `frac(u==0) < 10%`（现 **78.5%**）且 `u` 非零维 **>120**/192（现 41）。
2. 有效秩 ≥0.8×维度，**按 279 有效维计**：⚠ 现状 tile 1052/1632=64% ⇒ 去重前**结构上不可达**；删 13 通道后是 **1052/1190=88.4%** ✓（ctx 46/55=84% ✓ · cand 85/96=89% ✓ · **evt 65/93=70% ✗** ⇒ 事件塔的秩本身不够，这也是 d 192→128 的第二个理由）。

## 8 优先级裁定（第一百零五轮 · 项目方逐字裁定落成）

> 项目方原话（逐字，2026-10-18）：
> > "我建议不要将对称性放置在很重要的地位"

### 8.1 裁定落成（三条，按优先级）

1. **对称共享 = 参考设计 + 可选消融（缺省关）**。`--sym-share {none|suit|wind|dragon|rank|all}` 的缺省值固定为 **`none`**（不给该开关 = 与没有这段代码逐位相同）；§7 的群/编码/参数账/三段式测试**只作参考设计与消融素材**保留，⛔ 不进关键路径、⛔ 不作为闸门/验收的**前置**、⛔ 不用它做优先级排序。消融若要跑，必须作为**独立实验**预注册（读数只对该实验成立），⛔ 不许把"共享省参数"当成实现理由。
2. **#0 身份/位次嵌入 = 必修**（与本裁定**无关**，⛔ 不因第 1 条降级）。理由是**实测缺陷**：`tile` 塔对 34 行整行互换（2m↔8m）只改 `|Δlogits|` = **1.5e-5**（§7.5）—— 即塔"看不见是哪张牌"，这是**过度不变（伪对称）**，不是"对称共享"。修它的机制是**身份/位次编码**（打破伪对称），与 §7 的群共享是两件事。判据仍是"修完后 2m↔8m 整行互换的 `|Δlogits|` 必须显著大于 1.5e-5，且不破坏既有三端一致"。
3. **破缺通道（`is_green` 等）= 暂缓**。破缺点**只在需要解释读数时引用**（如 `緑一色` / `宝牌`），⛔ **不新增 `is_green` 通道作为近期任务**；§7.1 的 `is_green[34]` 只是"若将来要做，T1 档可做（纯派生、不重建数据）"的备查，不是排期承诺。

⚠ 本裁定**不改变** `MV1-PLAN.md` §1–§9 与 `MV1-AMENDMENT.md` §4 的任何判据；它只改**优先级与关键路径**。

### 8.2 判据 c 重标（旧 `5e-3` 作废）

- **实测（第一百零四轮，未坏的 base）**：固定 256 行 val 探针批、每 10 步的**单步 policy KL** `p99 = 0.0341` —— 旧阈值 `5e-3` 被**超 6.8×**。⇒ 旧阈值与 `lr 3e-3`（floored-cosine .75、1,200 步）这套配方**不自洽**：它会把"没坏的 base"判成坏，失去分辨率。
- **旧判据（§6.3 表 c 行）**："单步 policy 移动 `KL(π_t‖π_{t−1})` 的 p99 ≤ `5e-3`" ⇒ **作废**。⛔ 从本轮起**不得再用 `5e-3` 判任何东西**（包括 B3 是否修好、两臂是否可分、是否上闸门）。
- **新判据（冻写，第一百零五轮）**：
  > **级联判据 = `aux` 与 `base` 的单步 KL p99 比 ≤ 1.2 ∧ 两臂 p99 ≤ 0.05 ∧ 无 KL 早停 ∧ 跑满声明步数。**
  - 四条是**合取**；任一不达 ⇒ 判"级联未消失"，但⛔ **不得**再用旧 `5e-3` 另行判。
  - `p99` 的测量口径必须与第一百零四轮一致（固定 256 行 val 探针批、每 10 步、探针自证非扰动），或**事先声明等效口径**并留档。
  - "无 KL 早停" = `stop_reason` 为空且未触发 `--kl-early-stop`；"跑满声明步数" = 实际步数 = 声明步数。
