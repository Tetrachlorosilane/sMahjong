## 3 项目方裁定（2026-10-18，逐字引用 + 可机检判据）—— R1/R2 的执行口径

> 本节在**执行 R1+R2 之前**写定（唯一允许之后追加的是 §5「跑后读数」）。四条裁定**不许改写成别的意思**。

### R-1 训练必须"完全在线"

**原话**：「先尽量保证训练完全在线，否则反而拖累训练时长」。

判据（三条同时）：
1. **`--init` 必须等于数据生成策略**（本仓 PPO 口径闸门已强制；本批数据 `ov-A-s00` 的生成策略 = `v4-expert-defrep-g10` ⇒ `--init` / `--behaviour` 都必须是 `tools\build\v4-expert-defrep-g10\net.bin`，sha256 `167A7002…87DF`）。
2. **锚必须弱到让策略真的动**：`--ref-beta 0.5 → 0.1`（唯一改动；其余同 §2/§10 已冻写）。
3. **训练后必须量 `KL(π_trained‖π_init) ≥ 0.1`（学生行）才许进闸门**；不达 ⇒ **不许跑闸门**，报"仍欠在线"。⚠ **先量再判**，⛔ 不许用"步数够"代替。

测量方法：复用第九十一轮那套**纯推理复算**（同一份数据切分；对 `--init` 与训练产物两两在前向里取 `log_softmax`，只在 `is_student==1` 的行上取 `KL(π_trained‖π_init)=Σ π_trained·(log π_trained − log π_init)` 的均值；⛔ 不用训练日志里的 `ref_kl`（那是 π_ref 口径））。

### R-2 内存用"准入控制"而非"跑到一半杀"

**原话**：「RAM 占用超出预警值时，不得进一步加入新训练负载」。

判据（每个重负载相起跑前）：
- **准入** = `commit_free ≥ 该相预期峰值 × 1.5` **且** `预期峰值 × 1.5 ≤ 空闲基线`；不达 ⇒ **拒绝起跑 / 拒绝再加新负载**。
- 跑中越线 ⇒ **只记账 + 关闭新增负载**，⛔ **不因此杀当前相**。
- **硬地板**（本批写定）：`commit_free < 2.0 GB` ⇒ 才允许杀当前相（这是唯一允许杀的地方）。
- 本机实测：空闲基线 **10.5 GB**、训练相峰值 committed **4.35 GB** ⇒ 旧的绝对线 `commit_free < 8 GB 立即停` **自相矛盾**（8 GB > 10.5 − 4.35 = 6.15 GB 的可用余量），**本批起被替换**。
- 落点：`tools\overlap-orchestrator.py`（`admission_check` / `AdmissionGate`，缺省 `mode="admission"`；`--mem-kill` = 旧口径逐字保留）· `tools\ceiling-gate.py`（`collect_run` 起跑前准入 + 跑中只记账；`--mem-kill` = 旧绝对口径）。selftest 各 +2 条（准入拒绝 / 跑中越线不杀但拒绝新增）。

### R-3 不同优化算法不要求逐位相同

**原话**：「训练端不要求两种不同优化算法的计算值完全相同，只要都能达到预期趋势」。

判据：
- **同一算法 / 同一配置**（同数据 sha、同 `--init`、同 seed、同 batch/threads）⇒ 仍须**逐位不变**（既有判据全部保留）。
- **跨算法 / 跨实现** ⇒ 改判"**趋势判据**"：① 同方向（Δ 同号）；② 幅度差 ≤ **事先声明的容差 20%**（相对 `|Δ|` 的较大者）；③ 不出现反向。**预注册容差 = 0.20（相对）**，判据写成 `|Δ_a − Δ_b| ≤ 0.20 × max(|Δ_a|,|Δ_b|)` 且 `sign(Δ_a)=sign(Δ_b)`。

### R-4 ⭐ 训练前向与 server 前向不得在"选择"上分歧

**原话**：「不能有大到产生不同选择的差异（忽略设备/平台/语言的浮点微小差异），否则应当修改 server 端前向方法」。

判据：同一份 `net.bin`、同一批状态（**≥2,000 个决策**），**训练侧前向与 Java server 前向的 argmax 动作必须一致**。
- **并列阈值（跑前声明）**：`TIE = max(1e-5, 2 × 实测 max|Δlogits|)`。依据：若两侧逐元素差 ≤ δ，则 argmax 翻转的行必有 top1−top2 ≤ 2δ（数学必然）⇒ gap > TIE 而 argmax 不同 = **真分歧**；gap ≤ TIE = 并列，不算分歧。
- **出口**：真分歧 = 0（或全部可归因于并列）⇒ 通过；**存在真分歧 ⇒ 停下报告**（⛔ 本批不改 server 前向）。
- 驱动工具（⛔ 不新造第二套前向）：`tools\trainer-v4-parity.mjs --golden`（Python 夹具 ↔ Java `V4Probe` ↔ C++ `trainer v4net`）+ `tools\trainer-v4-parity.mjs <net> <corpus…>`（Java ↔ C++）+ `tools\v4-forward-gpu.py --traces … --format cpp`（Python/torch 侧）。

## 4 R2 闸门的**双口径**与冲突裁决（跑前冻写）

- **并列主口径 = `score`（千点）与 `rank_points`（顺位点）**，两者都按 3 族 Bonferroni（z=2.394）报 Δ / CI / `MDE_Bonf`；护栏 `wins`(0.10) / `deals`(0.10) / `win_points`(150) 逐口径照报 `tol`、`MDE`、`usable_as_veto`。
- **n 由 `score` 定**：`n = (2.394·sd/1.0)²`，sd 取 **21.071** ⇒ **n ≥ 2,545** ⇒ 3 族 × **849 场/族/臂** = **n 2,547 配对**（5,094 场）。
- **裁决规则（逐字；⛔ 不许事后挑口径）**：
  1. **有效** ⇔ 两口径的 Bonf CI 下界都 > 0 ∧ 3 族逐族同号为正 ∧ 所有 `usable_as_veto=true` 的护栏未越带 ∧ 安慰剂不显著。
  2. **反向** ⇔ 两口径的 Bonf CI 上界都 < 0。
  3. **口径冲突** ⇔ 一口径 Bonf CI 排除 0、另一口径含 0 ⇒ 判 **「测不出（口径冲突）」**，⛔ 不许取对己方有利的那一个。
  4. **真阴性** ⇔ 两口径 Bonf CI 都含 0 ∧ **两口径各自的实测 `MDE_Bonf` 都 ≤ 1.0** ∧ 逐族不翻转 ∧ 安慰剂不排除 0。⚠ 本轮 n 由 `score` 定 ⇒ `rank_points` 的 `MDE_Bonf` 预计 ≈2.3 >1.0 ⇒ **本轮结构上不可能判真阴性**（照实写在这里，⛔ 不许跑后改）。
  5. 其余 ⇒ **测不出**。
  6. 判决**条件于 seed `53610001`/`53610002`/`53610003` 这三套牌山**，⛔ 不跨族外推；`tol/MDE` 与 `usable_as_veto` 按跑后 `verdict.json` 实值照报；安慰剂按第九十五轮零和口径 `usable_for_veto=false`（只记账）。

### 7.1 诊断五条（`文件:行` + 数字）

1. **损失装配（sum 还是 mean）**：`pretrain.py:1395` `per_row_own = BCE(..., reduction="none")` →
   `pretrain.py:1397` `l_own = per_row_own.mean()` → `pretrain.py:1399` `total += w_own * l_own`。
   ⇒ **mean，对全部 B=512 行求平均**（不是 sum）。对照：policy = `pretrain.py:1310`
   `reduce_row(surr, row_keep)`，`reduce_row`（`:1200-1209`）= `Σ(per_row·mask)/Σmask` = **学生行上的
   mean**（学生行 24.9% ≈ 128/512 行）；value/placement/belief_* = 普通 `.mean()`（`:1343` 等）。
   ⇒ **三项都是"逐行平均"**，aux 与 state 级头（value 等）同口径；**不存在 ~512× 的 sum/mean 量级 bug**。
2. **梯度尺度实测**（同配方，step 0/10/20；`|g|` = 全参数裁剪前范数）：
   | 量 | step 0 | step 10 | step 20 |
   | --- | ---: | ---: | ---: |
   | policy | **1.887**（trunk 1.885） | 0.970（0.969） | 0.784（0.784） |
   | aux 原项（w=1） | **7.415**（trunk 4.005） | 0.557（0.505） | 0.210（0.174） |
   | aux × w=0.3 | **2.225**（trunk 1.202） | 0.167（0.152） | 0.063（0.052） |
   | value | 9.603 | 2.082 | 0.819 |
   | ref（β=0.1 的 KL） | 2.983 | 1.832 | 2.186 |
   | total | 7.949 | 1.573 | 0.945 |
   ⇒ **aux(w=0.3) / policy = 1.18×（step 0）、0.17×（step 10）、0.08×（step 20）**；只算**主干**时
   是 **0.64× → 0.16× → 0.066×**。随后继续衰减：step 300 **0.055×**、600 **0.052×**、640 **0.062×**、
   647 **0.0063×**。**结论：aux 对主干的梯度贡献从来不是 policy 的 X>1 倍；它在 step 0 之后一路 ≤0.2×。**
   `--head-lr-mult 3.0` 的放大：头每步 `‖ΔW‖≈0.010–0.034`（头 lr 0.009 ≈ 主干 0.003 的 3×，Adam 步长 ∝ lr），
   648 步后头 `max|W| 0.0718→0.9688`（**13.5×**）、`‖W‖₂ 0.548→1.937`（**3.5×**）。
3. **发散动力学**（aux 0.3 的 649 步逐 step）：KL 常年 **0.05–0.40**，**不是** 600 步匀速累积；
   末段是**级联**：`|g| 2.98(640) → 9.31(641) → 18.78(644) → 10.89(645) → 12.72(646) → 92.12(647)
   → 50.35(648)`，KL `0.133(640) → 0.370(641) → 2.230(648)`。级联前（640–641）aux 头 `max|W|=0.9662/0.9667`、
   BCE **0.4685/0.4597**（训练窗最低 0.4529）、`‖W‖₂=1.934`；级联中 `own_bce` 在 645–648 抬到
   `0.598/0.494/0.547/0.862`，**是主干被级联带坏的结果，不是原因**。**级联的每一跳都是 policy 项**：
   step 647 `g_policy=97.17` vs `g_aux_w=0.615`（aux 只占总范数平方的 **4.5e-05**）。
4. **对照（base vs aux 同点）**：epoch 1 的 `|g|` 均值 **base 2.74 / aux 2.80 = 1.02×**（不是 10.5×）。
   ⚠ **简报里的 `|g|=28.81` 不属于本臂**：它是**第一百零一轮 C1-a**（`NOTES.md:6537`：去 `fusion.out`
   末端 ReLU + floored(.75)@1200 ⇒ KL 早停 step 27）的读数。本臂 step 0 实测 **base 7.734 vs aux 7.949
   （+2.8%）**，且 **policy 1.8875 / value 9.6033 / ref 2.9833 两臂逐位相同**（4 位小数）⇒ 两臂在 step 0
   的**唯一**差别就是 aux 项本身。`w_aux × 梯度尺度` 也不符：aux 只把总范数抬高 2.8%。
5. **怀疑清单六条结论**：
   - ① **aux 损失 sum/mean 口径：❌ 不成立** —— 已是 mean（§7.1-1）；改成 mean 是**空操作**。
   - ② **误吃 `row_keep`/RWR：❌ 不成立** —— aux 走 `per_row_own.mean()`，**不经过 `reduce_row`**
     （`pretrain.py:1395-1397`），`row_keep`/`row_w` 一个都没进 aux。
   - ③ **aux 头 lr 3× 是否过大：⚠ 部分成立、⛔ 但不是级联主因** —— 头 `max|W|` 涨 13.5×，但**进主干的
     梯度**在 step 0 只有 policy 的 0.64×、step ≥10 后 ≤0.16×；且 `--head-lr-mult` 作用于**整个 heads
     参数组**（`pretrain.py:2153-2162`：`model.heads.parameters() + ssl_head + own_win_head` 同一个
     `lr = args.lr * head_lr_mult`）⇒ 改它**同时改 base 臂的头 lr**，破坏"两臂只差辅助头"的比较性。
   - ④ **warmup 缺失：⚠ 成立但不是主因** —— aux 从 **step 0** 就全权重（占比 1.18×/0.42×/0.17× 于
     step 0/1/10），但级联发生在 **640–648**，那时 aux 只占 **0.05×/0.006×** ⇒ 调 warmup 改不动级联点。
   - ⑤ **`--grad-clip 0.5` 裁"裁剪前总范数"污染主损失方向：❌ 机制不成立** —— `_clip_grad`
     （`pretrain.py:246-259`，调用 `:2766`）是**对总范数等比缩放**（`clip_grad_norm_`），**不改方向**；
     aux 只占总范数平方的 7.8%(0) → 0.18%(600) → 0.004%(647)，被它"挤掉"的 policy 份额可忽略；
     且 `|g|` 常年 ≫0.5 ⇒ 两臂的裁剪**一直生效、同口径**。
   - ⑥ **`no_grad`/`detach` 漏或多余：❌ 未发现** —— aux 读 `out["state"]`（有 grad，设计如此，头要训主干）；
     π_ref 的 logits 确在 `no_grad` 下预算（`pretrain.py:1216-1220`）；V_old/行为 logp 也都 detach。
   ⇒ **总判断：这不是"aux 量级写错"的 bug，而是"一条本来就在稳定性边缘的配方的 Policy 侧数值级联"；
   w=0.3 的 aux 用 2.8% 的 step-0 扰动把轨迹推到了另一侧（Adam 第一步是 scale-free 的 ±lr，微小分量
   也会翻转大量坐标的符号）。**

### 7.2 修法预注册（按改动面从小到大；⛔ 一次只上一个）

- **修法-1（统一 mean）：⛔ 不适用**。已是 mean；再"统一"等于给 aux 乘 512，是反方向的 bug。
- **修法-2（把 aux 梯度裁到与 policy 同量级）：⛔ 不适用（空操作）**。诊断：aux 主干梯度已 ≤0.64×
  policy、step≥10 后 ≤0.16×；"裁到同量级"不会改变任何东西，也解释不了 step 647 的 `g_policy=97`。
- **修法-3（`--head-lr-mult 3.0→1.0`）：⛔ 不做**。① 它作用于**全部 heads**（`pretrain.py:2153-2162`）
  ⇒ base 臂也会变，**两臂差两个旋钮 ⇒ 比较性破产**；② 诊断显示头→主干的耦合不是级联主因。
- **修法-4（剂量 `0.3 → 0.1`；必要时 `0.05`）：⭐ 采用（先试 0.1）**。
  - **为什么最小**：0 参数、0 代码；只动"辅助头剂量"这一个**比较性允许**的旋钮（base 臂无需重跑）。
  - **它验证的命题（⛔ 不夸大）**：不是"修好了一个 bug"，而是"**0.3 的剂量是否把一条本来就在稳定性
    边缘的配方推过了阈值**"。若 0.1 仍失败，证据指向"配方族内 aux 不可在线"，而不是"剂量还不够小"。
  - **预期**：step 0–20 的扰动降到 ~0.39×/0.14×/0.06×；KL 落在 **0.08–0.12**、`stop_reason` 空、
    top1 **≈0.64–0.66**、跑满 **1200/1200**、sha 与 base 不同（78/78 张量应仍不同）。
  - **判据（判据 23 四条腿，合取）**：`KL(T1) ≥ 0.1` ∧ `stop_reason` 无 KL 早停 ∧ `top1 ≥ 0.4505`
    ∧ **跑满 1,200**。另报 `KL(T0.5)`、翻转率、`frac(u==0)`、`max|W|`、末窗 BCE、`|g|` 曲线、墙钟、sha。
  - **停止规则（冻写）**：第一个让 aux 过判据 23 的修法即采用、后续不再试；0.1 失败 ⇒ 追加预注册
    `0.05`（同一修法族的最后一档）；两档都失败 ⇒ 报"**配方族内 aux 不可在线**"，⛔ **不跑 R2 闸门**。
  - **比较性声明**：base 臂（sha `C5D86973…A30F7`，KL 0.104113、top1 0.6626、1200/1200）**不重跑**；
