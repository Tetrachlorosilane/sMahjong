## 3. 日志措辞修正（本轮顺手修的"误标定根因"）

**改前**（上轮 `v4-wl-w2800-c2-g02` 日志原文，`pretrain.py`）：

```
… ⇒ **0.45361× 结果奖励的尺度**（= 「这一轴会不会支配梯度」的**尺度**读数：远小于 1 就推不动；要 1:1 大约要 `w=2`）
```

**改后**（本轮 `v4-wl-w14000-c1-g01` 日志原文）：

```
… ⇒ **0.92942× 结果奖励的尺度**（= 「这一轴会不会支配梯度」的**尺度**读数：远小于 1 就推不动；**放大倍数 w*/w = 1.08**（⛔ 不是「该设的 w」） ⇒ **所需 w**（= 当前 w 14000 × 1.08）≈ **15063**）
```

改法：`style_reward.py` 新增 `current_weight()` / `parity_note()`（**只排版措辞，⛔ 不动任何数值语义**：
`stats["style_reward"]["w_for_parity"]` 这个键仍 = `base_std/std(塑形列)` = `w*/w`，meta JSON 逐字不变），
`pretrain.py` 的那行打印改为调用它。读不到当前 `w` 时**明确写"读不到、⛔ 不拿倍数当 w 用"**，不猜。

⚠ 顺带记录一处**读数缺陷**（本轮才看清）：`base_std` 是 `std(delta + 塑形)`（塑形已乘过 `w`）
⇒ `w` 越大分母越被塑形自己撑大，比值趋于 1、算出的"所需 w"**有偏**（`w=2800` 时估 6170、
`w=14000` 时估 15063；按 `std(delta)` 直接量则是 2.52×）。真正的 1:1 判据应是
`std(塑形列) / std(delta)`（本次 = 2.52×），或把 `base_std` 换成 `std(delta)`。
