# 判别性实验：**逐决策付奖**（`--style-bonus-mode decision`）· 单链 1 代 · `w = 6170`

> 回答一个是非题：**把信度分配到"立直那一手"之后，立直率能不能被推上去**（预注册门槛 **≥ +2pp**）。
> 配方与 `PROBE-w14000.md` 的探针**逐字相同**（起点 `v4-expert-defrep-g10/net.bin`、风格桌
> `def7/atk3/win2`×g01..g10、`-NoGate`、1000 场、`--rotate-perm` 24 排列、`w=6170`），
> 只多一个 `--style-bonus-mode decision`。链标签 `v4-wl-dec6170-c1`（seed **24310051**，与
> 24310011..32/41、40970001..4 都不相交）。台账实证：`"style_bonus_mode":"decision"`。

## 0. 结论（三句话）

1. **训练后的立直率 29.63%**（3387/11432），对**同 seed、同牌山、同风格桌**的训练前读数
   28.30%（3227/11404）：**配对 Δ = +1.51pp**（逐场配对 SE 0.51pp、**t = 2.98**、df=999、
   95% CI **[+0.52, +2.51]pp**）⇒ **有显著位移，但没到预注册的 +2pp 门槛（≥30.5%）**。
2. **口径匹配的对照（都是"训 1 代后"）**：hand 模式的 g02 臂均值 29.30%（`w=0`）/ 30.13%（`w=300`）
   / **30.63%（`w=2800`）** —— 本链的 29.63% **落在同一带里、还略低于 `w=2800`**。
   ⇒ **没有证据表明"把信度分配到立直那一手"比 hand 模式已经在做的更强** ⇒ 转上报。
3. ⚠ **顺带查出一处口径事故（影响上一轮结论的读法）**：`g01` 行的轨迹是**训练前**采的
   （`loop.py` L841-849：`net_in = --init`，跑完一轮才 `net_in = net_out`；采集命令行里就是
   `--policy net:…defrep-g10/net.bin@0#0.5`）⇒ **每一臂的 `g01` 测的都是同一个现任策略**，
   那条"g01 剂量-反应"在原理上**测不出任何训练效果**（0.85pp 极差=采样噪声）。
   `PROBE-w14000.md` 用 `w=14000` 的 **g01(28.59%)** 对 `w=0/300/2800` 的 g01 下的结论
   （"位移落在噪声内 ⇒ 不是尺度问题"）**建立在一个不会动的读数上**；**口径匹配的那一行是 `g02`**
   （上轮 `w` 阶梯的 g02 是 29.30/30.13/30.63，本来就是单调↑）。

## 1. 新模式的行为 + 三条硬判据（原始输出）

**模式语义**：`hand`（缺省）= 现有语义**逐位不变**；`decision` = 奖励**只付在"真的执行了该轴动作"
的那一行**（`chosen` 以该轴动作键开头），其余行 **0**（⛔ 不是 `−μ/σ` 的负偏移）；伴随质量轴
`no_deal` **仍按该小局**判定；白化总体随之换成**学生席的决策行**（否则列的 std 掉到 `w` 的 ~0.2×，
就变成"顺手把剂量也改了"）。⛔ `deal/no_deal/win_points` 没有"哪一行做了它" ⇒ 当付奖轴**报错**。

### ① 缺省/`hand` 模式逐位不变（权重哈希 + 产物逐字节）

基线 = `git worktree add --detach <tmp> HEAD`（改动前的代码），同一份小紧凑集各训一步：

```
=== npy 逐字节对拍（A=基线 HEAD / B=改动后，都是 hand 模式、同一源）===
npy 个数=48  不一致=0
[meta.json] 只多一个 "mode":"hand" 键（⛔ 训练不读这段）

[train] label=v4-mode-base data=… steps=1 → 322d092d812b4b1fb5d21b1f86c77f2b538febd5e8afabf47b3321bd769ccdb6
[train] label=v4-mode-new  data=… steps=1 → 322d092d812b4b1fb5d21b1f86c77f2b538febd5e8afabf47b3321bd769ccdb6
```
命令行层（自检 772/0 里那条）：`hand` 时紧凑集命令**只多出** `--style-bonus / --style-bonus-whiten`
两个开关、`decision` 时**只多** `--style-bonus-mode decision`（`hand` 时不进命令）。

### ② `decision`：**付奖行数 == 立直宣言的决策行数**（全量原始输出）

```
风格奖励：白化统计（本数据集实测，范围 = student；11404 个小局，其中 11403 个进入统计）
  轴 riichi w=6170 质量轴=no_deal  μ=0.018786 σ=0.135768  付奖小局 2872  付奖总额 +122662084.3
风格奖励：**逐决策（decision）付奖** —— 奖励只落在'真的做了那个动作'那一行；
          白化总体 = student 席的**决策行**（171777 行）
  轴 riichi：动作行（`riichi` 的动作键）3227  付奖行 2872  质量轴 `no_deal` 拦下 355
            ⇒ 付奖行 +拦下 == 动作行 (✓)
     白化（逐行，本模式实际使用）μ=0.018786 σ=0.135768 n=171777 行
            ⇒ 动作行拿到的钱 w·(1−μ)/σ = +44591.3 点
     ⚠ 手级白化（仅作参照，本模式不用）：μ=0.282996 σ=0.450454；
        『立直小局数』（手级指示量=1）3227 ⇒ 付奖行数 / 立直小局数 = 0.890
    逐行 `style_bonus` 非 0 行占比：train 0.4% / val 0.5%（decision：只有动作行非 0、行内不同值是刻意的）
```
**三条互相独立的对账**（全量）：
* `selfplay-check.mjs` 的动作分布 `riichi=15414` == 审计账**全部座位** `action_rows=15414`；
* 学生范围：`action_rows 3227 == hands_indicator 3227`（每个立直小局**恰好 1 行动作**）、
  `paid_rows 2872 + blocked_rows 355 == 3227`；
* 列里非 0 行 `train 2702 + val 170 = 2872` == 白化那一遍算出的 `paid_rows 2872`
  （**两条独立的累加路径**：父进程全量扫 vs 6 个并行子进程逐文件写列）。

小样本上另有**逐行独立复算**（自写脚本，不复用 `style_reward` 的付奖函数；`hand` 模式先自证这把尺子
正确：0 不一致）：
```
=== hand 模式（验尺子）==== train 892 行 ⇒ 逐行不一致 0 行
=== decision 模式 ==== train 892 行 动作行 15 应付奖 15 拦下 0 列里非 0 行 15 ⇒ 不一致 0 行
                       val   746 行 动作行  8 应付奖  7 拦下 1 列里非 0 行  7 ⇒ 不一致 0 行
```

### ③ 白化仍 mean≈0 / var≈1（范围=学生席），常数轴 σ=0 硬拒

```
白化自检（均值≈0、方差≈1）：{'riichi': (0.0, 1.0)} ⇒ ✅ 通过      ← 全量 171777 行

        "whitening_check":{"riichi":{"n":171777,"mean":6.57e-19,"var":1.0000000000000002,"ok":true}}}
自检（772 项）：行级 μ=8/48=1/6、σ=√(μ(1−μ))=0.372678 ✓；σ=0（没有任何一行立直）两种模式都硬拒 ✓
```

### ④ 取不到"哪一行做了它" ⇒ 明确报错（⛔ 不退化成 `hand`）

自检红证（手级公开状态位说"2 号席立直了"、但没有任何一行记下 `riichi:` 动作键）：
```
`decision` 模式取不到'哪一行做了这个动作'（共 1 个小局）：game=0 hand=0: [riichi]
手级指示量=1（本小局发生过这个动作），但**范围内一行都没有**执行它 —— 取不到'哪一行做了它'。
⛔ **不退化**成 `hand` 模式：行级信度分配是这个模式的全部意义。
```
同一份轨迹在 `hand` 模式下照常算得出（μ=0.5、两小局）⇒ 上一条不是"文件本身坏了"的假红。
