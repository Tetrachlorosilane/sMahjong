# argmax 型自对弈前向迁 GPU · **确定批**跨局推理（本批 = 小规模证明 + 可复用实现，⛔ 未切生产管线）

2026-10-11 · 新增 `tools/v4-batch-serve.py`（`--selftest` **26 项**）· 顺手修 `tools/v4-forward-gpu.py` 的 `--rows <npz> --index-file` 崩溃（`TypeError` 在 `forward` **之后**才炸、`--out` 不生成；自检 16→19 项）· **`trainer/src` 一个字都没改**（下一批改哪里见 §5）· 只跑小规模自对弈采集（180 场 / 62.6 s）与前向对拍 · ⛔ 未跑 PPO / 训练 / 闸门 / 大采集；⛔ 未改 `powercfg`。
## 1. 接口设计
规则/特征留 **CPU**（C++ `selfplay` 既有实现），只把"前向那一格"换成确定批 GPU 推理；服务是**独立进程**（torch 只在 python 里 —— C++/Java 不引入 ML 依赖，Java 手写前向一个字不动）。

| 层 | 入口（`tools/v4-batch-serve.py`） | 说明 |
| --- | --- | --- |
| 键表 | `--keys-from-traces <轨迹目录>` / `--keys keys.tsv` | 只读 `type/game/step/seat`，⛔ **不读 obs**（键不能变成第二套特征语义） |
| 行级输入 | `--rows rows.npz`（`tile/evt/ctx/cand/nlegal[/h0/steps]`） | **已经算好的**张量；`h0` 必须是 `v4/cache.carry_prefix`（C++ `v4net` 的整手重放口径） |
| 批计划 | `plan_batches(order, K, tail)` + `assert_canonical` | 纯函数 + **提交前**守卫（乱序在这里死，不烧 GPU）；`tail = keep/drop/error` 全记账 |
| 前向 | `forward_plan(...)` → 按 `row` 回填 | 复用 `tools/v4-forward-gpu.py`（权重/分桶/设备），不复制一行；`K` 组内仍按 `legal` 条数分桶 |
| 输出 | `--format jsonl\|cpp`、`--out-order row\|canonical`、`--manifest plan.json` | 行对齐 + 批指纹 + 记账（`served` = **真正前向的行数**） |
| 对拍 | `--compare <trainer v4net stdout>`、`--margins` | argmax 全同 + 随量纲 maxΔ + 近边界间距分布 |
📌 下一批**线格式**建议：传 `obs+legal` 行（**3.8 KB/行**，服务端复用既有 `blocks.assemble`）而不是张量（**43 KB/行**，4.9 GiB/121k 行）—— IPC 小 11×，"特征在 CPU"这条也不动。
## 2. 确定批的排序键
**键 = `(game, step, seat)`**：`game` 场号（0 基，= `g<N>.jsonl` 的 N）· `step` 该场内决策序号（0 基、跨小局连续 ⇒ 已含 `hand_no` 先后）· `seat` 座位（本仓数据里冗余，写出来是为了键自解释 + 将来一场内多座位并行）。**规范序** = 该三元组的字典序全序；**`batch(b) = 规范序[b·K, (b+1)·K)`**。
- ⛔ 键必须**唯一**（`(game,step)` 重复 ⇒ 报错），**绝不用 `row` 兜底** —— 兜底 = 把到达顺序放回排序。
- 批指纹 = `sha256(b, pos, row, game, step, seat…)`（`--manifest` 落盘）⇒ "同一输入两次 ⇒ 同一批"可比。
- ⚠ **K 组 ≠ 数学批**：组内按 `nlegal` 分桶（补 0 行会经 `u.mean`→`policy_gate` 改 logits，与逐行语义不等价）。
## 3. 判据（五条，原始输出见 §4）
① **argmax 全同**：批版 vs 逐行版（C++ `v4net`）在 **121,120 行（≥5 万）上 0 处不符**；② **随量纲 maxΔ**：`|Δ| ≤ 1e-4 × max(1,|ref|)`，**绝对与相对都报**（绝对量纲单独看会误判：CPU 臂绝对 maxΔ 1.678e-04 **超** 1e-4、相对只有 2.003e-05）；③ **确定批自证**：同输入**两次独立进程** ⇒ 批成员顺序与逐行结果**逐位相同**，**负向**：故意乱序 ⇒ 报错不许提交；④ **加速**：同一批行数下逐行 vs 批版的墙钟与行/秒（冷/热分开）+ 端到端外推（1,000 / 12,000 场）；⑤ **近边界量化**：`top1−top2` 的 p1/p5/p50 + `<1e-6` 行数 + 12,000 场预期分岔（假设写清）。

- **吞吐由 K 决定**：K 组内平均 ~15 个 `nlegal` 桶 ⇒ 每微批只有 K/15 行（K=512 ⇒ ~34 行/微批），**每微批的 H2D + 启动开销 ~1.2 ms 摊到极少的行上**；K 到 **8192** 最优（20,502 行/秒），**单批（121,120）反而崩回**（tile+evt+cand 一次性 ~4.5 GB 上 8 GB 卡）。⚠ 普查报的"GPU 热 23,259 行/秒"是大得多的有效批上的数，**不能**与 K=512 的采集口径直接比；⚠ K=1 那臂 3 次里 **1 次 0xC0000005 崩**（20,000 次同步的病态配置，本就不该用），照实记。
- **端到端外推**（口径 = `COLLECT-PROFILE.md`：前向占 3.081/3.268 = **94.3% CPU-ms/行**；687,915 行/1000 场）：前向搬走后 CPU 侧剩 **0.187 CPU-ms/行**（特征 0.064 + JSON 0.050 + 规则 0.044 + 轨迹 0.029）⇒ w=4 时 CPU 地板 **0.047 ms/行**；GPU 要 **0.209 ms/行**（K=512）/ **0.080**（K=2048）/ **0.049**（K=8192）⇒ 管线墙钟 ≈ `max(CPU, GPU)`（**未计会合/传输开销，属乐观端**）：**1,000 场 ≈ 2.4 / 0.9 / 0.6 min**；**12,000 场（8.25 M 行）≈ 29 / 11 / 6.9 min**（CPU 地板 6.5 min），对照现状 **1.2–2.0 h ⇒ 2.5–4× / 6.5–11× / 10–17×**。
- **⑤ 外推**：假设 673 决策/场、12,000 场 = **8.08 M 决策**、"0 观测 ⇒ 95% 上界 3/n = 2.5e-5/决策"（规则三）、一处分岔 = 一场受影响 ⇒ **期望 0、上界 ≈ 202 场（1.7%）**（1,000 场 ≈ 17 场）。结构性上界：间距 `<1e-4` 的行占 1.4e-4 ⇒ 即使 Δ 分布恶化到"每个近分行都翻"，12,000 场上限 ≈ **1,131 行**。⛔ 所以**"同种子 ⇒ 逐字节相同"必须退役**（maxΔ ≠ 0），能保住的是"同种子 + 同批组成 ⇒ 统计可复现"。
## 5. 下一批要改 `trainer/src` 的哪几处（本批只做设计 + 离线证明）
1. `trainer/src/policies.hpp:222-257`（`makeV4NetPolicy` 的 lambda）= **唯一的同步前向调用点**：`:235` `obs->toJson()` + `:240` `v4Logits(...)` + `:243` `netArgmax(...)` 换成"提交 (键, obsJson, legalKeys) → 等这批回来 → 取 `logits[pick]`"。

4. `trainer/src/selfplay.cpp:258-272`（worker 池：**每场一线程跑到底**）⇒ 跨局批要**决策级会合**：worker 在自己的决策处阻塞，收集器在**所有未决键里取最小的 K 个**成批（⛔ 不是"先到先凑"）；⚠ 别破坏 `selfplay.cpp:252-257` 的"每场无共享可变状态"—— 批服务是唯一的新共享点，必须自己串行化。
5. `trainer/src/v4policy.cpp:1253 forwardAll` / `:1617 logits` / `:1632 v4Logits` + `v4policy.hpp` 的 `V4Scratch`：加批入口（K 行一次 GEMM + 每行一份 scratch）；走张量线格式再看 `npzwriter.hpp`。进程边界见 §1。
## 6. 风险与红线
- ⛔ **本批不切管线**：`trainer/src` 未改、`selfplay`/parity 判据一个字没动、未跑 PPO/训练/闸门。
- ⛔ **"逐字节"在 GPU 前向上已退役**（实测 maxΔ 9.968e-05 ≠ 0）⇒ 判据只能是"**argmax 全同 + 随量纲 maxΔ**"；**不许"先放宽再补证"**，也不许把"同种子统计可复现"说成"逐字节相同"。
- ⛔ 批组成只由 `(game,step,seat)` 决定：**不许**按到达时刻/线程完成时间凑批（负向 `--shuffle-plan` 必须红）。
- ⛔ 特征留 CPU（用户口径）；Java 手写前向不动；不改 `powercfg`；一次一个重负载、`--workers ≤4`。
- ⚠ **吞吐不是普查那个数**：K=512 只拿到 8.8×（每微批行数太少）。要 20×+ 必须 ① 加大 K（K=8192 = 37.5×，代价是批组成粒度变粗、在线延迟变高），或 ② 服务端**按 `nlegal` 重排** —— ⚠ 后者会改批组成 ⇒ 必须把"nlegal 桶序"写进规范序的第二键，否则"同种子 ⇒ 同批"当场失效。
- ⚠ `<1e-6` 间距的行**实测存在**（2 行）⇒ 更大样本/更近的平分必然翻；风险上界随场次线性增长。
- ⚠ 服务端必须喂 `h0 = carry_prefix`（整手重放口径），窗口冷启动会让 4.1% 的行（events>60）整片错位。
- 复现：`python\.venv\Scripts\python.exe tools\v4-batch-serve.py --selftest`；判据跑法见 `tools/AUTOMATION.md` §6。
