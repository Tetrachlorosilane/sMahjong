> 目标：把 `train(D_k, θ_k)` 与 `collect(D_{k+1}, θ_k)` 真并发，并把"数据生成策略 ≠ 训练 `--init`"做成**合规可判**

## 1 冻写的阈值（跑前定，跑后不许调）

| 名 | 值 | 理由 |
|---|---|---|
| `--rho-max`（重要性比上限） | **100.0** | 单轮同策略实测 `ratio ≤ 34.5`（`TRAINING-V4.md` §PPO 闸门）；跨 1 轮 off-policy 留 ~3× 余量。⚠ 现路径只有 `LOG_RATIO_CLAMP=4.0`（ρ≤54.6）的**静默**夹取 ⇒ 本次把它变成**有界 + 记账** |
| `--rho-max-action` | `fail`（缺省） | 命中上限**响亮失败**（`SystemExit`、exit 1、无 traceback）；`account` = 显式降级（夹到 `ln rho_max`）+ **记账 + 打印超限行数**。⛔ 两种都不许静默裁剪 |
| ρ 分布**必须**报 | p50 / p90 / p99 / max / `n_gt_rho_max` / `n_gt_clamp` | 判据 3 的原始输出 |
| `--stale-kl-budget`（允许陈旧度） | **0.30** | = 本 recipe 的 KL 早停阈值 `0.03` 的 **10×**。理由：段内自然漂移实测 0.0331（`NOTES §6.5` 第八十轮）⇒ 预算是"还能救"的量级，不是"没漂"。**超预算 = 记账 + 响亮告警，⛔ 不是硬拒**（陈旧度是质量轴，不是口径轴） |
| per-id 复算容差 | `1e-2`（沿用） | `KL(记录‖复算)` 同一条数据、同一策略 ⇒ 必须 ≈0 |
| 闸门硬拒（唯一） | `--init` 的 `sha256` 与**全部** `behaviour_id` 脱钩 ⇒ `SystemExit` | 判据 4（⛔ 不许把闸门削成无用） |
| 省时上限（对照） | **2.31×**（`OVERLAP-EXPLORATION.md` §5） | 目标 ≤ 上限；B3b 生产比例实测 **25.0 / 27.8%** 为对照 |

## 2 四条机制（逐条可机检）

1. **数据侧**：紧凑集加逐行 `behaviour_id`（`int16`）+ meta `behaviour_table[{id,spec,temp,sha256,path,verified}]`；
   sha256 由**构建器自己算**（⛔ 不信生产者声明）。开关 `--behaviour-id` 缺省**关** ⇒ 旧路径逐字节不变。⛔ 模型不许读该列。
2. **逐 id `logp_old`**：K 个行为 ⇒ K 遍全量前向（每多一种 ≈ +59 s/轮，如实报）；ρ 有界（见 §1）。
3. **闸门**：逐 `behaviour_id` **复算 logp 并比对** `KL(记录‖复算) ≈ 0`；陈旧度降级为预算/记账（见 §1）。
4. **回路编排**：**复用** `tools/overlap-orchestrator.py`（G1–G7 + 收尸 + 采样器，⛔ 不另造第二套），
   每轮结束写 `rounds.jsonl`（θ_k 指纹 · D_k 指纹 · 各自 behaviour_id · ρ 统计 · 陈旧度）。

## 3 判据（七条，逐条贴原始输出）

1. **列不泄漏**：加/不加 `behaviour_id` 列 ⇒ 前向**逐位相同**（sha256 相同）。
2. **逐 id 复算**：`KL(记录‖复算)` 逐 id ≈ 0（给数字与最大偏差）+ **开关关着时旧单策略路径逐字节不变**。
3. **ρ 上限真实生效（负向红证）**：故意用**更陈旧**的行为策略造数据 ⇒ **必须**命上限并**响亮失败/明确记账**（⛔ 不许静默通过）。
4. **闸门仍咬人**：`--init` 与全部 `behaviour_id` 脱钩 ⇒ `SystemExit`、exit 1、**无 traceback**。
5. **利用率实测**（安静窗 A/B，同一工作量）：每轮墙钟 / GPU 忙碌% / CPU 忙碌% / 空闲占比 / `commit_free` 最低 / 峰值 committed（ws 另报）。
6. **回归**：`python/selfcheck.py` 跑前跑后（条数/失败）+ 续跑/等价性（合法切点那套）。`trainer --selftest` 未改 C++ ⇒ 跳过。
7. **BL-13 配方**：确切命令序列（含 `--workers/--threads/--max-steps`、单段信任域 ≈100±10 步、段末撞 KL 早停的存档不许续、哪一步并发）。

## 4 两种结果的解释（跑前写死，避免事后挑口径）

- **A（机制与收益都成立）**：省% ≥ 18% 且 ρ 全部 ≤100 且 per-id 复算 ≈0 ⇒ 该路线在生产比例下**可用**，利用率结论写入 BL-13 配方。
- **B（机制成立、收益不足）**：省% < 18% 或某 behaviour 的 `kl_stale` > 0.30 ⇒ 机制**可用但不足以省算力**；
  结论 = 陈旧度必须先降（更短段 / 更频繁发布），并把 ρ/陈旧度分布如实入档。**两种结果都不做强度结论。**
